> 객체 인스턴스를 하나만 생성해서 공유하는 <strong>싱글톤 방식은 여러 클라이언트가 하나의 같은 객체 인스턴스를 공유</strong>하기 때문에 <strong>싱글톤 객체는 상태 유지(stateful) 하게 설계하면 안</strong>된다&#46; 

<a id="1c3eda9b0fe181e8ad40eb29cfebd0be"></a>

### <u>무상태(stateless)로 설계</u>

- <strong>특정 클라이언트에 </strong><strong>의존적인 필드가 있으면 안</strong><strong>된다&#46;</strong>

- <strong>특정 클라이언트 </strong><strong>값을 변경할 수 있는 필드가 있으면 안</strong><strong>된다&#46; </strong>

- 가급적 <strong>읽기만 가능 </strong>( <code>readonly</code> )

- <strong>필드 대신,</strong> 자바에서 <strong>공유되지 않는 지역변수, 파라미터, </strong><strong><a href="https://javacan.tistory.com/entry/ThreadLocalUsage">ThreadLocal</a></strong><strong> 등을 사용</strong>해야 한다&#46; 

> ⚠️ 
> 
> <a id="1c3eda9b0fe1810ca272edccc26bdbed"></a>
> 
> 만약 스프링 빈의 필드에 공유 값을 설정하면, 큰 장애가 발생 할 수 있다&#46; 
> 
> <a id="1c3eda9b0fe181bdb41cd6a3e52b541e"></a>
> 
> → <strong>스프링 빈 필드에 절대로 공유값을 설정하면 안된다&#46; </strong>

<a id="1c3eda9b0fe18151b949dd8410634264"></a>

### ⚠️ 상태 유지(stateful) 설계 시, 발생되는 문제점 예시

---

<details>
<summary><strong>StatefulService</strong></summary>

<a id="1c3eda9b0fe181f48de4e3ed5cfc3202"></a>

```java
package hello.core.singleton;

public class StatefulService {
    
    private int price; // 상태를 유지하는 필드
    
    public  void order(String name, int price){
        System.out.println("name + \" price = \" + price = " + name + " price = " + price);
        this.price=price;  // 문제가 발생되는 코드
    }

    public int getPrice() {
        return price;
    }
}
```

</details>

<details>
<summary><strong>StatefulServiceTest</strong></summary>

<a id="1c3eda9b0fe181b695aadba210795af0"></a>

```java
package hello.core.singleton;
import org.assertj.core.api.Assertions;
import org.junit.jupiter.api.Test;
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.Bean;

public class StatefulServiceTest {
    @Test
    void statefulServiceSingleton() {
        ApplicationContext ac = new AnnotationConfigApplicationContext(TestConfig.class);

        StatefulService statefulService1 = ac.getBean("statefulService", StatefulService.class);
        StatefulService statefulService2 = ac.getBean("statefulService", StatefulService.class);

        //ThreadA: A사용자 10000원 주문
        statefulService1.order("userA", 10000);
        //ThreadB: B사용자 20000원 주문
        statefulService2.order("userB", 20000);

        //ThreadA: 사용자A 주문 금액 조회
        int price = statefulService1.getPrice();
        //ThreadA: 사용자A는 10000원을 기대했지만, 기대와 다르게 20000원 출력
        System.out.println("price = " + price);

        Assertions.assertThat(statefulService1.getPrice()).isEqualTo(20000);
    }
    
    static class TestConfig {
        @Bean
        public StatefulService statefulService() {
            return new StatefulService();
        }
    }
}
```

</details>

> (최대한 단순히 설명하기 위해, 실제 쓰레드는 사용하지 않았다고 함)<br>&#91; Thread A → 사용자A 코드 &#93; 호출, &#91; Thread B → 사용자 B 코드 &#93; 호출 한다고 가정

<a id="1c3eda9b0fe181148f18cf02d5dc95c6"></a>

<code>StatefulService</code> 의 <strong><code>price</code></strong><strong> 필드는 공유되는 필드</strong>이기 때문에, <strong><u>클라이언트(user B)가 값을 변경 시,  특정 클라이언트(user A)의 값이  변경</u></strong>된다&#46; <br>따라서 <strong><u>사용자 A의 주문금액은 10000원이 되어야 하는데, 20000원이라는 결과가 나온다&#46;</u></strong> 

<a id="1c3eda9b0fe181078a86cb119937524d"></a>

실무에서 이런 경우를 종종 보는데, 이로인해 정말 해결하기 어려운 문제들이 터진다고 한다 (몇년에 한번씩 꼭 만난다고 함)

<a id="1c3eda9b0fe1812580bcf6ff14e47608"></a>

따라서 <strong>공유필드는 항상 조심</strong>해야 하며, <strong>스프링 빈은 항상 무상태(stateless)로 설계</strong><strong>해야 한다&#46; </strong>
