## 어떤 것을 로그로 남겨야 할까?

---

<a id="221eda9b0fe1805584c1f38d6bfd2e2b"></a>

### 1&#46; 로그( Log )의 유래

![](5043d04dc5240815.webp)

<a id="221eda9b0fe180d0a85acc57b6165c11"></a>

‘로그’ 는 항해에서 사용하던 항해 기록을 의미하는 로그북에서 유래됐다&#46;

<a id="221eda9b0fe1808ab2dee185e6c25baa"></a>

지금이야 GPS를 통해 간단히 배의 현재 위치를 알고있고 목적지로 가려면 어느 방향인지 알수 있지만 

<a id="221eda9b0fe1806e8ac6d54979fe1917"></a>

과거의 기술이 발달되기 이전, 배의 현재 위치, 목적지까지의 진행 방향 등을 알기 위해서 중간 중간 해가 뜨거나 지는 방향, 별자리 등을 보면서 배의 진행 방향과 속도를 기록해 지도상에서의 배의 위치를 계산해야 했다&#46;

<a id="221eda9b0fe180c5a781d09597bf09f5"></a>

과거 항해에서 이러한 기록(로그북)을 통해서 배의 현재 위치를 측정할 수 있던 것 처럼 비슷한 맥락으로 <strong><u>로그 시스템을 통해 우리 앱의 현재 상태를 파악</u></strong>한다&#46;

- 시스템에서 문제가 발생 되었을 때, 과거의 시스템에서 어떤 일이 있었는지 로그를 통해 파악한다&#46; 

<a id="221eda9b0fe180c18342c80456e263a6"></a>

### 2&#46;  유의미한 로그 데이터

![](55a065f34757be71.webp)

<a id="221eda9b0fe180c8b722e52bfecc97f5"></a>

서비스에서 남긴 로그에서도 트러블 슈팅에 도움도 안되는 로그만 잔뜩 남겨봐야 문제 해결에는 도움이 안된다&#46;  ( 불필요한 저장 공간 낭비만 발생한다&#46; )

<a id="221eda9b0fe180dba818c197dd188daf"></a>

따라서 트러블 슈팅에 도움이 될 것 같은 정보를 로그로 남겨 문제 발생 시 원인을 파악할 수 있도록 해야한다&#46;

<a id="221eda9b0fe1800eba7ade9b7c5b2fa2"></a>

그렇다면 트러블 슈팅에 도움이 될 것 같은 정보는 무엇인가?

<a id="221eda9b0fe180f4a450f8879d2c185e"></a>

서비스의 특성에 따라 중요한 로그 지표들이 다르다&#46; 

<a id="221eda9b0fe180b8a740cfe8be861a62"></a>

따라서 범용적으로 <strong><u>대부분 서비스에서 남기는 로그들</u></strong> 과 <strong><u>운영에 필요한 로그를 어떻게 찾</u></strong>아야 하는지만 다룬다&#46; 

<a id="221eda9b0fe18090b9eccbdf111f5290"></a>

법적으로 필요한 부분들은 당연히 남겨야 한다&#46;
