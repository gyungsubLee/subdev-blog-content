## 1&#46; 컴퓨터 프로비저닝, 기상화 기술

<a id="21eeda9b0fe180a7acdcd143aee4bf02"></a>

### 프로비저닝 

> ✏️ 
> 
> <a id="21eeda9b0fe180499d71ebca09c26728"></a>
> 
> 프로비저닝은 IT 시스템이나 서비스를 사용 가능한 상태로 준비하는 전체 과정이다&#46; 

> <strong>주요 요소</strong>

- 하드웨어 설정

- 소프트웨어 설치 및 구성

- 네트워크 연결 설정

> <strong>프로비저닝의 중요성</strong>

- 효율성&#58; 잘 구성된 시스템은 효율적으로 동작한다&#46; 

- 일관성&#58; 일관된 시스템 구성을 제공한다&#46; 

- 확장성&#58; 필요따라 시스템을 쉽게 확장 가능하다&#46; 

<a id="21eeda9b0fe1807f9ff4c3550a756812"></a>

### 기상화 기술의 개요와 발전

> ✏️ 
> 
> <a id="21eeda9b0fe1800b8067ffacfded171b"></a>
> 
> 가상화는 물리적 컴퓨팅 자원을 논리적으로 분할하여 여러 가상 환경을 생성하는 기술이다&#46; 

> ✅ 
> 
> <a id="21eeda9b0fe180989246e9a4f9b06865"></a>
> 
> 가상화 장점
> 
> <a id="21eeda9b0fe18043ba4cdc98adbfe268"></a>
> 
> 상화 기술은 현대 IT 인프라의 근간으로, 클라우드 컴퓨팅이라는 새로운 패러다임을 가능하게 했다&#46;
> 
> 1. 자원 활용도 향상
> 
> 1. 비용 절감
> 
> 1. 유연성

<a id="21eeda9b0fe180a8b475cf711247b0e0"></a>

### 가상화 기술의 발전

1. <strong>메인프레임</strong>
    > 메인프레임 시대의 가상화는 1960년대부터 시작되었다&#46; 이 시기의 컴퓨터는 엄청나게 크고 비쌋기 때문에 한 대의 컴퓨터를 최대한 효율적으로 사용해야 했다&#46;

    > 📌 
    > 
    > <a id="21eeda9b0fe180069324ce1124d76295"></a>
    > 
    > <strong>사례&#58; IBM의 System/360 프레임</strong>
    > 
    > <a id="21eeda9b0fe180d19d3cee330f09b329"></a>
    > 
    > 해당 시스템에서는 ‘시분할’ 기술을 사용했다&#46;
    > 
    > <a id="21eeda9b0fe180f7bae8fb9d0f2330af"></a>
    > 
    > 이는 마치 대형 도서관에서 여러 학생이 같은 책을 번갈아 가며 읽는 것과 비슷하다&#46;  <br>한 명이 책을 잠깐 보고 있는 동안, 다른 사람은 다른 페이지를 읽을 수 있다&#46;<br> (CPU 스케쥴링과 비슷)
    > 
    > <a id="21eeda9b0fe1807cbda7d350d9f1ac3c"></a>
    > 
    > 컴퓨터도 이와 비슷하게 작동했다&#46; 여러 사용자가 동시에 접속해 있지만 컴퓨터는 아주 빠른 속도로 각 사용자의 작업을 번갈아 처리했다&#46; 이로<br> 인해 각 사용자는 마치 컴퓨터를 혼자 쓰는 것처럼 느꼈다&#46;

1. <strong>x86 서버 가상화</strong>
    > 2000년대 초반, 개인용 컴퓨터에 사용되는 x86 프로세서가 서버에도 널리 사용되었다&#46;<br>이때 <code>VMware</code> 와 같은 회사들이 x86 서버에서 동작하는 가상화 소프트웨어를 개발했다&#46; 

    > 📌 
    > 
    > <a id="21eeda9b0fe180e28baad71481df9b46"></a>
    > 
    > <strong>사례&#58;  VMware ESX Server</strong>
    > 
    > <a id="21eeda9b0fe1802c8574f5563abdd947"></a>
    > 
    > 해당 소프트웨어를 사용하면 <strong><u>하나의 물리적 서버에서 여러 개의 가상 머신(VM)을 실행</u></strong>할 수 있다&#46; 
    > 
    > <a id="21eeda9b0fe1805e8cbff21b6b818ce1"></a>
    > 
    > 이는 마치 하나의 대형 아파트에 여러 개의 독립된 원룸으로 나누는 것과 비슷하다&#46; 
    > 
    > <a id="21eeda9b0fe180a7abc1d6b0307af4e0"></a>
    > 
    > 예를 들어,  한 대의 강력한 서버에 Windows Server, Linux, 그리고 특별한 용도의 <strong>운영체제를 각각 별도의 VM으로 실행</strong>할 수 있다&#46; 
    > 
    > <a id="21eeda9b0fe180b7969ecbb6401e424f"></a>
    > 
    > 각 VM은 독립적으로 작동하며, 서로 간섭하지 않았다&#46; 이로 인해 하나의 물리적 서버에 여러 가지 다른 작업을 동시에 수행할 수 있게 되었다&#46;

1. 클라우드 컴퓨팅
    > 2000년대 후반부터 클라우드 컴퓨팅이 등장 했다&#46;

    > 📌 
    > 
    > <a id="21eeda9b0fe180be9d5ddab6042057b7"></a>
    > 
    > <strong>사례&#58; Amazon Web Services (AWS)</strong>
    > 
    > <a id="21eeda9b0fe1808d895ad278d7ffe12f"></a>
    > 
    > AWS는 세계 각지에 대규모 데이터 센터를 운영한다&#46; 해당 데이터 센터들은 수많은 서버들로 구성되어 있고, 가상화 기술을 통해 거대한 컴퓨팅 자원 풀을 형성한다&#46; 
    > 
    > <a id="21eeda9b0fe180c687a6ef827d6ecb73"></a>
    > 
    > 직접 물리적인 서버를 구축하지 않고 클라우드 서비스인 AWS를 통해 <strong><u>필요한 만큼의 서버 용량, 스토리지, 네트워크 등을 &#39;빌려&#39; 사용</u></strong>할 수 있다&#46;
    > 
    > <a id="21eeda9b0fe180e6b994e1cc7c3dea16"></a>
    > 
    > 서비스가 성장하면 더 많은 자원을 사용하고, 사용량이 줄어들면 자원 사용을 줄일 수 있다&#46;<br> 이렇게 필요에 따라 유연하게 컴퓨팅 자원을 사용할 수 있는 것이 클라우드 컴퓨팅의 큰 장점 중 하나이다&#46; 

<a id="21eeda9b0fe180f892e2f6b33e1b9eb5"></a>

이러한 발전 과정을 통해 컴퓨팅 자원의  활용도와 유연성이 크게 향상되었고, 기업들은 더 효율적으로 IT 인프라를 운영할 수 있게 되었다 &#46;

### 1&#46; 기본 단계 &#45; app, db 띄우기

<a id="21eeda9b0fe180c09ac3e1cbe0db7416"></a>

```yaml
version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: bugfixhub-app
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/BugFixHub
      SPRING_DATASOURCE_USERNAME: ${DB_USERNAME}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD}
    depends_on:
      - db

  db:
    image: mysql:8.0
    container_name: bugfixhub-db
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: BugFixHub
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

### 2&#46; 이전 단계 개선

> ✏️ 
> 
> - <code>version</code> 삭제 (최신 Compose에서는 불필요)
> 
> - MySQL 연결 옵션 추가 (<code>useSSL=false&#38;allowPublicKeyRetrieval=true</code>)
> 
> - 환경변수 기본값 설정 (<code>&#58;&#45;rootpassword</code>)
> 
> - 데이터베이스 <u>헬스체크</u> 추가 (앱이 DB 준비 완료 후 시작하도록)

<a id="21eeda9b0fe180a2b400eb7d579f3267"></a>

```yaml
services:
  app:
    build: .
    container_name: bugfixhub-app
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/BugFixHub?useSSL=false&allowPublicKeyRetrieval=true
      SPRING_DATASOURCE_USERNAME: ${DB_USERNAME:-root}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD:-rootpassword}
    depends_on:
      db:
        condition: service_healthy

  db:
    image: mysql:8.0
    container_name: bugfixhub-db
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD:-rootpassword}
      MYSQL_DATABASE: BugFixHub
    volumes:
      - db_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  db_data:
```
