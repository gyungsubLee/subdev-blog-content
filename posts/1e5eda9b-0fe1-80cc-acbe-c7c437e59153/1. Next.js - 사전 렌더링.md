## NextJS &#45; 사전 렌더링

> 📖 
> 
> <a id="1e5eda9b0fe180f7b6fdeeaadd14ee03"></a>
> 
> <strong><code>사전 렌더링</code></strong>
> 
> ---
> 
> ![](9a55534417be16b5.webp)
> 
> <a id="1e5eda9b0fe180dabe6fe5468533d3ee"></a>
> 
> 브라우저의 요청이 사전에 렌더링이 완료된 HTML을 응답하는 렌더링 방식
> 
> - <strong><code>CSR</code></strong>(<code>Client Side Rendering</code>)의 <strong><u>단점을 효율적으로 해결</u></strong>하는 기술

<details>
<summary><strong><code>CSR</code></strong><strong> 및 단점</strong></summary>

> ✏️ 
> 
> <a id="1e5eda9b0fe1800c9a9cd769833c10a0"></a>
> 
> <strong><code>Client Side Rendering</code></strong> ( <strong><code>CSR</code></strong> )
> 
> ---
> 
> - <code>React&#46;js</code> 앱의 기본적인 렌더링 방식
> 
> - 클라이언트(브라우저)에서 직접 화면을 렌더링한다&#46;
> 
> ![](f49685a61c0f565d.webp)

![](7934e0e9d1382537.webp)

<details>
<summary>위와 같이 서버에 클라이언트에서 js를 실행해서 컨텐츠를 렌더링한다&#46;</summary>

![](c3f6174763637bc4.webp)

</details>

<details>
<summary>따라서 <u>초기 접속 이후</u> 매우 빠르게 컴포넌트를 갈아 끼우면서 화면을 보여준다 &#46;</summary>

![](71a3d4927d0de532.webp)

- 이미 번들링이 되었기 때문에 유저가 요청한 페이지를 클라이언트에서 실행하여 바로 보여줄 수 있다&#46; 
    - 네트워크 I/O 비용 ❌

</details>

<details>
<summary>그러나 <strong><u>첫 요청</u></strong> 시, 실제 유저가 <strong><u>정상 화면</u></strong>을 보기까지 <strong><u>너무 오랜 시간이 걸</u></strong>린다&#46; 즉, <code>FCP</code> 가 <strong><u>너무 늦</u></strong>어져 <strong>유저 이탈률이 증가</strong>한다&#46;</summary>

<details>
<summary>🧐 <code>FCP</code> ( <strong>First Contentful Paint</strong> )</summary>

> ✏️ 
> 
> <a id="1e5eda9b0fe180f28f55c665cb2f8d69"></a>
> 
> <code>FCP</code> 란, 유저의 요청 이후 첫화면이 보이기까지 걸리는 시간을 말한다&#46;

![](3e06aa2f115640bf.webp)

![](b52e56d6567fb71c.webp)

![](a2a0eea7e97df259.webp)

</details>

![](7ba1a8a295012b98.webp)

</details>

</details>

<details>
<summary><strong>사전 렌더링</strong></summary>

> ✏️ 
> 
> <a id="1e5eda9b0fe18082a0c8f5fd76d1b892"></a>
> 
> <code>사전 렌더링</code>
> 
> ---
> 
> ![](9a55534417be16b5.webp)
> 
> <a id="1e5eda9b0fe1805ba2ebfa554c8f5273"></a>
> 
> <strong><u>CSR의 단점</u></strong>인 <u><code>FCP</code></u><u>가 </u><u>느리다</u>는 단점을 보안하기 위해서 나온 방식이다&#46; 
> 
> - <code>CSR</code>에서는 <strong><u>클라이언트에서 JS를 렌더링</u></strong> ( React → HTML )했지만,
> 
> <a id="1e5eda9b0fe1809f96cae58b90779ac5"></a>
> 
> <code>사전 렌더링</code>은 <strong><u>서버에서 JS를 렌더링( React → HTML )</u></strong> 하고 바로 클라이언트로 내려준다&#46; 
> 
> <a id="1e5eda9b0fe1804c8385d8716b6722b4"></a>
> 
> 이로 인해, <strong><u>FCP 시간을 단축</u></strong>시켜 CSR의 단점을 해결한다&#46; 

<details>
<summary>사전 렌더링 과정</summary>

<details>
<summary>1&#46; 빠른 화면을 보여주기 위해 서버에서 JS를 렌더링하여 클라이언트로 보낸다&#46; </summary>

![](824356765ae8b20f.webp)

- 이때, React → HTML 변환하여 내려보는데, JavaScriptr가 번들링되지 않았기 때문에 상호작용(interactive)는 불가능하다&#46;
    ![](b94ed59f285f4198.webp)

</details>

<details>
<summary>2&#46; 상호작용을 위해 후속으로 JS를 번들링하여 클라이언트로 보낸다&#46;</summary>

![](732c66be9f01e23b.webp)

- 이후 유저는 웹 페이지에서 상호작용이 가능하다&#46; 
    - 상호작용이 가능한 지점을 <strong><u>Time To Interactive</u></strong>라 하여 <code>TTI</code>라 부른다&#46;

<details>
<summary>이렇게 FCP를 낮추기 위해 먼저 HTML, CSS를 보내고, 이후 상호 작용을 위해 JS를 보내는 것을 <strong><u>메마른 땅에 물을 뿌려주는 것과 같</u></strong>다고 하여 <strong><code>수화</code></strong>(<strong><code>Hydraction</code></strong>) 이라고 표현한다&#46;</summary>

![](1cb6688adc75836e.webp)

</details>

</details>
