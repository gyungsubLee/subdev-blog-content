<summary>Core Container</summary>

<summary>Beans </summary>

- Spring 기본 구성 요소 

- <code>&#64;Component</code> ( <code>&#64;Controller</code>, <code>&#64;Service</code>, <code>&#64;Repository</code> … ) Annotation을 통해 클래스를 빈으로 정의

- 스프링 시작 시, 컴포넌스 스캔을 하여 해당 Annotation으로 선언 
    - <code>&#64;ComponentScan</code>은 앱의 최상단 root 클래스에 명시되며, 스프링에서 자동으로 설정해줌

    - url path 변경을 통해 세부 설정도 가능함

- 빈으로 등록되어야 loC 컨테이너에서 생명주기 관리(생성, 소멸&#46;&#46; ) 및 의존성 주입을 해줌

<summary>&#91; 코드 &#93; 예시 </summary>

<a id="236be9004cb44894a7a53352034036fd"></a>

```java

// 2. AOP Module
@Aspect
@Component
public class LoggingAspect {
    private static final Logger logger = LoggerFactory.getLogger(LoggingAspect.class);
    
    @Around("@annotation(Transactional)")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object proceed = joinPoint.proceed();
        long executionTime = System.currentTimeMillis() - start;
        logger.info(joinPoint.getSignature() + " executed in " + executionTime + "ms");
        return proceed;
    }
}
```

// 3. Data Access/Integration Layer
@Repository
public class JpaUserRepository implements UserRepository {
    @PersistenceContext
    private EntityManager entityManager;
    
    @Override
    public User save(User user) {
        if (user.getId() == null) {
            entityManager.persist(user);
            return user;
        } else {
            return entityManager.merge(user);
        }
    }
}

@RestController
@RequestMapping("/api/users")
public class UserController {
    private final UserService userService;
    
    @Autowired
    public UserController(UserService userService) {
        this.userService = userService;
    }
    
    @PostMapping(value="/")
    public ResponseEntity<User> createUser(@RequestBody @Valid UserDTO userDTO) {
        User user = convertToEntity(userDTO);

<details>
<summary>Singleton Scope ( 기본 스코프 )</summary>

<details>
<summary>싱글톤 스코프 </summary>

- 스프링 컨테이너마다 하나의 인스턴스만 생성

- 하나의 인스턴스를 생성 후 공유하므로 공유 변수 사용헤 있어 주의가 필요하다&#46;

- 기본 스코프

</details>

<details>
<summary>싱글톤 스코프를 가지는 객체들</summary>

- ApplicationContext

- Spring Core Containers

- Beans
    - Controller, Service, Repository

    - Configurantion

- Spring Security Configurations

</details>

<details>
<summary>생명주기 관리</summary>

- <code>생성</code> &#45;  컨테이너 시작 시

- <code>소멸</code> &#45;  컨테이너 종료 시

</details>

<summary>🧐 테넌트 ( Tenant )</summary>

- 소프트웨어나 시스템에서 여러 사용자 그룹(주로 고객이나 조직)을 구분하고 각 그룹이 독립적으로 동작하도록 하는 구조를 의미한다&#46;

- 멀티 테넌트 아키텍처는 클라우드 기반의 애플리케이션과 SaaS(Software as a Service) 환경에서 특히 자주 사용된다&#46;

- 이 구조에서 각 테넌트는 시스템의 공유 리소스를 사용하지만, 데이터 및 설정은 독립적으로 관리되어 각 테넌트가 서로의 정보를 볼 수 없도록 보장한다

</details>

- 테넌트별 데이터소스

- 테넌트별 설정 정보

- 테넌트별 캐시

- 테넌트별 리소스 관리자

</details>

<details>
<summary>생명주기 관리</summary>

- 테넌트의 생명주기는 <strong>생성 → 초기화 → 운영 → 정지 → 종료</strong> 단계로 설계되어야 하며, 각 단계에서 리소스 관리와 상태 변경 감지가 필요하다&#46;

</details>

// 6. Custom Scope Example
@Component
@Scope(value = "tenant", proxyMode = ScopedProxyMode.TARGET_CLASS)
public class TenantScopedBean {
    private String tenantId;
    private DataSource tenantSpecificDataSource;

    public void setTenantId(String tenantId) {
        this.tenantId = tenantId;
        // Initialize tenant-specific resources
    }
}

// 7. Scope Configuration
@Configuration
public class ScopeConfig {
    @Bean
    public CustomScopeConfigurer customScopes() {
        CustomScopeConfigurer configurer = new CustomScopeConfigurer();
        Map<String, Object> scopes = new HashMap<>();
        scopes.put("tenant", new TenantScope());
        configurer.setScopes(scopes);
        return configurer;
    }
}

<details>
<summary>🧐 <strong>스프링 앱 실행 시 위 두개의 Context 2개가 관리 되니까, 기본 쓰레드가 2개인가?</strong></summary>

> ☝🏻 
> 
> - 스프링 애플리케이션 실행 시 ApplicationContext와 WebApplicationContext가 생성되는 것은 스레드 생성과는 직접적인 관계가 없다&#46;
> 
> - 이 두 컨텍스트는 스프링의 IoC 컨테이너로서, 빈들의 생명주기를 관리하는 구성요소이다&#46;

<details>
<summary>1&#46; 컨텍스트와 스레드 관계</summary>

<a id="142eda9b0fe180b392bfe8535ac51e09"></a>

```java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        // 메인 스레드에서 실행
        SpringApplication.run(Application.class, args);
    }
}
```

<a id="142eda9b0fe180feb775f578eeff1591"></a>

두 컨텍스트 <u>모두 메인 스레드에서 초기화</u> 되며<br><u>생명주기를 관리</u>하는 컨테이너일 뿐, <strong>별도의 쓰레드를 생성하지 않</strong>는다&#46;

</details>

<details>
<summary>2&#46; 실제 쓰레드 생성 예시  &#45; 쓰레드 풀</summary>

<a id="142eda9b0fe180bfb3bcf01f106f9f63"></a>

```java
// Tomcat의 스레드 풀 설정 예시
@Bean
public TomcatServletWebServerFactory tomcatFactory() {
    return new TomcatServletWebServerFactory() {
        @Override
        protected void customizeConnector(Connector connector) {
            connector.setMaxThreads(200);    // 최대 스레드 수
            connector.setMinSpareThreads(10); // 최소 유지 스레드 수
        }
    };
}
```

- 내장 톰캣의 스레드 풀

- 비동기 작업을 위한 별도 스레드 풀

- &#64;Async 애노테이션 사용 시

- 스케줄링 작업

</details>

</details>

<details>
<summary><strong>Root ApplicationContext (루트 컨테이너)</strong></summary>

- <strong>특징</strong>
    - 애플리케이션 전반의 핵심 컨테이너

    - 비즈니스 로직, 데이터 액세스 계층의 빈 관리

    - 다른 컨테이너의 부모 컨테이너 역할

- <strong>관리하는 빈들</strong>
    - Service 계층 (<code>&#64;Service</code>)

    - Repository 계층 (<code>&#64;Repository</code>)

    - 데이터 소스, 트랜잭션 매니저 등 인프라 빈

- <strong>설정 방법</strong>
    <a id="142eda9b0fe180caa228d1c4508891ec"></a>

    ```java
    @Configuration
    @ComponentScan(basePackages = {"com.example.service", "com.example.repository"})
    public class RootConfig { ... }

    ```

</details>

<details>
<summary><strong>Web ApplicationContext (웹 컨테이너)</strong></summary>

- <strong>특징</strong>
    - 웹 관련 빈들을 관리

    - 루트 컨테이너를 부모로 가짐

    - Request/Session 스코프 빈 관리

- <strong>관리하는 빈들</strong>
    - Controllers (<code>&#64;Controller</code>)

    - ViewResolvers

    - HandlerMappings

    - 웹 관련 인터셉터

- <strong>설정 방법</strong>
    <a id="142eda9b0fe18035a3c1fd7becde920e"></a>

    ```java
    @Configuration
    @EnableWebMvc
    @ComponentScan(basePackages = "com.example.web")
    public class WebConfig implements WebMvcConfigurer { ... }
    ```

</details>

<details>
<summary>Bean 생명주기, 스코프</summary>

<details>
<summary>싱글톤 스코프(기본)</summary>

<a id="142eda9b0fe1803b9d54e15d941a3fbf"></a>

```java
@Component
@Scope("singleton")
public class SingletonBean { ... }
```

</details>

<details>
<summary>프로토타입 스코프</summary>

<a id="142eda9b0fe180b5afb9e3c9100623fb"></a>

```java
@Component
@Scope("prototype")
public class PrototypeBean { ... }
```

</details>

<details>
<summary>웹 관련 스코프 </summary>

- request&#58; 요청당 하나의 인스턴스

- session&#58; 세션당 하나의 인스턴스

- application&#58; 서블릿 컨텍스트당 하나의 인스턴스

</details>

</details>

<details>
<summary><strong>컨테이너 계층 구조</strong></summary>

<a id="142eda9b0fe180bd90fbe4426bb8bc9b"></a>

```java
Root ApplicationContext
     ↓
Web ApplicationContext
     ↓
Servlet Context
```

</details>

<details>
<summary><strong>컨테이너 초기화 순서</strong></summary>

1. 서블릿 컨테이너(톰캣) 시작

1. Root ApplicationContext 생성

1. Web ApplicationContext 생성

1. 서블릿 초기화

</details>

<details>
<summary><strong>Bean 검색 규칙</strong></summary>

- 현재 컨테이너에서 먼저 검색

- 없으면 부모 컨테이너에서 검색

- Web Context → Root Context 순으로 검색

</details>

<details>
<summary><strong>주요 기능</strong></summary>

- <strong>자동 의존성 주입</strong>
    <a id="142eda9b0fe18053a90de8a1f60de77c"></a>

    ```java
    @Autowired
    public UserController(UserService userService) {
        this.userService = userService;
    }
    ```

- <strong>AOP 프록시 생성</strong>
    <a id="142eda9b0fe180bfab7de0cf0783df69"></a>

    ```java
    @Transactional
    public class UserService { ... }
    ```

- <strong>이벤트 처리</strong>
    <a id="142eda9b0fe180bfa457f6efbb26ce7b"></a>

    ```java
    @EventListener
    public void handleCustomEvent(CustomEvent event) { ... }
    ```

</details>

<details>
<summary>컨테이너  생명주기 관리</summary>

- <strong>초기화 콜백</strong>
    <a id="142eda9b0fe180ce9d6fc854776e3391"></a>

    ```java
    @PostConstruct
    public void init() { ... }
    ```

- <strong>소멸 콜백</strong>
    <a id="142eda9b0fe1808fb181fdba38d72e66"></a>

    ```java
    @PreDestroy
    public void destroy() { ... }
    ```

</details>

<details>
<summary>컨테이너 구조 장점</summary>

1. <strong>계층적 구조</strong>
    - 관심사의 명확한 분리

    - 모듈화와 재사용성 향상

1. <strong>유연한 구성</strong>
    - 다양한 환경에 맞는 설정 가능

    - 프로파일을 통한 환경별 설정

1. <strong>효율적인 리소스 관리</strong>
    - 스코프별 적절한 인스턴스 관리

    - 메모리 사용 최적화

</details>
