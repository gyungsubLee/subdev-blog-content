> Jenkins 을 통한 자동화 파이프라인 구축
> 
> - 젠킨슨을 베포 서버 앞 단에 구축하여 빌드된 패키징 파일을 자동으로 베포 서버들로 전송할 수 있도록 파이프라인 구축

> ☝🏻 
> 
> <a id="204eda9b0fe1804dbbd4dba9f8d7af5d"></a>
> 
> Jenkins를 원활하게 실행하기 위해서는<strong><u>최소 2GB이상의 메모리가 필요</u></strong>하다&#46; 
> 
> <details>
> <summary><strong>각 구성요소별 메모리 사용량 대략치</strong></summary>
> 
> | <strong>구성 요소</strong> | <strong>최소 메모리 (RAM)</strong> | <strong>실무 권장 메모리</strong> | <strong>설명</strong> |
> | --- | --- | --- | --- |
> | <strong>Jenkins 서버</strong> | 512MB | 1GB&#126;2GB | Java 기반&#46; 빌드 수 많아지면 급격히 증가 |
> | <strong>Maven 빌드</strong> | 512MB | 1GB&#126;1&#46;5GB | 컴파일, 테스트, 플러그인 실행 시 추가 사용 |
> | <strong>Nginx (리버스 프록시)</strong> | 30MB&#126;50MB | 50MB&#126;100MB | 정적 리소스 서빙 &#43; 프록시 역할 |
> | <strong>OS 및 기본 서비스</strong> | 200MB&#126;300MB | 300MB&#126;500MB | sshd, systemd, logging 등 |
> 
> - <strong>최소 메모리 기준 (계산 결과)</strong>
>     | <strong>구분</strong> | <strong>RAM (최소)</strong> | <strong>RAM (권장)</strong> |
>     | --- | --- | --- |
>     | 전체 시스템 | <strong>1&#46;5GB</strong> | <strong>2&#46;5GB 이상</strong> |
> 
>     - <strong>1&#46;5GB 이하</strong>이면 Jenkins 빌드 도중 Out&#45;of&#45;Memory로 <strong>죽을 확률이 높음</strong>
> 
>     - 정적 리소스만 Nginx가 담당하고 Jenkins에서 무거운 빌드만 하지 않는다면 <strong>1&#46;5GB 정도로 실습 가능</strong>
> 
> </details>

> | <code>t3&#46;small</code> | 2 | 2GB | ✅ 기본 실습 가능 |  |
> | <code>t3&#46;medium</code> | 2 | 4GB | ✅ 실무 테스트용 |  |
> | <code>t3&#46;large</code> | 2 | 8GB | ✅ 여유롭고 병렬 빌드 가능 |  |

1. Jenkins 홈 디렉토리 생성
    <details>
    <summary>🧐 Jenkins 홈 디렉터리 생성 이유 </summary>

    <a id="203eda9b0fe1805abf86fd51df0c37c2"></a>

    Jenkins는 아래과 같은 <strong>상태 정보</strong>들을 저장한다&#46; 

    | <strong>저장되는 데이터 유형</strong> | <strong>예시</strong> |
    | --- | --- |
    | 사용자 설정 | 관리자 계정, 로그인 정보 등 |
    | 설치된 플러그인 | Slack, GitHub, Docker 등 |
    | 파이프라인 및 Job 기록 | Jenkinsfile, 빌드 이력, 로그 등 |
    | 시스템 설정 | 글로벌 설정, 자격증명 등 |

    <a id="203eda9b0fe180e68412ddb2c90fd063"></a>

    위 정보들이 저장되는 본 경로가 컨테이너 내부의 <code>/var/jenkins&#95;home</code>이다&#46;

    <a id="203eda9b0fe180abab4ed64457f757ad"></a>

    이에 대한 정보를 EC2 내부에 마운트하기 위해서 저장하는 디렉토리를 생성하고 볼륨 마운트 설정을 한다&#46; 

    <a id="203eda9b0fe180d2ab34edc2b5f6af5e"></a>

    ```bash
    # 컨테이너와 마운트할 폴더 생성
    mkdir -p ~/jenkins_home

    # 볼륨 마운트: -v 옵션: 
    -v ~/jenkins_home:/var/jenkins_home
    ```

    - 호스트의 <code>&#126;/jenkins&#95;home</code> 디렉토리를 Jenkins 컨테이너의 <code>/var/jenkins&#95;home</code>에 <strong>연결 시킨다&#46;</strong>

    > ✅ 
    > 
    > <a id="203eda9b0fe180ea86d7c343105c1761"></a>
    > 
    > 장점
    > 
    > - 컨테이너가 삭제되더라도 Jenkins 설정과 이력은 유지
    > 
    > - 백업/복구가 쉬워짐
    > 
    > - Jenkins 업데이트 시에도 설정 유지 가능

    > ❗ 
    > 
    > <a id="203eda9b0fe18095812ff17e87024b7e"></a>
    > 
    > 만약 생성하지 않는다면?
    > 
    > <a id="203eda9b0fe180528c70f06d2ff28e6d"></a>
    > 
    > ```bash
    > sudo docker run -d ... -v ~/jenkins_home:/var/jenkins_home ...
    > ```
    > 
    > <a id="203eda9b0fe1806ea5c7fcb090355feb"></a>
    > 
    > 위 명령에서 &#126;/jenkins&#95;home이 <strong>존재하지 않으면</strong>, 도커가 해당 경로를 <strong>빈 디렉토리로 자동 생성하긴 한다&#46; </strong>
    > 
    > <a id="203eda9b0fe1802184b3d7440665d497"></a>
    > 
    > 그러나 아래와 같은 문제점이 발생될 수 있다&#46; 
    > 
    > - 권한 문제 발생 가능 (jenkins 유저가 접근 못함)
    > 
    > - 파일 시스템 구조가 꼬일 수 있음
    > 
    > <a id="203eda9b0fe180fcba77f427a854018b"></a>
    > 
    > <strong>따라서 </strong><strong><u>명시적으로 생성하고 시작</u></strong><strong>하는 게 </strong><strong>안정적</strong><strong>이다&#46;</strong>

    </details>

    <a id="203eda9b0fe180e78f37f0b1d567f985"></a>

    ```bash
    mkdir -p ~/jenkins_home
    ```

> 📌 
> 
> - EC2 인스턴스 자동 베포 파이프라인 구축
>     - 해당하는 github 클론하여 maven으로 테스트 및 빌드 
> 
>     - <code>scp</code>로 EC2 인스턴스에 jar 파일 복사
> 
>     - <code>ssh</code> 원격 실행&#58; 기존 java 프로세스 종료 및 새로 복사한 jar 파일 실행
> 
>     <details>
>     <summary>slack webhook으로 알람 연동</summary>
> 
>     - Create App → <strong>Webhook URL 추가</strong>
> 
>     - ‣
> 
>     </details>

<a id="204eda9b0fe180418e7cf494d50ee8b2"></a>

```groovy
pipeline {
    agent any

    tools {
        maven "M3"
    }

    environment {
        SERVER_IP = 'ec2-3-37-127-81.ap-northeast-2.compute.amazonaws.com'
        DEPLOY_PATH = '/home/ubuntu'
        USER = 'ubuntu'
        PORT = '8080'
    }

    stages {
        stage('Checkout') {
            steps {
                git url: 'https://github.com/lleellee0/deploy-test.git', branch: 'main'
            }
        }

        stage('Build') {
            steps {
                sh 'mvn clean package'
            }
        }

        stage('Deploy') {
            steps {
                sshagent(['deploy_ssh_key']) {
                    script {
                        def jarFile = sh(script: "ls target/*.jar", returnStdout: true).trim()
                        def jarName = jarFile.tokenize('/').last()

                        // 로그 삭제 및 JAR 복사
                        sh "ssh -o StrictHostKeyChecking=no $USER@$SERVER_IP 'rm -f $DEPLOY_PATH/app.log $DEPLOY_PATH/deploy-check.log' || true"
                        sh "scp -o StrictHostKeyChecking=no $jarFile $USER@$SERVER_IP:$DEPLOY_PATH/"

                        // 애플리케이션 실행 (기존 프로세스 종료 포함)
                        sh """
                        ssh -o StrictHostKeyChecking=no $USER@$SERVER_IP << 'EOF'
													jarName="$jarName"
													pid=\$(pgrep -f "\$jarName")
													if [ -n "\$pid" ]; then
													  kill -9 \$pid
													fi
													nohup java -jar $DEPLOY_PATH/\$jarName --server.port=$PORT > $DEPLOY_PATH/app.log 2>&1 < /dev/null &
													sleep 5
													tail -n 100 $DEPLOY_PATH/app.log > $DEPLOY_PATH/deploy-check.log
													EOF
                        """

                        // 로컬 로그 복사
                        sh "scp -o StrictHostKeyChecking=no $USER@$SERVER_IP:$DEPLOY_PATH/deploy-check.log ."
                    }
                }
            }
        }
    }

    post {
        success {
            script {
                def logContent = readFile('deploy-check.log')
                if (logContent.contains("APPLICATION FAILED TO START")) {
```
