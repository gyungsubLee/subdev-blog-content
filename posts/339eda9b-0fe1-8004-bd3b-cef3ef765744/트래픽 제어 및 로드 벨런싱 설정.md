    <a id="33eeda9b0fe180e4966acf4745743406"></a>

    ```java
    @Configuration
    public class RateLimitConfig {

        @Bean
        public RedisRateLimiter redisRateLimiter() {
            // replenishRate: 초당 허용되는 요청 수

        @Bean
        public KeyResolver userKeyResolver() {
            return exchange -> Mono.just(
                exchange.getRequest().getHeaders().getFirst("X-User-ID") != null ?
                exchange.getRequest().getHeaders().getFirst("X-User-ID") :
                exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()

    }
    ```

<summary>Rate Limiting (요청 제한) 설정</summary>

- Bean Config로 설정
    <a id="33eeda9b0fe180b3a13eea8b555a94f4"></a>

    &#91;코드&#93; <code>RateLimitConfig</code>

    <a id="33eeda9b0fe1808e8a6ae1bdd9916459"></a>

    ```java
    package com.fastcampus.apigateway.config;

    import org.springframework.cloud.gateway.filter.ratelimit.KeyResolver;
    import org.springframework.cloud.gateway.filter.ratelimit.RedisRateLimiter;
    import org.springframework.context.annotation.Bean;
    import org.springframework.context.annotation.Configuration;
    import reactor.core.publisher.Mono;

    @Configuration
    public class RateLimitConfig {

        @Bean
        public RedisRateLimiter redisRateLimiter() {
            // replenishRate: 초당 허용되는 요청 수
            // burstCapacity: 최대 누적 가능한 요청 수
            return new RedisRateLimiter(10, 20);
        }

        @Bean
        public KeyResolver userKeyResolver() {
            return exchange -> Mono.just(
                exchange.getRequest().getHeaders().getFirst("X-User-ID") != null ?
                exchange.getRequest().getHeaders().getFirst("X-User-ID") :
                exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()
            );
        }
    }
    ```

    <details>
    <summary>코드 설명</summary>

    > ✏️ 
    > 
    > <a id="33feda9b0fe1802da408d30e730f9f2a"></a>
    > 
    > <strong>진행 흐름</strong>
    > 
    > 1. 요청이 Gateway로 들어옴
    > 
    > 1. KeyResolver가 <strong>요청자를 식별 (key 생성)</strong>
    > 
    > 1. RedisRateLimiter가 <strong>Redis에서 요청 횟수 체크</strong>
    > 
    > 1. 초과하면 429 (Too Many Requests) 반환

    - <strong> RedisRateLimiter 설정</strong>
        <a id="33feda9b0fe1800fbbfad391e4c3aa30"></a>

        ```java
        @Bean
        public RedisRateLimiter redisRateLimiter() {
            return new RedisRateLimiter(10, 20);
        }
        ```

        - 토큰 버킷(Token Bucket) 알고리즘 기반
            | <strong>파라미터</strong> | <strong>의미</strong> |
            | --- | --- |
            | replenishRate = 10 | 초당 10개의 요청 허용 |
            | burstCapacity = 20 | 최대 20개까지 순간적으로 허용 |

    - <strong>KeyResolver</strong>
        <a id="33feda9b0fe180f98852fba64676e808"></a>

        ```java
        @Bean
        public KeyResolver userKeyResolver() {
            return exchange -> Mono.just(
                exchange.getRequest().getHeaders().getFirst("X-User-ID") != null ?
                exchange.getRequest().getHeaders().getFirst("X-User-ID") :
                exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()
            );
        }
        ```

        - <strong>요청을 구분할 기준(key) 생성</strong>
            1. <strong>로그인 사용자 </strong>→ <strong>유저별 제한</strong>
                <a id="33feda9b0fe180daa1dee764e3275276"></a>

                ```java
                X-User-ID: 123
                → 사용자 단위 rate limit
                ```

                - X&#45;User&#45;ID 있음 → 그걸 key로 사용

            1. <strong>비로그인 사용자 </strong> → <strong>IP별 제한</strong>
                <a id="33feda9b0fe180e6b639d480b6bfa0be"></a>

                ```java
                → IP 기준 rate limit
                ```

                - X&#45;User&#45;ID 없음 → IP 주소를 key로 사용

    </details>

<details>
<summary>🧐 <strong>서킷 브레이커(Circuit Breaker) 패턴</strong></summary>

> ✏️ 
> 
> <a id="33feda9b0fe180f994d1ec33d7464e0a"></a>
> 
> <code>서킷 브레이커(Circuit Breaker) 패턴</code>은 <strong>분산 시스템에서 </strong><strong><u>장애 전파를 막</u></strong><strong>고, </strong><strong><u>빠르게 실패(fail&#45;fast)</u></strong>하도록 하는<strong> 보호 장치</strong>이다&#46;
> 
> - <strong>문제가 생</strong>기면 <strong><u>연결을 끊어</u></strong>버린다&#46;

<details>
<summary>왜 필요한가? → <strong>장애 전파 방지</strong></summary>

<a id="33feda9b0fe1801dacf1cad7fbfa4907"></a>

```yaml
A 서비스 → B 서비스 → DB
```

- B 서비스가 느려지거나 장애 발생

- A는 계속 B를 호출 → 타임아웃 증가

- 쓰레드 고갈 → A도 장애

- 결국 전체 시스템 장애 (Cascade Failure)

</details>

<details>
<summary> <strong>서킷 브레이커(Circuit Breaker) 패턴 개념</strong></summary>

> ✏️ 
> 
> <a id="33feda9b0fe18054af39e913d276a066"></a>
> 
> 문제가 반복되면 호출을 막는다&#46;
> 
> <a id="33feda9b0fe18032947acfd9c88f26d7"></a>
> 
> ```plaintext
> [Closed]
>   ↓ 실패 누적
> [Open]
>   ↓ 일정 시간 후
> [Half-Open]
>   ↓ 성공 → Closed
>   ↓ 실패 → Open
> ```
> 
> - 일정 횟수 이상 실패 → 차단
> 
> - 일정 시간 후 → 복구 시도 

1. <strong><code>Closed</code></strong><strong> (정상 상태)</strong>
    - 요청 정상 처리
        <a id="33feda9b0fe180b9931ce1c3c2ddd752"></a>

        → 실패 카운트 누적

1. <strong><code>Open</code></strong><strong> (차단 상태)</strong>
    - 실패 임계치 초과 시 전환
        <a id="33feda9b0fe18008a97de955a8a5001e"></a>

        <strong>→ 요청을 아예 보내지 않음<br>     즉시 fallback 반환</strong>

        <a id="33feda9b0fe180be9217f67419eb3507"></a>

        ```plaintext
        A → ❌ (B 호출 안함)
        ```

1. <strong><code>Half&#45;Open </code></strong><strong>(복구 확인 상태)</strong>
    - 일정 시간 후 일부 요청만 허용
        - 성공하면 → Closed

        - 실패하면 → 다시 OPEN

<summary><strong>코드 예시 (Spring &#43; Resilience4j)</strong></summary>

- 의존성
    <a id="33feda9b0fe18077be2eebe88550095a"></a>

    ```groovy
    implementation 'org.springframework.cloud:spring-cloud-starter-circuitbreaker-resilience4j'
    ```

- 설정
    <a id="33feda9b0fe180dcbaf4c6e6bb214bf4"></a>

    ```yaml
    resilience4j:
      circuitbreaker:
        instances:
          userService:
            slidingWindowSize: 10
            failureRateThreshold: 50
            waitDurationInOpenState: 10s
    ```

    | <strong>옵션</strong> | <strong>의미</strong> |
    | --- | --- |
    | <code>slidingWindowSize</code> | 최근 요청 개수 |
    | <code>failureRateThreshold</code> | 실패율 (%) 기준 |
    | <code>waitDurationInOpenState</code> | Open 상태 유지 시간 |
    | <code>permittedNumberOfCallsInHalfOpenState</code> | Half&#45;Open 테스트 요청 수 |

- 코드
    <a id="33feda9b0fe180c5b54defb7c9938cb7"></a>

    ```java
    @Service
    public class UserClient {

        @CircuitBreaker(name = "userService", fallbackMethod = "fallback")
        public String callUserService() {
            return restTemplate.getForObject("http://user-service/api", String.class);
        }

        public String fallback(Throwable t) {
            return "fallback response";
        }
    }
    ```

```yaml
# api-gateway/.../application.yml
... 

resilience4j:
  circuitbreaker:
    instances:
      authCircuitBreaker:
        registerHealthIndicator: true
        slidingWindowSize: 5 # 서킷 브레이커가 고려할 최근 호출 수
        minimumNumberOfCalls: 10 # 최소 호출 횟수, 이 수를 넘어야 서킷 브레이커의 상태가 변경됨
        permittedNumberOfCallsInHalfOpenState: 10 # 반-열린 상태에서 허용되는 호출 수
        automaticTransitionFromOpenToHalfOpenEnabled: true # 서킷 브레이커가 자동으로 반-열린 상태로 전환되는지 여부
        waitDurationInOpenState: 5000 # 서킷 브레이커가 열린 상태로 유지되는 시간
        failureRateThreshold: 50 # 실패율 기준, 이 비율을 초과하는 실패가 발생하면 서킷 브레이커가 열립니다
        eventConsumerBufferSize: 10
        record-exceptions:
          - java.util.concurrent.TimeoutException
          - org.springframework.cloud.gateway.support.NotFoundException
          - io.github.resilience4j.circuitbreaker.CallNotPermittedException
```

- <strong>slidingWindowSize</strong> → 실패율 계산에 사용할 최근 요청 개수

- <strong>minimumNumberOfCalls</strong> → 이 횟수 이상 호출돼야 실패율 계산 시작

- <strong>failureRateThreshold</strong> → 이 실패율(%) 넘으면 Circuit Open

- <strong>waitDurationInOpenState</strong> → Open 상태를 유지하는 시간

- <strong>permittedNumberOfCallsInHalfOpenState</strong> → Half&#45;Open에서 테스트 요청 개수

- <strong>automaticTransitionFromOpenToHalfOpenEnabled</strong> → Open → Half&#45;Open 자동 전환 여부

- <strong>registerHealthIndicator</strong> → Actuator health에 Circuit 상태 노출 여부

- <strong>eventConsumerBufferSize</strong> → Circuit 이벤트 저장 버퍼 크기

- <strong>record&#45;exceptions</strong> → 실패로 간주할 예외 목록
