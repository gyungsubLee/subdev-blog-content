## Cascade (영속성 전이)

---

> 📖 

<details>
<summary>사용 위치</summary>

> 연관관계 주인 반대편 (역방향) &#45; 부모 엔티티, <code>N&#58;1</code> 관계에서의 <code>1</code> 

- <code>&#64;OneToMany</code> ( <code>&#64;OneToOne</code> 도 가능 )

- ex) 게시글 &#45; 첨부파일 ( <code>1&#58; N</code> ) 에서의 게시글(<code>1</code>)에 설정

</details>

<details>
<summary>사용 조건</summary>

- <u>양쪽 엔티티</u>의 <u>라이프 사이클</u>이 <u>동일</u>하거나 <u>비슷</u>해야한다&#46; 
    - ex) 게시글 삭제 시, 첨부파일도 같이 삭제

- 대상 엔티티의 영속성 전이는 현재 엔티티에서만 전이 되어야 한다&#46; 
    - 의존성의 depth가 1 이상인 경우, 사용 X

    - ex) 첨부파일을 게시글이 아닌 다른 곳에서 영속성 전이 하면 안된다&#46;

</details>

<details>
<summary>옵션 종류</summary>

- <code>ALL</code>&#58; 전체 상태 전이

- <code>PERSIST</code> &#58; 저장 상태 전이

- <code>REMOVE</code> &#58; 삭제 상태 전이

> 아래 3개는 거의 안씀

- <del><code>MERGE</code></del><del> &#58; 업데이트 상태 전이</del>

- <del><code>REFERESH</code></del><del> &#58; 갱신 상태 전이</del>

- <del><code>DETACH</code></del><del> &#58; 비영속성 상태 전이</del>

<a id="159eda9b0fe1805daaa2fc3acbde5fb3"></a>

```java

/**
 * Defines the set of cascadable operations that are propagated
 * to the associated entity.
 * The value<code>cascade=ALL</code>is equivalent to
 *<code>cascade={PERSIST, MERGE, REMOVE, REFRESH, DETACH}</code>.
 *
 *@since1.0
 */
public enum CascadeType {

/** Cascade all operations */
ALL,

/** Cascade persist operation */
PERSIST,

/** Cascade merge operation */
MERGE,

/** Cascade remove operation */
REMOVE,

/** Cascade refresh operation */
REFRESH,

/**
     * Cascade detach operation
     *
     *@since2.0
     *
     */
DETACH
}

```

</details>

## <strong>orphanRemoval (고아 객체 제거)</strong>

---

> 📖 
> 
> <a id="6cc0423b1ed0447686818cbb13de88c7"></a>
> 
> 부모 객체에서 리스트 요소삭제를 했을경우 해당 자식 객체는 매핑정보가 없어진다&#46; <br>이를 부모가 제거된다고 하여 고아객체라 하는데, 해당 기능을 통해 이러한 고아 객체를 자동으로 삭제 처리한다&#46;
> 
> - <strong>Cascade&#46;REMOVE</strong> 와 비슷한 용도로 <u>삭제를 전파</u>하는데 쓰인다&#46;

<details>
<summary>사용 위치</summary>

> 부모 엔티티

- <code>&#64;OneToMany</code>, <code>&#64;OneToOne</code> 

</details>

- 옵션 &#45; <code>true</code>, <code>false</code>

<details>
<summary>🧐 <code>Cascade&#46;REMOVE</code> 와 <code>orphanRemoval</code> 차이점</summary>

- <code>Cascade&#46;REMOVE</code>의 경우, <code>1&#58;N</code> 관계에서 <code>1</code>에 해당하는 부모 엔티티를 <code>em&#46;remove()</code>를 통해 직접 삭제하는 경우, 하위에 존재하는 <code>N</code>의 자식 엔티티들이 같이 삭제되는 것이다&#46; 


- <code>orphanRemoval=true</code>는 위 케이스도 포함하며, <code>1</code>에 해당하는 부모 엔티티의 리스트에서 요소를 삭제하기만 해도 해당 <strong>다</strong>에 해당하는 자식 엔티티가 delete된다&#46; 
    <a id="159eda9b0fe18039b8b9d68b8a1ba1b8"></a>

    즉, <strong>orphanRemoval=true 는 리스트 요소로써의 영속성 전이도 해준다</strong>

</details>

> ✏️ 
> 
> <a id="88ada00d78fc4da4aa48f9f5ca44f743"></a>
> 
> 영속성 전이 최강 조합&#58; <code>orphanRemoval=true</code> &#43; <code>Cascase&#46;ALL</code>
> 
> <a id="159eda9b0fe180ea8148d9a2f3b9f43d"></a>
> 
> 위 2개를 함께 설정 시, 아래와 같은 이점이 있다&#46; 
> 
> - <u>자식 엔티티와 부모 엔티티</u>의 <strong><u>생명주기( Life Cycle )</u></strong> 가 <strong><u>동일</u></strong>해진다&#46; 
> 
> - <strong><u>직접 자식 엔티티의 생명주기를 관리</u></strong>할 수 있어, <u>자식 엔티티의 repository 조차 없</u>어도 된다&#46; 
>     - 부모 엔티티 저장 시, 하위 자식 엔티티들도 같이 저장됨
> 
>     - 부모 엔티티 삭제 시, 하위 자식 엔티티 들도 같이 삭제됨
> 
> <a id="159eda9b0fe180be9a39f39bddbc1169"></a>
> 
> 해당 방법을 매핑 테이블에서 많이 사용한다&#46;

## Fetch (조회시점) &#45; 즉시로딩, 지연로딩

---

> 📖 

<details>
<summary>사용 위치</summary>

> Entity의 연관관계 설정 필드에 FetchType으로 설정 가능하다&#46;

- <code>&#64;ElementCollection</code>, <code>&#64;ManyToMany</code>, <code>&#64;OneToMany</code>, <code>&#64;ManyToOne</code>, <code>&#64;OneToOne</code>

> ✏️ 
> 
> <a id="3f473e0a18b54969b262ea4d6e4dba3b"></a>
> 
> Query 수행시 <strong><u>fetch Join </u></strong>을 통해서<u> LAZY 인 경우도 즉시 불러올 수 있</u>다&#46;

</details>

<details>
<summary>사용법</summary>

- <u>기본을 </u><u>LAZY (지연로딩)</u><u> 설정</u> 후, <u>필요한 때만 </u><u>fetch Join을 통해 한번에 불러</u>온다&#46; 

- <u>항상 같이 쓰이는 연관관계인 경우</u>만, 따로<u> EAGER로 설정</u>하여 사용한다&#46; 

</details>

<details>
<summary>옵션 &#45; FetchType</summary>

- EAGER &#58; 즉시 로딩 (부모 조회 시 자식도 같이 조회)

- <strong>LAZY</strong> &#58; 지연 로딩 (자식은 필요할때 따로 조회)
    - 프록시 객체를 조회하며, 실제 사용 시에만 쿼리를 날림

<a id="159eda9b0fe180a689a9e85c18781e0a"></a>

```java
/**
 * Defines strategies for fetching data from the database.
 * The<code>EAGER</code>strategy is a requirement on the persistence
 * provider runtime that data must be eagerly fetched. The
 *<code>LAZY</code>strategy is a hint to the persistence provider
 * runtime that data should be fetched lazily when it is
 * first accessed. The implementation is permitted to eagerly
 * fetch data for which the<code>LAZY</code>strategy hint has been
 * specified.
 *
 *<pre>
*   Example:
 *&#064;Basic(fetch=LAZY)
 *   protected String getName() { return name; }
 *</pre>
*
*@see Basic
*@see ElementCollection
*@see ManyToMany
*@see OneToMany
*@see ManyToOne
*@see OneToOne
*@since1.0
 */
public enum FetchType {

/** Defines that data can be lazily fetched. */
LAZY,

/** Defines that data must be eagerly fetched. */
EAGER
}
```

</details>
