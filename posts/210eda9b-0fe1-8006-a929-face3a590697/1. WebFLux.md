## Spring WebFlux

---

> 📖 
> 
> <a id="212eda9b0fe18083abf6c8dd3ee108ef"></a>
> 
> <code>Spring WebFLux</code>는 <strong><u>Spring Framework 5&#46;0</u></strong>에서 도입된 <strong>리액티브(reactive) 프로그래밍</strong> 기반 웹 프레임워크이다&#46; 
> 
> - 전통적인 <strong><code>Spring MVC</code></strong>가 <u>서블릿 API</u>와 <u>블로킹 I/O</u>를 기반으로 하는데 반해, 
> 
> - <code>WebFlux</code>는 <strong><u>논블로킹(Non&#45;blocking) I/O</u></strong> 와 <strong><u>Reactive Streams</u></strong> 표준을 지원하여 <strong><u>높은 동시성 처리와 효율적인 리소스 사용</u></strong>이 가능하다&#46;

<details>
<summary>주요 특징</summary>

- <code>비동기</code> / <code>Non&#45;blocking</code>
    - HTTP 요청을 처리할 때 <strong><u>쓰레드를 점유하지 않</u></strong>고 데이터가 도착하면 반응적으로 처리

    - 요청 처리 중 스레드가 블로킹 되지 않아 적은 리소스로 더 많은 요청을 처리할 수 있다&#46;

- <code>리액티브 스트림 지원</code>
    - <code>Mono&#60;T&#62;</code>, <code>Flux&#60;T&#62;</code> 형태로 Publisher를 반환

    - Reactor의 <strong><u>Flux(다수 데이터)</u></strong>와 <strong><u>Mono(단일 데이터)</u></strong> 타입을 사용하여 데이터 선언적으로 조작한다&#46;

- <code>서버 선택의 유연성</code>
    - Netty, Undertow, 서블릿 컨테이너(ex&#46; Tomcat) 등 다양한 서버에서 동작한다&#46; 

    - 경량 서버 지원 &#45; Netty 기반 서버 포함

- <code>적은 리소스로 많은 요청 처리</code>
    - 적은 쓰레드로 수천 &#126; 수만 개의 연결 유지 가능

</details>

<details>
<summary><strong>기존 </strong><strong><code>MVC</code></strong><strong> vs </strong><strong><code>WebFlux</code></strong><strong> 비교</strong></summary>

| 항목 | <code>Spring MVC</code>  | <code>Spring WebFlux</code> |
| --- | --- | --- |
| 실행 모델 | 동기 &#43; 블로킹  | 비동기 &#43; 논블로킹 |
| 컨트롤러 반환 타입 | Spring, List, ResponseEntity 등 | Mono, Flux |
| 서버 | 서블릿 기반(Tomcat) | Netty, Undertow, 서블릿 3&#46;1 비동기 |
| 병렬 처리 | Thread Pool | 이벤트 루프 기반 |

</details>

<details>
<summary><strong> 언제 </strong><strong><code>WebFlux</code></strong><strong>를 사용하는 것이 좋은가?</strong></summary>

| <strong>사용 시나리오</strong> | <strong>설명</strong> |
| --- | --- |
| 실시간 알림 서비스 | SSE, WebSocket과 잘 맞음 |
| 수천 개 이상의 동시 요청 처리 | 논블로킹 구조 덕분에 적은 리소스로 가능 |
| 외부 API 병렬 호출이 많을 때 | WebClient &#43; Mono/Flux로 효율적 |
| 마이크로서비스 | 리액티브 환경에 적합 (ex&#46; RSocket, Kafka, Redis PubSub 등과 결합) |

</details>

<details>
<summary><strong>WebFlux의 핵심 구성요소</strong></summary>

- <code>Mono&#60;T&#62;</code>&#58; 0 또는 1개의 비동기 데이터

- <code>Flux&#60;T&#62;</code>&#58; 0 &#126; N 개의 스트림 데이터

- <code>WebClient</code>&#58; 리액티브 HTTP 클라이언트 ( RestTemplate 대체 )

- <code>RouterFunction</code>&#58; 함수형 라우팅 방식

- <code>Sinks&#46;Many</code>&#58; 비동기 스트림 생성 및 발행 도구

- <code>Netty</code>&#58; 기본 논블로킹 HTTP 서버 구현체ㄴ

</details>

<details>
<summary>구조</summary>

<a id="212eda9b0fe180618171d1f2d2be32b1"></a>

```java
[Client Request]
       ↓
[Netty (논블로킹 IO)]
       ↓
[DispatcherHandler]
       ↓
[Handler → Mono/Flux 반환]
       ↓
[응답 스트림 전송]
```

</details>
