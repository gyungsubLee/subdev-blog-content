1. 왜 개발자를 선택하였는가?
    - 취미로 공부를 시작했다가, 생각보다 적성에 맞아서 진로를 선택하게 되었습니다&#46;

    -  공부를 하고, 해당 내용을 정리 및 이해를 하며, 그에 맞게 구현을 하는 이 과정이 꽤 재밌는 것 같습니다&#46; 

    - 아직까지 베포나 서비스 운영을 해보지는 못하였으나, 실제 내가 만든 서비스가 사용자가 사용하며 그에 따른 가치 창출이 이뤄진다면 굉장히 보람차고 재밌을 것 같다고 생각하고 있습니다&#46; 

1. 프로젝트 준비 내용
    > 진행 중인 프로젝트 간단한 서비스 소개

    - 프로젝트 이름&#58; Connect
        - 각 개인 마다 본인들의 취미에 해당하는 활동들을 계획하고 비슷한 사람들을 매칭하여 소통하도록 도와주는 앱

    >  본인이 담당한 부분, 기여도, 왜 그렇게 생각했는지 이유

    - 담당한 기능&#58; 채팅, 알람

    - 기여도&#58;  1인분 하려고 노력하고 있습니다&#46;
        <a id="7785bf55431b402d9cae4cbf5633e891"></a>

        팀원들이 뛰어나셔서 부지런히 따라가려고 하고 있습니다&#46; 

    - 사용한 기술 내용
        - Java, Spring, JPA

        - MySQL

        - WebSocket

1. 본인 구현 기능에 대한 설명, 사용한 기술, 그 이유 
    > 구현 기능&#58; 실시간 채팅

    > 사용한 기술&#58; WebSocket, 메세지 브로커 

    > WebSocket 사용 이유

    <a id="cff608a03d76445caf26afb03d1e8c21"></a>

    기존에 많이 사용한 HTTP 통신 방식은 매 요청마다 TC  P/IP 연결이 이루어져야 한다&#46; 

    <a id="db0091ef38a445c891a332eb3ac4df3e"></a>

    즉, 3 Way Hand Shake 비용이 발생된다&#46; 

    <a id="ebaa6138b72f4e8196a0603733f8e075"></a>

    따라서 지속적인 트래픽이 발생되는 상황인 경우, HTTP 통신 방식은 효율적이지 못하다&#46; 

    <a id="39ee328f51ad41e9b31199af2fbadbf7"></a>

    또한 실시간 채팅의 경우, 상대방의 메세지를 요청없이 받아야 한다&#46; 이는 HTTP 통신 방식으로는 해결할 수 없다&#46; 

    <a id="17849018c0ec4990a69b5cadb534ae4c"></a>

    이를 해결하기 위해서 WebSocket 통신을 사용한다&#46; 

    <a id="bf0f1303b7df49e987e53749ce9da0d0"></a>

    WebSocket 통신을 사용하면, HTTP의 ‘비연결성’ 과, ‘비상태성’을 해결할 수 있다&#46; 

    > 메세지 브로커

    <a id="c6e7d995ad0d4b26a86dde9f2cd02f9a"></a>

    메세지 브로커를 사용 시, 클라이언트에서 채널(채팅방)을 구독하면, 이후 발행되는 메세지들을 해당 채널에 전달하고, 해당 채널은 구독한 모든 클라이언트들에게 브로드캐스트 처리한다&#46;
