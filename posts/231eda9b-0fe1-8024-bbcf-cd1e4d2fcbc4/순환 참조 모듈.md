## 순환 참조(의존성) 

---

> ✏️ 
> 
> <a id="231eda9b0fe1800d8cfbf23d549013f2"></a>
> 
> <code>순환 의존성(Circular dependency</code><strong><code>)</code></strong>는 두 클래스가 서로 의존할 때 발생한다&#46;
> 
> - ex) 클래스 A는 클래스 B를 필요로 하고, 클래스 B도 클래스 A를 필요로 한다&#46;
> 
> <a id="231eda9b0fe180a0a7ebf2187506c0c5"></a>
> 
> Nest에서는 <code>Module</code> 및 <code>Provider</code> 간에 <strong><u>순환 종속성이 발생할 수 있</u></strong>다&#46;
> 
> <a id="231eda9b0fe180619536ea3e5fdf55f2"></a>
> 
> 순환 종속성은 가능한 피해야 하지만, 항상 그럴 수 없다&#46;
> 
> <a id="231eda9b0fe18089b20ac2e15c3dfa9e"></a>
> 
> 이러한 경우 Nest에서는 2가지 방법으로 공급자 간의 순환 종속성을 해결할 수 있도록 한다&#46; 
> 
> 1. <strong>전방 참조</strong>
> 
> 1. <strong>ModuleRef</strong> 클래스

<a id="231eda9b0fe181d3b08bf3333ecd52b3"></a>

### 문제점

<a id="231eda9b0fe180339a2ccb3d5f6f3a7d"></a>

두 모듈이 서로를  import하여 순환 참조가 발생되고 있다&#46;

<a id="231eda9b0fe1801c8db4c94ba0ee3bcc"></a>

```typescript
// common.module.ts
@Module({
  imports: [CatsModule],
})
export class CommonModule {}


// cats.module.ts
@Module({
  imports: [CommonModule],
})
export class CatsModule {}
```

<a id="231eda9b0fe180958377f52c0221ed97"></a>

### 해결

> ✏️ 
> 
> <a id="231eda9b0fe1809a817ccba288497e1c"></a>
> 
> 모듈 간의 순환 종속성을 해결을 위해,  양쪽 모듈 <code>import</code>에  <code>forwardRef()</code> 유틸리티 함수를 사용하여 모듈을 불러온다&#46; 

<a id="231eda9b0fe18076a54fcd927feda576"></a>

```typescript
// common.module.ts
@Module({
  imports: [forwardRef(() => CatsModule)],
})
export class CommonModule {}


// cats.module.ts
@Module({
  imports: [forwardRef(() => CommonModule)],
})
export class CatsModule {}
```
