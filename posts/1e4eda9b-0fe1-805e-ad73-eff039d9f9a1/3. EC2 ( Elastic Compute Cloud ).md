### 1&#46; <code>EC2</code> ( Elastic Compute Cloud ) 

> 📖 
> 
> <a id="1e9eda9b0fe180869015d0aeac2351a4"></a>
> 
> EC2는 <code>Elastic Compute Cloud</code>의 줄임말이다&#46;
> 
> <a id="1e9eda9b0fe180e1a763e30abfea6053"></a>
> 
> AWS에서 제공되는 컴퓨팅 서비스, 즉 <code>EC2</code>를 통해 <strong><u>서버 장비 구축없이 쉽게 탄력적으로 서비스를 운영</u></strong> 할 수 있다&#46;

<details>
<summary>클라우드 서비스 종류</summary>

- <code>IaaS</code> ( Infrastructure as a Service )
    - 하드웨어 인프라를 인터넷을 통해 제공하는 서비스

    - <code>IaaS</code>는 가상화된 하드웨어, 스토리지, 네트워크, 운영체제 등을 제공하며, 사용자는 이를 통해 서비스를 구축할 수있다&#46; 

    - ex) <code>AWS EC2</code>, <code>Microsoft Azure</code>, <code>Google Compute Engin</code> 등

- <code>PaaS</code> ( Platform as a Service )
    - 애플리케이션을 개발, 실행 관리하기 위한 플랫폼
        - 동일하게 인터넷을 통해 서비스를 제공한다&#46;

    - <code>PaaS</code>는 IaaS에서 제공하는 하드웨어 인프라와 미들웨어를 이용하여 앱 개발, 베포, 운영 등에 필요한 환경을 제공한다&#46;

    - ex) <code>AWS Elastic Beanstalk</code>, <code>Heroku</code>, <code>Goolge App Engine</code> 등

- <code>SaaS</code> ( Software as a Service )
    - 사용자에게 완전한 애플리케이션 제공
        - 해당 애플리케이션은 클라우드 제공업체의 서버에서 실행된다&#46; 

        - 대부분의 사용자에게 필요한 소프트웨어 서비스를 제공한다&#46; 

    - 사용자가는 앱에 대한 제한된 제어권을 가지며, 클라우드 제공업체가 모든 인프라, 운영체제, 백엔드 앱 및 데이터 관리를 담당한다&#46;

    - ex) <code>구글 드라이브</code>, <code>마이크로소프르 오피스 365</code>, <code>Salesforce</code> 등 

</details>

<details>
<summary>EC2란?</summary>

> <strong>EC2</strong>

<a id="1e9eda9b0fe18038a5d9f799ab64e112"></a>

EC2는 Elastic Compute Cloud의 줄임말이다&#46;

<a id="1e9eda9b0fe18053816aff1ff887d75c"></a>

AWS에서 제공되는 클라우드 컴퓨팅 서비스, 즉 <code>EC2</code>를 통해 서버 장비 구축없이 쉽게 탄력적으로 서비스를 운영 할 수 있다&#46;

- <code>Elastic</code>  &#45; 고무줄의 탄력성을 뜻한다&#46;

> <strong>탄력적 운영</strong>

<a id="1e9eda9b0fe1800ab287e6d42e762321"></a>

여기서 ‘탄력적’이라는  말은 ‘유연성’과 같은 의미이다&#46; 

<a id="1e9eda9b0fe180bf9dcefbd6bea1a7be"></a>

트래픽이 증가될 경우, EC2 인스턴스를 추가하여 처리하다가

<a id="1e9eda9b0fe1801d8d07c3872b78e551"></a>

다시 감소하거나 사용되지 않을 경우 해당 인스턴스를 중단 및 삭제하여 상황에 맞게 적절하게 서비스를 운영할 수 있다&#46;

- 필요한 시간만큼 가상 서버를 생성하고 사용 가능

- 필요에 따라 스케일 업 또는 스케일 다운 가능

> <strong>인스턴스 </strong>

<a id="1e9eda9b0fe1800c93e1f91fe42b5edc"></a>

해당 환경은  실제로는<u> 하드웨어 리소스를 가상화</u>하여 사용하고 있기 때문에, 하드웨어 상에서 실행 중인 <u>물리적인 서버와는 다르다&#46;</u>

<a id="1e9eda9b0fe1808fab67d971a1d8b47e"></a>

따라서 이러한 가상화된 컴퓨팅 환경을 ‘인스턴스(instance)’ 라 부르며 각 인스턴스는 독립적으로 실행되고 관리된다&#46; 

- 필요에 따라 생성, 시작, 중지, 종료 등이 가능하다&#46;

> <strong>인스턴스 유형 </strong>

<a id="1e9eda9b0fe180bcba57cc7f7144df97"></a>

EC2 인스턴스는 다양한 운영 체제 (예&#58; Linux, Windows)와 인스턴스 유형 (예&#58; 범용, 컴퓨팅 최적화, 메모리 최적화)을 지원한다&#46;

- 웹 애플리케이션 호스팅

- 데이터베이스 호스팅

- 컴퓨팅 작업 (예&#58; 데이터 분석, 머신 러닝)

- 애플리케이션 테스트 및 개발

</details>

<details>
<summary>EC2 옵션</summary>

<details>
<summary>1&#46; 인스턴스 유형 (Instance Types)</summary>

- 인스턴스 유형은 서버에 할당되는 CPU, 메모리, 스토리지 및 네트워크 리소스와 같은 기본 성능 스펙을 결정한다&#46; 

</details>

<details>
<summary>2&#46; 운영 체제 ( Operating System )</summary>

- EC2 인스턴스는 다양한 운영체제를 지원한다&#46; 

- ex) Amazon Linux, Ubuntu, Window 등

</details>

<details>
<summary>3&#46; 스토리지 옵션 ( Storage Options )</summary>

- EC2 인스턴스에는 인스턴스 스토어, Amazon EBS 및 Amazon S3 와 같은 다양한 스토리지 옵션이 있다&#46;

</details>

<details>
<summary>4&#46; 보안 그룹 ( Security Groups )</summary>

- 보안 그룹은 인바운드 및 아웃바운드 트래픽을 제어하는 방화벽 규칙이다&#46; 

- 각 보안 그룹은 포트범위, 프로토콜 및 허용되는 IP 주소 범위를 정의 가능하다&#46;

</details>

<details>
<summary>5&#46; 키 페어 ( Key Pair )</summary>

- 키 페어는 EC2 인스턴스에 대한 SSH 엑세스를 허용한다&#46; 

- 키 페어 생성한다면 EC2 인스턴스 시작(생성) 시 원하는 키페어를 설정 가능하다&#46; 

</details>

<details>
<summary>6&#46; 탄력적 IP 주소 ( Elastic IP Address )</summary>

- 탄력적 IP 주소는 EC2 인스턴스에 고정 IP 주소를 할당한다&#46; 

- 이는 EC2 인스턴스를 중지하거나 시작할 때마다 IP 주소가 변경되는 것을 방지할 수 있다&#46;
    - 왜 변경되는가?

</details>

<details>
<summary>7&#46; 사용 가능한 영역 ( Availability Zones ) </summary>

- EC2 인스턴스는 여러 가용 영역에서 실행될 수 있다&#46; 

- 이는 장애 대응 및 고가용성을 위해 중요하다&#46;

</details>

</details>

<summary>포트</summary>

- <code>22</code>&#58;  ssh ( secure shell ) 로 인스턴스에 원격 접속

- <code>21</code>&#58; FTP 파일 전송 프로토콜

- <code>80</code>&#58;  http 웹 접속 

- <code>443</code>&#58; https &#45; http &#43; secure ( 보안 ) 

<a id="1ebeda9b0fe1805ab689d71e7f544d43"></a>

개발 할 때, 보통 <code>80</code>, <code>443</code> 두개 다 열고 시작한다&#46; 

- HTTPS 설정을 바로 하지 않기 때문에 보통 HTTP 설정도 추가한다&#46; 

- 나중에 도메인 설정 후, 인증서 발급이 완료되면 HTTPS 통신이 가능하다&#46;

### 3&#46; EC2 <code>SSH</code> ( 로컬 환경에서 접속 )

<details>
<summary>🧐 <code>chmod</code></summary>

> ✏️ 
> 
> <a id="1ebeda9b0fe180e3a505f159bd29aa5e"></a>
> 
> <code>chmod</code>는 <strong>파일, 디렉토리 </strong><strong><u>권한을 변경</u></strong>하는 유닉스 명령어이다&#46; 
> 
> <a id="1ebeda9b0fe1803d9b79feb82bd4f323"></a>
> 
> ```bash
> chmode { 권한 번호 } { 파일명 or 디렉토리명 }
> ```

<details>
<summary><strong><u>파일, 디렉토리</u></strong>는  <strong><u>소유자(owner), 그룹(group), 기타(others</u></strong><u>)</u> 카테고리를 갖는다&#46;</summary>

| <strong>카테고리</strong> | <strong>설명</strong> |
| --- | --- |
| <strong>소유자 (</strong><strong><code>owner</code></strong><strong>)</strong> | 해당 파일을 만든 사용자&#46; |
| <strong>그룹 (</strong><strong><code>group</code></strong><strong>)</strong> | 해당 파일이 속한 그룹의 사용자들&#46; |
| <strong>기타 (</strong><strong><code>others</code></strong><strong>)</strong> | 위 두 범주에 속하지 않는 모든 사용자&#46; |

</details>

<details>
<summary>각 카테고리는 <strong><u>3 가지 권한</u></strong>(<code>읽기</code>, <code>실행</code>&#46; <code>쓰기</code>) 가진다&#46;</summary>

| <strong>권한</strong> | <strong>기호</strong> | <strong>설명</strong> |
| --- | --- | --- |
| 읽기 | <code>r</code> | 파일 내용을 읽을 수 있음 <br>(디렉토리 라면 목록 확인 가능) |
| 쓰기 | <code>w</code> | 파일 내용을 수정하거나 삭제 가능 <br>(디렉토리 라면 파일 추가/삭제 가능) |
| 실행 | <code>x</code> | 실행 가능한 파일이면 실행할 수 있음 (디렉토리 라면 진입 가능) |

- 각 카테고리는 3가지 권한 중 <strong><u>일부 또는 전부</u></strong>를 가질 수 있다&#46; 

</details>

</details>

<details>
<summary>🧐 권한 번호</summary>

> ✏️ 
> 
> <a id="1ebeda9b0fe180ecbf18d9536a1f922b"></a>
> 
> <strong>권한 번호</strong>&#58; <code>XXX</code>
> 
> ---
> 
> - <strong><code>1번째 자리</code></strong>&#58; 소유자 권한 설정
> 
> - <strong><code>2번째 자리</code></strong>&#58; 그룹 권한 설정
> 
> - <strong><code>3번째 자리</code></strong>&#58; 기타 권한 설정

- <code>1</code>&#58; 실행 권한

- <code>2</code>&#58; 쓰기 권한

- <code>4</code>&#58; 읽기 권한

- <code>6</code>&#58; 읽기(4) &#43; 쓰기(2), 더한 값

---

- <code>소유자</code>&#58; 읽기

- <code>그룹</code>&#58; ❌

- <code>나머지</code>&#58; ❌

<details>
<summary>SSH 연결</summary>

> ✏️ 
> 
> <a id="1ebeda9b0fe1805b8a65c7bae75508ed"></a>
> 
> 생성한 <strong><u>SSH 키</u></strong>를 활용하여 <strong><u>로컬 환경에서 EC2 인스턴스 콘솔에 접속</u></strong> 가능하다&#46; 

<a id="1e9eda9b0fe18033b85afacb102506ec"></a>

```bash

# 1. SSH 키 파일에 권한 설정
chmod 400 [keypair 파일명]

# 2. SSH 접속
ssh -i [keypair 파일명] [유저명]@[IP 주소]   # unbuntu 기본 유저명: ubuntu

# 3. 접속 종료
exit
```

### 4&#46; EC2 인스턴스 백업 &#45; <code>EBS</code> ( Elastic Block Store )

<details>
<summary>EBS</summary>

> ✏️ 
> 
> <a id="1ebeda9b0fe1801da656ca7f1e40d7d1"></a>
> 
> <code>EBS</code> ( <strong>Elastic Block Store</strong> )
> 
> ---
> 
> - EBS는 <strong>EC2 인스턴스에 연결</strong>할 수 있는 <strong><u>블록 수준 스토리지 볼륨</u></strong>이다&#46;
> 
> - 데이터 지속성을 보장하기 위해<strong><u> AWS 내에서 복제 및 백업</u></strong>되므로<strong><u> 안정적</u></strong><u>이고, </u><strong><u>내결함성이 높</u></strong>은 스토리지 옵션이다&#46; 
> 
> - 네트워크를 통해 EC2 인스턴스에 연결된다&#46; <br>따라서<strong><u> 데이터 지속성</u></strong><strong>, </strong><strong><u>스냅샷 백업</u></strong><strong> 및 </strong><strong><u>다른 인스턴스에서 쉽게 사용</u></strong>할 수 있다&#46; 
> 
> ![](690f810ac780bebf.webp)
> 
> > <strong>비유) </strong><strong>인스턴스의 usb 메모리</strong>
> 
> - 인스턴스를 terminate(삭제) 한 후에도 데이터를 유지할 수 있다&#46;
> 
> - 특정 AZ에 한정된다&#46;
> 
> - 하나의 EBS에는 하나의 인스턴스만 연결 가능하지만, <br>하나의 인스턴스에는 여러 EBS가 연결될 수 있다&#46; 
>     - <strong><code>EC2 인스턴스 &#58; EBS</code></strong> = <code>1&#58;N</code>
>

> 
> - 복원을 하는데 시간은 오래걸리나, 비용 절약이 된다&#46;
