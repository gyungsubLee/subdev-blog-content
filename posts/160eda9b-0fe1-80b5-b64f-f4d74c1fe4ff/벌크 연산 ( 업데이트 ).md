## 서론

---

<a id="160eda9b0fe180a1810fd2cc05d41581"></a>

Querydsl에 대해  추가 학습하면서  벌크 연산을 통한 최적화 방법을 알게 되었다&#46; 

<a id="160eda9b0fe1804d88ecf406b0a68437"></a>

그러면서 JPQL이나, SQL 등 다른 방법이 없을까 궁금증이 생겨 찾아보고 그에 대한 내용을 정리한다&#46; 

<a id="160eda9b0fe1808bbc15cc2bbd220e6a"></a>

## 벌크 연산

---

<a id="160eda9b0fe18059ba97e5c735ee5b49"></a>

벌크  연산는 JPA에서 <strong><u>여러 엔티티를 한 번에 효율적으로 쓰기(</u></strong><strong><u><code>C</code></u></strong><strong><u>, </u></strong><strong><u><code>U</code></u></strong><strong><u>, </u></strong><strong><u><code>D</code></u></strong><strong><u>) 연산</u></strong> 하는 방법으로 <br>해당 기능을사용 시,  <strong><u>단일 쿼리로 다수의 데이터를 변경</u></strong>할 수 있어 <strong><u>성능을 크게 향상</u></strong>시킬 수 있다&#46;

- 벌크 업데이트의 특징
    - 단일 쿼리 실행
        - 벌크 업데이트는 하나의 쿼리로 여러 행을 동시에 업데이트 가능

    - 영속성 컨텍스트 우회
        - 벌크 연산은 <u>영속성 컨텍스트를 거치지 않</u>고 <strong><u>데이터베이스에 직접 쿼리 날림</u></strong>

        - 따라서 영속성 컨텍스트와 DB 사이에 불일치 문제가 발생할 수 있기 때문에, 사용에 주의 필요
            - 벌크 연산 이후  <strong><u>동일 트랜잭션에서 바로 조회가 필요한 경우</u></strong>,  <strong>영속성 초기화 필요</strong><strong>함</strong>

    - 적용 범위
        - 주로 <code>UPDATE</code>와 <code>DELETE</code> 연산에 사용되며, <strong>Hibernate를 사용</strong>할 경우 <strong><u><code>INSERT</code></u></strong><strong><u> 연산도 가능</u></strong>

## 사용 방법

---

<a id="160eda9b0fe1801ebceee0e36529432f"></a>

### JDBC &#45; Batch Insert

<details>
<summary>MySQL을 사용하는 경우, <code>rewriteBatchedStatements=true</code> 옵션을 활성화 필요</summary>

<a id="160eda9b0fe1803d8517e811adcd5963"></a>

```java
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/yourdb?rewriteBatchedStatements=true
```

</details>

- Repository

<a id="160eda9b0fe18055bb04c59991687529"></a>

```java
@Repository
@RequiredArgsConstructor
public class ProductJdbcRepositoryImpl implements ProductJdbcRepository {

    private final JdbcTemplate jdbcTemplate;

    @Transactional
    public void batchInsert(List<Product> productList) {
        String sql = "INSERT INTO products(`name`, `price`) VALUES (?, ?)";

        int size = productList.size();
        jdbcTemplate.batchUpdate(sql, productList, size,
            (PreparedStatement ps, Product product) -> {
                ps.setString(1, product.getName());
                ps.setInt(2, product.getPrice());
            }
        );
    }
```

- 사용

<a id="160eda9b0fe1807f975df8e31c3c370c"></a>

```java
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductJdbcRepository productJdbcRepository;

    @Transactional
    public void batchInsert() {
        List<Product> productList = new ArrayList<>();
        for (int i=1; i<50; i++) {
            productList.add(new Product("상품 이름" + i, i * 100));
        }

        productJdbcRepository.batchInsert(productList);
    }
}
```

### 순수 JPA

<a id="160eda9b0fe18063a08efbcec6a99a5a"></a>

순수 JPA에서는 <code>EntityManager</code>를 통해 벌크 업데이트를 실행한다&#46;

<a id="160eda9b0fe18011b8c5e0240865ede4"></a>

```java
String query = "UPDATE Member m SET m.age = m.age + 1 WHERE m.age >= :age";
int updatedCount = em.createQuery(query)
                     .setParameter("age", 20)
                     .executeUpdate();
```

- <code>executeUpdate()</code> 메서드는 영향을 받은 엔티티의 수를 반환한다&#46;

<a id="160eda9b0fe1809b971ac08075a071f8"></a>

### Spring Data JPA

<a id="160eda9b0fe1800ebac5c50a8951876e"></a>

<code>&#64;Modifying</code> 어노테이션을 사용하여 벌크 업데이트를 수행

<a id="160eda9b0fe180719188e289604f4182"></a>

```java
@Modifying
@Query("UPDATE Member m SET m.age = m.age + 1 WHERE m.age >= :age")
int bulkAgePlus(@Param("age") int age);
```

- <code>&#64;Modifying</code> 어노테이션은 해당 쿼리가 수정 작업임 나타낸다&#46;

<a id="160eda9b0fe1809cad98fafb3f38bb34"></a>

```java
@Modifying
@Query("UPDATE User u SET u.status = 'BLOCKED' WHERE u.id IN :userIds")
int bulkUpdateUsersStatusBLoked(@Param("userIds") List<Long> userIds);
```

@Test
public void bulkUpdate() {
		
    // update된 엔티티 숫자를 반환함

<a id="160eda9b0fe180d180c3c39b175db468"></a>

```java
@Transactional
public void reportUsers(List<Long> userIds) {

    /**
     * Querydsl 벌크 연산
     * 사용 시, 영속성 컨텍스트 와 DB 불인치 문제 주의 필요
     */
    long count = queryFactory
            .update(user)
            .set(user.status, "BLOCKED")
            .where(user.id.in(userIds)) // userIds에 포함된 사용자 ID로 필터링
            .execute();
}
```

## 주의사항

---

<a id="160eda9b0fe180ef8fadc8d594db95ff"></a>

벌크 업데이트는 대량의 데이터를 처리할 때 매우 효율적이지만 영속성 컨텍스트를 무시하고 바로 직접 DB로 쿼리를 날리기 때문에 <strong>데이터 정합성에 주의</strong>해야 한다&#46;

- <strong><u>영속성 컨텍스트와의 동기화 문제에 주의</u></strong>하여 <strong>데이터 일관성을 유지</strong>하는 것이 중요하다&#46;

<a id="160eda9b0fe1801e88ccdfa4e7688877"></a>

상황에 따라 벌크 연산과 개별 엔티티 업데이트를 적절히 선택해 사용해, 앱 성능을 최적화하는 것이 중요하다&#46;
