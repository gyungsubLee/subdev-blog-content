## <strong>조회한 빈이 모두 필요할 때</strong>, List, Map

---

<a id="1c3eda9b0fe181789ce5ee438f87b289"></a>

의도적으로 <strong>해당 타입의 스프링 빈이 모두 다 필요한 상황</strong>이 존재한다&#46;<br><br>예를 들어서 할인 서비스를 제공하는데, 클라이언트(사용자)가 할인의 종류(rate, fix)를 선택할 수 있다고 할 때,  <strong>스프링을 사용</strong>하면 소위 말하는 <strong><u>전략 패턴</u></strong><u>을 매우 간단하게 구현</u>할 수 있다&#46;

<a id="1c3eda9b0fe181bb9e7fff8b8982757f"></a>

### 🧐<a href="https://victorydntmd.tistory.com/292"> 전략 패턴</a>이란? 

<a id="1c3eda9b0fe1810382e0e8fa9dca2422"></a>

객체들이 할 수 있는 행위 각각에 대해 <strong>전략 클래스를 생성</strong>하고, <strong>유사한 행위</strong>들을 캡슐화 하는 <strong>인터페이스를 정의</strong>하여, 객체의 행위를 동적으로 바꾸고 싶은 경우 직접 행위를 수정하지 않고 <strong>전략을 바꿔주기만(구현체만 수정) </strong>함으로써 행위를 <strong>유연하게 확장</strong>하는 방법을 말한다&#46; 

> 역할, 구현체를 분리(전략에 따른 구현체 생성) <br>→ 자세한 내용은  <a href="#/post/1c3eda9b-0fe1-818c-81c7-ef9e927f1359">페이지</a> 확인

> ex)  <code>discountPolicy</code> → <code>RateDiscountPolicy</code>, <code>FixDiscountPolicy</code>

<a id="1c3eda9b0fe181718c54e6cf2ae0317d"></a>

### 🧐  어떻게 해당 Map 해당하는 타입의 빈들을 가져올 수 있는가?

> <strong>필드  선언</strong>( 타입&#58; <strong><code>Map&#60;String, DiscountPolicy&#62;</code></strong><strong> </strong>) , <strong>생성자 의존관계  자동 주입</strong>

<a id="1c3eda9b0fe1817fac28f8414c095823"></a>

⇒  <strong>map</strong>의 <strong><u>키</u></strong><u>에 </u><strong><u>스프링 빈의 이름을 넣</u></strong><u>어</u>주고,<strong><u> 해당 키 값</u></strong>으로<strong> </strong><strong><code>DiscountPolicy</code></strong><strong><u> 타입</u></strong>으로 <strong><u>조회한 모든 스프링 빈을 담</u></strong>아준다&#46; <strong> </strong>(<strong>List </strong>도 동일)

---

### 테스트 코드 

---

<a id="1c3eda9b0fe181b79ee1d11f3be38993"></a>

```java
package hello.core.Autowired;

import hello.core.AutoAppConfig;
import hello.core.discount.DiscountPolicy;
import hello.core.member.Grade;
import hello.core.member.Member;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

import java.util.List;
import java.util.Map;

import static org.assertj.core.api.Assertions.assertThat;

public class AllBeanTest {
    
    @Test
    void findAllBean() {
       ApplicationContext ac = new AnnotationConfigApplicationContext(AutoAppConfig.class, DiscountService.class);
        DiscountService discountService = ac.getBean(DiscountService.class);

				// 더미 회원 데이터 생성
        Member member = new Member(1L, "userA", Grade.VIP);

				// 클라이언트(사용자)에서 받아오는 할인 정책 
        int discountPrice = discountService.discount(member, 10000, "fixDiscountPolicy");  

        assertThat(discountService).isInstanceOf(DiscountService.class);
        assertThat(discountPrice).isEqualTo(1000);
    }


    static class DiscountService {
        
        private final Map<String, DiscountPolicy> policyMap;
        private final List<DiscountPolicy> policies;

        // @Autowired
        public DiscountService(Map<String, DiscountPolicy> policyMap, List<DiscountPolicy> policies) {
            this.policyMap = policyMap;
            this.policies = policies;

            System.out.println("policyMap = " + policyMap);
            System.out.println("policies = " + policies);
        }

        public int discount(Member member, int price, String discountCode) {
            DiscountPolicy discountPolicy = policyMap.get(discountCode);

            System.out.println("discountCode = " + discountCode);
            System.out.println("discountPolicy = " + discountPolicy);

            return discountPolicy.discount(member, price);
        }
    }
}
```

<a id="1c3eda9b0fe181e7a915ceb4406d6077"></a>

### 로직 분석

- DiscountService는 <strong>Map</strong>으로 만든 모든 DiscountPolicy를 주입받는다&#46; 이때 <code>fixDiscountPolicy</code>, <code>rateDiscountPolicy</code>가 주입된다&#46;

- <code>discount()</code>는 클라이언트에서 받아오는(테스트&#58;  더미 값) <code>&#34;fixDiscountPolicy”</code> (or <code>“rateDiscountPolicy”</code>)을 넘겨받아 <strong>Map</strong>에서  <code>fixDiscountPolicy</code> (or <code>rateDiscountPolicy</code> )  빈을 찾아서 실행한다&#46; 

<a id="1c3eda9b0fe18135b25ad3c5d754deb7"></a>

### 주입 분석

- <strong><code>Map&#60;String, DiscountPolicy&#62;</code></strong> &#58; map의 키에 스프링 빈의 이름을 넣어주고, 그 값으로<br><code>DiscountPolicy</code> 타입으로 조회한 모든 스프링 빈을 담아준다&#46;

- <code>List&#60;DiscountPolicy&#62;</code> &#58; <code>DiscountPolicy</code> 타입으로 조회한 모든 스프링 빈을 담아준다&#46;<br>만약 해당하는 타입의 스프링 빈이 없으면, 빈 컬렉션이나 Map을 주입한다&#46;

> 위 테스트 코드를 통해, 클라이언트(사용자)에서 동적 전략이 변경되어도, <br>스프링과, Map을 통해  간단하게 처리되는 것을 확인할 수 있다&#46;<br>→ 스프링을 통해 다형성 코드(전략 패턴)를 편리하게 구현 가능

> 📌 <strong>스프링 컨테이너를 생성하면서 스프링 빈 등록하기<br></strong>스프링 컨테이너는<strong> </strong><strong>생성자에 클래스 정보를 받</strong>는다&#46;  <strong>인자로 넘겨 받는 클래스는 스프링 빈으로 자동 등록</strong>된다&#46;
> 
> > <code>new AnnotationConfigApplicationContext(AutoAppConfig&#46;class, DiscountService&#46;class);</code>
> > 
> > ---
> > 
> > <a id="1c3eda9b0fe1815e8599c7c0da6fabae"></a>
