## 탐색할 패키지의 시작 위치 지정

---

<a id="1c3eda9b0fe1816ea659fa778b998601"></a>

모든 자바 클래스를 다 스캔하면 너무 오래걸릴 뿐더러, 그럴 필요도 없다&#46;

<a id="1c3eda9b0fe181539a2cd63f55826ebd"></a>

→ <strong>탐색 시작 위치를 지정 가능</strong>

<a id="1c3eda9b0fe181af89dfc753c0d3cde1"></a>

```java
@ComponentScan(
		basePackages="hello.core",
)
```

> <strong>•</strong> <strong>basePackages</strong><br>시작 위치 지정, 지정한 패키지를 포함한 하위 패키지 모두 탐색한다&#46;<br><br>여러개의 시작 위치도 지정 가능<br> ex) <code>basePackages = {&#34;hello&#46;core&#34;, &#34;hello&#46;service&#34;}</code>
> 
> <a id="1c3eda9b0fe181c7ac4dff659572be57"></a>
> 
>  <br>만약 지정값이 없으면, <code>&#64;ComponentScan</code>을 명시한<strong> Config</strong>를 시작 위치로 설정한다&#46;  
> 
> > 📌 <strong>권장 방법<br></strong>패키지 위치를 지정하지 않고, <strong>설정 정보 클래스(Config</strong>)를 <strong>프로젝트 최상단</strong>에 두어 자동으로 시작 위치 지정 (스프링 부트 기본값<strong>)</strong>
> > 
> > <details>
> > <summary>예시</summary>
> > 
> > - 프로젝트 구조
> >     > <code>com&#46;hello</code><br><code>com&#46;hello&#46;service</code><br><code>com&#46;hello&#46;repository</code>
> > 
> > <a id="1c3eda9b0fe181c99145f130fcaa77c3"></a>
> > 
> > 프로젝트 시작 루트(com&#46;hello)에 메인 설정 정보(AppConfig)를 두고 <code>&#64;ComponentScan</code> 명시, <code>basePackages</code> 지정 생략
> > 
> > <a id="1c3eda9b0fe181c7b889f9fabad450a7"></a>
> > 
> > ⇒ 이렇게 하면 <code>com&#46;hello</code>를 포함한 하위는 모두 자동으로 컴포넌트 스캔의 대상이 된다&#46; <br>(또한 프로젝트의 메인 설정 정보이기 때문에 프로젝트 시작 루트 위치하는 것이 여러모로 좋다&#46;)
> > 
> > </details>

<a id="1c3eda9b0fe18119ba21fb786654b4a2"></a>

## 컴포넌트 스캔에서의 스캔 요소

---

<a id="1c3eda9b0fe181f8a121d90a112ab4c2"></a>

컴포넌트 스캔은 <code>&#64;Component</code>  애노테이션이 명시된 클래스를 탐색 후, 빈으로 등록한다&#46;

<a id="1c3eda9b0fe1812baec2c6fee3ba4baf"></a>

스프링에서 제공하는 Annotation 중 내부로직에서 &#64;Componenet를 포함하는 애노테이션이 존재하는데,

<a id="1c3eda9b0fe181aeb85cee169572211b"></a>

이런 애노테이션들도 자동으로 스캔되어, 해당 클래스를  빈으로 등록한다&#46;

<a id="1c3eda9b0fe18159b31ed54c757476d0"></a>

&#43;) 역할에 따른 애노테이션을 명시하고, 부가 기능도 포함<br>

<a id="1c3eda9b0fe181359ce6f16ca96803fd"></a>

### &#64;Component를 포함하는 Annotation

- &#64;Controller&#58; 스프링 MVC 컨트롤러에서 사용

- &#64;Service&#58; 스프링 비지니스 로직에서 사용

- &#64;Repository&#58; 스프링 데이터 접근 계층에서 사용

- &#64;Configuration&#58; 스프링 설정 정보에서 사용

> ⚠️ <strong>참고<br></strong>Annotation에는 <strong>상속관계라는 것이 없</strong>다&#46; <br>이렇게 <strong>애노테이션이 특정 애노테이션을 들고 있는 것을 인식</strong>할 수 있는 것은 자바언어가 아닌 <strong>스프링이 지원하는 기능</strong>이다&#46;

> 컴포넌트 스캔의 용도 뿐만 아니라 다음 애노테이션이 있으면 스프링은 <strong>부가 기능을 수행</strong>한다&#46;

- &#64;Controller&#58; 스프링 MVC 컨트롤러로 인식

- &#64;Repository&#58; 스프링 데이터 접근 계층으로 인식하고, 데이터 계층의 예외를 스프링 예외로 변환해준다&#46;

- &#64;Configuration&#58; 앞서 보았듯이 스프링 설정 정보로 인식하고, 스프링 빈이 싱글톤을 유지하도록 추가 처리를 한다&#46;

- &#64;Service&#58; &#64;Service 는 특별한 처리를 하지 않는다&#46; 대신 개발자들이 &#39;핵심 비즈니스 로직이 여기에 있겠구나’라고 비즈니스 계층을 인식하는데 도움이 준다&#46;
