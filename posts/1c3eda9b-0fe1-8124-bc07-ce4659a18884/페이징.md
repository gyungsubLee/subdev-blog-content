## 페이징

---

> 📖 
> 
> <a id="1c3eda9b0fe181308901fcc0adfa49ec"></a>
> 
> 조회 시 데이터를 나눠 가져오는 방법을 말한다&#46; 

- 조회 건 수 제한
    <a id="1c3eda9b0fe181018408e7bc5cfa6db2"></a>

    ```java
    @Test
    public void paging1() {

    		List<Member> result = queryFactory
          .selectFrom(member)
    			.orderBy(member.username.desc())
    			.offset(1) //0부터 시작(zero index) 
    			.limit(2) //최대 2건 조회
    			.fetch();
    		
    	  assertThat(result.size()).isEqualTo(2);
    }
    ```

- 전체 조회
    > ❗ 
    > 
    > <a id="293eda9b0fe180da8d3eefa6a5c4a0cd"></a>
    > 
    > &#91;주의&#93; count 쿼리가 실행되니 성능상 주의 필요

    <a id="1c3eda9b0fe181269949e93307673ae2"></a>

    ```java
    @Test
    public void paging2() {
         QueryResults<Member> queryResults = queryFactory
                 .selectFrom(member)
                 .orderBy(member.username.desc())
                 .offset(1)
                 .limit(2)
                 .fetchResults();
                 
         assertThat(queryResults.getTotal()).isEqualTo(4);
         assertThat(queryResults.getLimit()).isEqualTo(2);
         assertThat(queryResults.getOffset()).isEqualTo(1);
         assertThat(queryResults.getResults().size()).isEqualTo(2);
    }
    ```

> ☝🏻 
> 
> <a id="1c3eda9b0fe181adb118fb46eb23ab48"></a>
> 
> 실무에서 페이징 쿼리를 작성할 때, 데이터를 조회하는 쿼리는 여러 테이블을 조인해야 하지만, <u>count 쿼리 는 조인이 필요 없는 경우도 있</u>다&#46;
> 
> <a id="1c3eda9b0fe181c9862add7ca0613621"></a>
> 
>  그런데 이렇게 <u>자동화된 count 쿼리는 원본 쿼리와 같이 모두 조인</u>을 해버리기 때문에<u> 성능이 안나올 수 있</u>다&#46; 
> 
> <a id="1c3eda9b0fe181ff8c63ffb1cd10e041"></a>
> 
> count 쿼리에 <u>조인이 필요없는 성능 최적화가 필요</u>하다면, <u>count 전용 쿼리를 별 도로 작성</u>해야 한다&#46;
