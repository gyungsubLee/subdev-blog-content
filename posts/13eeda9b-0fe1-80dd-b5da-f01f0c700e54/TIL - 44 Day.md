과제 구현 및 강의 학습이 급해서 알고리즘 풀이 스킵함

<a id="13eeda9b0fe18161838bcf8328e37172"></a>

### 스프링

---

> <a href="#/post/13ceda9b-0fe1-8067-9531-e4fdae3568a2">페이지</a> 

- 2주차 정리  &#45; 세션, 토큰, jwt, 필터 정리 

- 3주차 &#45;  Spring Data JPA, JPA Auditing 정리

> 배운 내용 정리

<details>
<summary>세션</summary>

- 서버에서 상태 정보를 관리한다&#46; 

- 서버 저장소(Session Storage)에 유저의 상태 정보를 저장한다&#46;

- 메모리를 사용하기 때문에 트래픽이 많아지면 성능 저하가 심하게 되고, 서버가 다운될 수 있다&#46; 

</details>

<details>
<summary>jwt</summary>

- json 형식의 web Token 이다&#46; 

- payload, header, signature로 구성되어 있다&#46;

- signature는 payload&#46;header를 서버의 scret key를 활용하여 암호화 알고리즘을 통해 해시화 한 값이다&#46; 
    - signature를 통해 위조 여부를 판단한다&#46; 

    - 요청에 담긴 payload 와 header로 다시 signature를 생성하여 비교 후 동일한 경우 변경이 없다고 판단하여 요청을 허락한다&#46; 

- HTTP 통신 간에 전송이 원활하도록 Base64URL 형식으로 인코딩 한다 &#46;

- stateless 한 방식이기 때문에, 중간에 탈취 시 만료될 때까지 악용될 수있다 &#46;<br>이 때문에 만료시간을 짧게 설정하는데, 이러면 사용자가 매번 로그인 요청을 해야하므로 유저의 사용성이 매우 떨어진다&#46; 이를 refesh token, access token 방식으로 해결한다 &#46;
    - access token
        - 유저를 판별하는데 사용되는 token으로 매우 짧은 시간의 유효기간을 갖는다 &#46;

        - 해당 token이 만료되면 refesh token을 통해 서버에 다시 access token을 발급 받는다&#46;

    - refresh token
        - access token 재발급 시에 사용된다&#46;

        - 보안을 유지하기 위해 1회성으로 사용된다&#46;
            - 사용자가 리프레시 토큰을 사용해 새로운 액세스 토큰과 리프레시 토큰을 요청할 때, 서버는 새 리프레시 토큰을 발급하고 이전의 리프레시 토큰은 무효화된다&#46;

</details>

<details>
<summary>filter</summary>

- servlet&#46;filter 인터페이스를 상속하여 구현한다&#46;

- <code>init()</code>, <code>doFilter()</code>, <code>destroy()</code>로 구성되어 있는데,<br>생성(<code>init()</code>), 소멸(<code>destory()</code>)  메서드는 인페이스에 default로 구현되어 있기 때문에<br>구현 시, <code>doFilter()</code>만  오버라이드하여 내부에서 공통 관심 사항을 처리하면 된다&#46; 

- 필터 생성 후 빈으로 수동 등록을 해야 스프링에서 빈으로 가져와 처리한다&#46; 

</details>

<details>
<summary>Spring Data JPA</summary>

- 스프링부트 환경에서 JPA를 간편하게 사용하게 해주는 기술이다&#46; 

- JpaRepoistoy를 상속하는 interface를 정의하면 해당 구성 정보를 토대로 자동으로 저장소 구현체를 생성해 처리해준다&#46; 
    - 보통 구현체는 SImpleJpaRepository이다&#46; 

- QueryMethods를 사용해 메서드 이름을 통해 더 복잡한 조건의 JPQL을 자동으로 생성할 수 있다&#46; 
    - 동적 쿼리나, 더 복잡한 조건을 Query Method를 사용해 구현한다&#46; 
        - JPQL, Criteria를 사용하여 구현 가능하나 유지보수가 어려워 권장하지 않음

</details>

<details>
<summary>Spring Data JPA Auditing</summary>

- <code>&#64;EnableJpaAuditing</code> &#45; JPA Auditing 기능 활성화 

- <code>&#64;MappedSupterClass</code> 
    - 해당 Annotation이 선언된 클래스를 <code>extends(상속)</code> Enitity에 상속 처리 가능 → 공통 매핑 정보 제공

- <code>&#64;EntityListeners(AuditingEntityListener&#46;class)</code>
    - Spring Data에서 JPA Auditing 기능을 활성화하기 위해서 사용하며, JPA 엔티티의 라이프사이클(생성, 수정, 소멸) 이벤트를 감지하고 특정 동작을 수행할 수 있도록 해준다&#46;
        - <code>&#64;PrePersist</code>, <code>&#64;PreUpdate</code> 등을 자동으로 내부적으로 수행해 준다&#46;

- <code>&#64;CreateData</code> &#45; 생성 날짜 자동 기록

- <code>&#64;LastModifiedData</code> &#45; 수정 날짜 자동 기록

- <code>&#64;Temporal</code> &#45; 날짜 타입 세부적으로 지정 가능

</details>
