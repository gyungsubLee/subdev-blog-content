## 필터

---

> <strong><code>includeFilters</code></strong>&#58; 컴포넌트 스캔 대상을 추가로 지정한다&#46;<br><strong><code>excludeFilters</code></strong>&#58; 컴포넌트 스캔에서 제외할 대상을 지정한다&#46;

<details>
<summary><strong>컴포넌트 스캔 대상에 추가할 애노테이션 ( </strong><code>MyIncludeComponent</code> )</summary>

<a id="1c3eda9b0fe1819b9a20eec5cf49048e"></a>

```java
package hello.core.scan.filter;
 import java.lang.annotation.*;

 @Target(ElementType.TYPE)
 @Retention(RetentionPolicy.RUNTIME)
 @Documented
 public @interface MyIncludeComponent {
 }
```

</details>

<details>
<summary><strong>컴포넌트 스캔 대상에서 제외할 애노테이션 ( </strong><code>MyExcludeComponent</code> ) </summary>

<a id="1c3eda9b0fe181f68279cda54dd78a41"></a>

```java
package hello.core.scan.filter;

 }
```

</details>

### 스캔 범위에 필터 적용 후, 빈 테스트

<a id="1c3eda9b0fe181e587abc09c5cc3df81"></a>

```java
package hello.core.scan.filter;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.NoSuchBeanDefinitionException;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.ComponentScan.Filter;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.FilterType;

import static org.assertj.core.api.Assertions.assertThat;
import static org.junit.jupiter.api.Assertions.assertThrows;

public class ComponentFilterAppConfigTest {

    @Test
    void filterScan() {
        AnnotationConfigApplicationContext ac = new AnnotationConfigApplicationContext(ComponentFilterAppConfig.class);

        // BeanA가 빈으로 등록 됐는지 확인
        BeanA beanA = ac.getBean("beanA", BeanA.class);
        assertThat(beanA).isNotNull();

        // BeanB이 스캔에서 제외되어, 빈으로 등록되지 않았는지 확인
        assertThrows(
                NoSuchBeanDefinitionException.class,
                ()->ac.getBean("beanB", BeanB.class));
    }

    @Configuration
    @ComponentScan(
            includeFilters = @Filter(type = FilterType.ANNOTATION, classes = MyIncludeComponent.class),
            excludeFilters = @Filter(type = FilterType.ANNOTATION, classes = MyExcludeComponent.class)
    )
    static class ComponentFilterAppConfig{
    }
}
```

> <strong>• </strong><code>includeFilters</code> 에 <code>MyIncludeComponent</code> 애노테이션을 추가해,<strong> BeanA가 스프링 빈에 등록</strong>된다&#46;<br><strong><br>• </strong><code>excludeFilters</code> 에 <code>MyExcludeComponent</code> 애노테이션을 추가해서<strong> BeanB는 스프링 빈에 등록되지 않</strong>는 다&#46;

<a id="1c3eda9b0fe18130a143c371b8b160ad"></a>

### FilterType 옵션 (5)

- <strong>ANNOTATION</strong>&#58; 기본값, 애노테이션을 인식해서 동작한다&#46;<br>ex) <code>org&#46;example&#46;SomeAnnotation</code>

- <strong>ASSIGNABLE&#95;TYPE</strong>&#58; 지정한 타입과 자식 타입을 인식해서 동작한다&#46;<br>ex) <code>org&#46;example&#46;SomeClass</code>

- <strong>ASPECTJ</strong>&#58; AspectJ 패턴 사용<br>ex) <code>org&#46;example&#46;&#46;&#42;Service&#43;</code>

- <strong>REGEX</strong>&#58; 정규 표현식<br>ex) <code>org&#92;&#46;example&#92;&#46;Default&#46;&#42;</code>

- <strong>CUSTOM</strong>&#58; &#96;TypeFilter&#96; 이라는 인터페이스를 구현해서 처리<br>ex) <code>org&#46;example&#46;MyTypeFilter</code>

<details>
<summary>ex) BeanA도 제거</summary>

<a id="1c3eda9b0fe18169becde8e37c69283b"></a>

```java
@ComponentScan(
   includeFilters = {
         @Filter(type = FilterType.ANNOTATION, classes = MyIncludeComponent.class),
   },
   excludeFilters = {
         @Filter(type = FilterType.ANNOTATION, classes = MyExcludeComponent.class),
         @Filter(type = FilterType.ASSIGNABLE_TYPE, classes = BeanA.class)
   }
)
```

</details>

> ⚠️ <strong>참고</strong>
> 
> <a id="1c3eda9b0fe181359618c39c235d2ad4"></a>
> 
> <code>&#64;Component</code> 면 충분하기 때문에, <code>includeFilters</code>를 사용할 일은 거의 없다&#46; <code>excludeFilters</code> 는 여러가지 이유로 간혹 사용할 때가 있지만 많지는 않다&#46;<br>특히 최근 스프링 부트는 컴포넌트 스캔을 기본으로 제공하는데, 개인적으로는 옵션을 변경 하면서 사용하기 보다는 스프링의 기본 설정에 최대한 맞추어 사용하는 것을 권장하고, 선호하는 편이다
