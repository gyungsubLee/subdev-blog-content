### 코더가 아닌 개발자가 되는 법

<a id="11ceda9b0fe180a8aa00edb5b234d747"></a>

개발을 진행하면 정말 많은 문제들을 마주하게 된다&#46;

- 문제 인식 → 이 문제를 해결하기 위해 어떠한 선택을 했는지
    <a id="11ceda9b0fe1807f8ed9efae6547cb7a"></a>

    → 옳은 선택인지, 아닌지

    <a id="11ceda9b0fe1809894daf64019859035"></a>

    ⇒ 기록

    - 문제 인식

    - 의사 결정 과정

    <a id="11ceda9b0fe180eaa10ffe6d03a040d1"></a>

    ⇒ 비슷한 문제를 마주치면 더 빠르게 해결

- 좋은 팀을 만드는데 → 굉장히 오래 걸림
    - 잘못된 팀원 → 팀이 망가짐

    - 단기간에 보여지는 실력도 보지만

    - 이 사람이 얼마나 자기 성장을 위해 얼마나 꾸준히 노력하는지 

    - 이사람의 사고의  깊이가 어느  정도까지 되는지

    <a id="11ceda9b0fe180fcb394f7f088f813ee"></a>

    ⇒ 하루 공부 잘 정리하기

- 배운 내용 복습 → 사고력, 구현력 중점적으로 단련

- 기술적인 의사결정, 기술적 고민

- 어떤 프로젝트, 어떤 기능 → 이 부분을 구현하기 위해 이러한 선택을 했다&#46;

- 이 과정과, 트레이드 오프를 고려했을 때, 이러한 선택이효율적이라 생각했다&#46; 


- 주니어 개발자
    - 레거시 코드 개선 (빡셈)

    - 동료와 소통하며 원활한 협업

- 좋은 개발자에 대한 수요는 항상 있다&#46;
