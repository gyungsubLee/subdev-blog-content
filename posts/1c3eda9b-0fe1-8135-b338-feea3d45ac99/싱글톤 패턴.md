### 싱글톤 패턴이란?

<a id="1c3eda9b0fe18182aaf9ed92cdd94967"></a>

어떤 클래스의 인스턴스를 단 하나만 생성할 수 있다면, 해당 클래스는 싱글턴 클래스이며 <br>해당 디자인 패턴을 싱글턴 패턴이라 한다&#46; 

<a id="1c3eda9b0fe18135a9e6def03eb6d7df"></a>

비지니스 개념 관점에서 클래스에 시스템에 한번만 저장되어야 하는 데이터가 포함된 경우 해당 클래스는 싱글턴 클래스로 설계해야 한다&#46;  

> ex) 시스템의 설정 정보를 관리하는 클래스<br>ex) 고유 증분 ID 생성 클래스 
> 
> <details>
> <summary>ID 생성기 &#45; 싱글턴 패턴 구현</summary>
> 
> <a id="1c3eda9b0fe181059f7bc050a38a3908"></a>
> 
> ```java
> package singleton;
> 
> import java.util.concurrent.atomic.AtomicLong;
> 
> public class IdGenerator {
> 
>     private AtomicLong id =  new AtomicLong(0);
>     private static final IdGenerator instance = new IdGenerator();
> 
>     public IdGenerator() {}
>     
>     public static IdGenerator getInstance() {
>         return instance;
>     }
>     
>     public long getId() {
>         return id.incrementAndGet();
>     }
> }
> 
> ----
> 
> // IdGenerator 클래스 사용 예
> long id = IdGenerator.getInstance().getId();
> 
> ```
> 
> </details>

## 싱글톤 패턴 구현

<a id="1c3eda9b0fe181e3b8a4ff4ec6c3253d"></a>

싱글턴 패턴을 구현하는 방법은 여러가지가 있다&#46; <br>그리고 해당 방법들은 아래 4가지 조건을 만족해야 한다&#46;

> 📌 1) 생성자는 <strong><code>new</code></strong><strong> 예약어를 통한 인스턴스 생성을 피</strong>하기 위해<strong> </strong><strong><u><code>private</code></u></strong><strong><u> 접근 </u></strong><strong>해야한다&#46;<br></strong>2) 객체가 생성될 때 <strong><u>스레드 안정성을 보장</u></strong>하는지 확인해야 한다&#46;<br>3)<u> </u><strong><u>지연 로딩</u></strong>을 지원하는지 여부를 확인해야 한다&#46;<br>4) <code>getInstance()</code> 함수의 성능이 충분해야 한다&#46; 

<a id="1c3eda9b0fe1811b96c2cc2f90166928"></a>

### 구현1) 즉시 초기화 ( eager initialization )

<a id="1c3eda9b0fe18194bffefc6ce5633ebe"></a>

클래스가 메모리에 적재 될때 이미 생성되어 초기화가 완료되기 때문에, 인스턴스 생성 프로세스는 안전하다고 보장할 수 있다&#46; 그러나 해당 구현은 <strong>지연 적재(lazy loading)을 지원하지 않</strong>아 <strong>인스턴스</strong>가 사용되는 시점이 생성되지 않고 <strong>미리 생성</strong>되어 사용된다&#46;

<a id="1c3eda9b0fe181b987bffa63c36e36a2"></a>

```java
package singleton;

import java.util.concurrent.atomic.AtomicLong;

// 즉시 초기화 ( eager initialization )
public class  IdGeneratorEI{
    private AtomicLong id = new AtomicLong(0);
    private static final IdGeneratorEI instance = new IdGeneratorEI();

    private IdGeneratorEI() {};
    public static IdGeneratorEI getInstance() {
        return instance;
    }

    public long getId() {
        return id.incrementAndGet();
    }
}
```

<a id="1c3eda9b0fe18147bddaffb762a58b66"></a>

### 구현2) 늦은 초기화 ( lazy initialization )

<a id="1c3eda9b0fe18185a786faf26a3d3ceb"></a>

<code>lazy loadiang</code>이 지원되어, <strong><u>인스턴스 생성과 초기화가 실제로 사용되지 전까지 일어나지 않</u></strong>는다&#46; 

<a id="1c3eda9b0fe1817cb444f6369eef138f"></a>

```java
package singleton;

import java.util.concurrent.atomic.AtomicLong;

public class IdGeneratorLI {
    private AtomicLong id = new AtomicLong(0);
    private static IdGeneratorLI instance;

    private IdGeneratorLI() {};

    public static synchronized IdGeneratorLI getInstance() {
        if ( instance == null ) {
            instance = new IdGeneratorLI();
        }
        return instance;
    }

    public long getId() {
        return id.incrementAndGet();
    }
}
```

<a id="1c3eda9b0fe181068b60e79e6b30816c"></a>

### 구현3) 이중 잠금 ( double &#45; checked )

<a id="1c3eda9b0fe18182bcebc0e9cd532f2e"></a>

즉시 초기화 방식은 지연 적재를 지원하지 않고, 늦은 초기화 방식은 높은 동시성을 지원하지 않는다&#46; 이 두 방식을 모두 지원하는 이중 잠금 구현에 대해 …&#46;

<a id="1c3eda9b0fe181caae49f420a5d0cacc"></a>

```java
package singleton;

import java.util.concurrent.atomic.AtomicLong;

// Double Checked ( 이중 잠금 )
public class IdGeneratorDC {
    private AtomicLong id = new AtomicLong(0);
    private static IdGeneratorDC instance;

    private IdGeneratorDC() {};

    public static IdGeneratorDC getInstance() {
        if (instance == null) {
            synchronized (IdGeneratorDC.class) {  // 클래스 레벨의 잠금 처리
                if (instance == null) {
                    instance = new IdGeneratorDC();
                }
            }
        }
        return instance;
    }

    public long getId() {
        return id.incrementAndGet();
    }
}
```

<a id="1c3eda9b0fe181eea7acd987c0bf6eed"></a>

### 구현4) 홀더에 의한 초기화 ( initialization demand holder idiom )

<a id="1c3eda9b0fe181a29e99c7552741ec7f"></a>

<strong><u>java의 정적 내부 클래스를 사용</u></strong>하는 방식으로 <code>구현3 &#45; 이중 잠금</code> 보다 간단하게 구현하는 방식이다&#46; 보기에는 즉시 초기화 방식과 유사하지만 지연 로딩이 가능하다&#46;

<a id="1c3eda9b0fe181ce94f3cd0d2f753e46"></a>

```java
package singleton;

import java.util.concurrent.atomic.AtomicLong;

// 홀더에 의한 초기화 ( Initialization on demand holder idom )
public class IdGeneratorIDHI {
    private AtomicLong id = new AtomicLong(0);

    public IdGeneratorIDHI() {}

    private static class SingletonHolder {
        private static final IdGeneratorIDHI instance = new IdGeneratorIDHI();
    }

    public static IdGeneratorIDHI getInstance() {
        return SingletonHolder.instance;
    }

    public long getId() {
        return id.incrementAndGet();
    }
}
```

<a id="1c3eda9b0fe18105bde3ea86596d7ac4"></a>

### 구현5) 열거

<a id="1c3eda9b0fe181039d55f4b53da9d5b5"></a>

java의 열거형이 가지는 특성을 이용하여 인스턴스 생성 시 스레드 안전성과 인스턴스의 유일성을 보장한다&#46; 

<a id="1c3eda9b0fe181e199e1c32db79abdf9"></a>

```java
package singleton;

import java.util.concurrent.atomic.AtomicLong;

// 열거 ( enumeration )
public enum IdGeneratorEnum {
    INSTANCE;
    private AtomicLong id  = new AtomicLong(0);

    public long getId() {
        return id.incrementAndGet();
    }
}
```
