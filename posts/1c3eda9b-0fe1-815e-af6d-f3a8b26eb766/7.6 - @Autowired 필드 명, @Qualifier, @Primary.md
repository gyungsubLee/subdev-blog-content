### 조회 대상 빈이 2개 이상일 때,  자동 의존관계 주입에서 해결 방법(3)

<a id="1c3eda9b0fe1817a9923c727527ec2f0"></a>

## &#64;Autowired 필드 명 매칭

---

> <code>&#64;Autowired</code> 는 처음에 <strong>타입 매칭</strong>을 시도한다&#46;<br>이때 <strong><u>여러개의 빈이  매칭 </u></strong><strong>되면,</strong> <strong><u>필드 이름, 파라미터 이름</u></strong><u>으로 빈 </u><strong><u>추가 매칭</u></strong>한다&#46;<br>(처음 타입 매칭 시, 1개의 빈이 조회되면 추가 매칭은 발생되지 않음)

> 타입 매칭&#58;  <strong><u>본인과 같은 타입 </u></strong>이거나 또는 <strong><u>그 타입의 자식들</u></strong>을 다 끌고 온다&#46; 

<details>
<summary><strong>기존 코드</strong></summary>

<a id="1c3eda9b0fe1812f9291f253d05d9981"></a>

```java
@Autowired
private DiscountPolicy discountPolicy
```

</details>

<a id="1c3eda9b0fe18147a8b1f0aaf96cf192"></a>

### 필드 매칭

<a id="1c3eda9b0fe1819fb62dea998a76c622"></a>

```java
@Autowired
private DiscountPolicy rateDiscountPolicy
```

<a id="1c3eda9b0fe1812e8ab7de086af9396f"></a>

### 파라미터 매칭

> <code>discountPolicy</code> → <code>rateDiscountPolicy</code>

<a id="1c3eda9b0fe18130b139c990f01704c6"></a>

생성자의 경우 파라미터의 이름을 보고 해당 이름과 같은 빈이 존재하는 경우 가져온다&#46;

<a id="1c3eda9b0fe1811d9753f80893bcc34e"></a>

```java
@Component
public class OrderServiceImpl implements OrderService {
    private final MemberRepository memberRepository;
    private final DiscountPolicy discountPolicy;

    @Autowired
    public OrderServiceImpl(MemberRepository memberRepository, DiscountPolicy rateDiscountPolicy) {
        this.memberRepository = memberRepository;
        this.discountPolicy = rateDiscountPolicy;
    }
```

> 📌 <strong>&#64;Autowired 정리</strong>
> 
> 1. 타입 매칭
> 
> 1. 타입으로 매칭 시 여러개의 빈이 있을 때, &#91; 필드명, 파라미터 명 &#93; 으로 빈을 추가 매칭한다&#46;

<a id="1c3eda9b0fe181a286cedc214964e9a3"></a>

## &#64;Qualifier <strong>사용</strong>

---

> <strong>추가 구분자</strong>를 붙여주는 방법, 주입 시 추가적인 방법을 제공 (빈 이름을 변경 X)

<a id="1c3eda9b0fe18196a218fc37d0a330a2"></a>

### <strong><code>fixDiscountPolicy</code></strong><strong>, </strong><strong><code>rateDiscountPolicy</code></strong><strong>  빈 등록 시,  </strong><strong><code>&#64;Qualifier(”구분 명칭”)</code></strong><strong> 붙여준다&#46;</strong>

<a id="1c3eda9b0fe181b88e3ae4ef34f6e492"></a>

```java
@Component
@Qualifier("mainDiscountPolicy")
public class RateDiscountPolicy implements DiscountPolicy{
```

<a id="1c3eda9b0fe181fe99bcd2ec9c1a6e09"></a>

```java
@Component
@Qualifier("fixDiscountPolicy")
public class FixDiscountPolicy implements DiscountPolicy{
```

<a id="1c3eda9b0fe1812490e4edcf13154f04"></a>

### 주입 시, <code>&#64;Qualifier</code>  사용하여 하위 특정 빈을 가져와, 인자로 넣는다&#46;

<a id="1c3eda9b0fe181ffb08af30c62d04310"></a>

```java
// 생정자 주입
@Autowired
public OrderServiceImpl(MemberRepository memberRepository,
  @Qualifier("mainDiscountPolicy") DiscountPolicy  discountPolicy) {
      this.memberRepository = memberRepository;
      this.discountPolicy = discountPolicy;   
}
```

<a id="1c3eda9b0fe18148adb9ebbb0ba34682"></a>

```java
// 수정자 주입
@Autowired
 public DiscountPolicy setDiscountPolicy(@Qualifier("mainDiscountPolicy") DiscountPolicy discountPolicy) {
     this.discountPolicy = discountPolicy;
 }
```

<a id="1c3eda9b0fe1816a9841ededd5be59b5"></a>

### 직접 빈 등록 시에도 동일하게 사용가능하다&#46;

<a id="1c3eda9b0fe1811ba10ffc0dd4b0dcaa"></a>

```java
@Bean
 @Qualifier("mainDiscountPolicy")
 public DiscountPolicy discountPolicy() {
   return new ...
 }
```

> 📌 <strong><code>&#64;Qualifier</code></strong><strong>는 </strong><strong><code>&#64;Qualifier</code></strong><strong>로 구분을 명시하고 가져올 때만 사용 해야한다&#46;</strong><strong><br></strong><code>&#64;Qualifier</code>로 주입 시, 해당하는 <code>&#64;Qualifier</code>를 찾지 못하면 <u>해당 명칭의 빈을  찾아 있면 가</u>져온다&#46;
> 
> > ex) <code>&#64;Q &#64;ualifier(&#34;mainDiscountPolicy&#34;)</code>  해당하는 Qualifier X<br>               → <code>mainDiscountPolicy</code> 스프링 빈 찾아 가져온다&#46;(없으면 X&#95;
> 
> <a id="1c3eda9b0fe181d98513f871c4cc8030"></a>
> 
> 하지만 <code>&#64;Qualifier</code> 를 사용하여 빈을 구분하는 것은 강사님도 헷갈리는 애매한  방법이다&#46;<br>개발은 항상 혼자가 아닌 팀을 생각하면서 행동해야한다&#46; 즉, 다른사람이 잘 모를 것 같은 애매한 방법이면 사용하지 말자&#46;

<a id="1c3eda9b0fe181288451fb0a67426809"></a>

### 정리

---

<a id="1c3eda9b0fe1810fbbe6d9785a2aaaee"></a>

1&#46; <strong>&#64;Qualifier끼리 매칭 (해당 방법으로만 사용)</strong>

<a id="1c3eda9b0fe181d69ae1eff242ccb8d5"></a>

2&#46;  빈 이름 매칭

##  &#64;Primary <strong>사용 </strong>

---

> <strong>우선순위를 정</strong>하는 방법, <strong><u><code>&#64;Autowired</code></u></strong><strong><u> 시에 여러 빈이 매칭되면 </u></strong><strong><u><code>&#64;Primary</code></u></strong><strong><u> 가 우선권을 가진</u></strong>다&#46;<br>(자주 사용되지만, 한계점이 있음)

<a id="1c3eda9b0fe1816595bacc8c30875e5b"></a>

### <code>rateDiscountPolicy</code>에 우선순위(&#64;Primary) 설정

<a id="1c3eda9b0fe1811296c5ddba1e72b9ac"></a>

```java
@Component
 @Primary
 public class RateDiscountPolicy implements DiscountPolicy {}
```

<a id="1c3eda9b0fe1811d9089f7afdab5ee95"></a>

### DiscountPolicy를 주입하면 우선순위에 의해 <code>rateDiscountPolicy</code> 매칭되어 주입된다&#46; 

<a id="1c3eda9b0fe1813ea9b4c37e1bc5c55e"></a>

```java
//생성자
@Autowired
public OrderServiceImpl(MemberRepository memberRepository,
                         DiscountPolicy discountPolicy) {
     this.memberRepository = memberRepository;
     this.discountPolicy = discountPolicy;
 }
```

<a id="1c3eda9b0fe181e1b2caf46947d54249"></a>

```java
//수정자
@Autowired
public DiscountPolicy setDiscountPolicy(DiscountPolicy discountPolicy) {
     this.discountPolicy = discountPolicy;
 }
```

## <code>&#64;Primary</code> 와 <code>&#64;Qualifier</code> 

<a id="1c3eda9b0fe181f295efd82ebda64806"></a>

### <code>&#64;Qualifier</code> 의 단점

---

<a id="1c3eda9b0fe181a491a6ca0d3ac1faae"></a>

→  주입 받을 때 다음과 같이 모든 코드에 <code>&#64;Qualifier</code> 를 붙여주어야 한다

<a id="1c3eda9b0fe1819fafb4fd8aa8e6f607"></a>

⇒ 그러나 <code>&#64;Primary</code>는 그럴 필요가 없다&#46;

<a id="1c3eda9b0fe18185b244ee5de013bf57"></a>

```java
@Autowired
 public OrderServiceImpl(MemberRepository memberRepository,
                         @Qualifier("mainDiscountPolicy") DiscountPolicy
 discountPolicy) {
     this.memberRepository = memberRepository;
     this.discountPolicy = discountPolicy;
}
```

<a id="1c3eda9b0fe1810fa42fe0824462d562"></a>

### <strong><code>&#64;Primary</code></strong><strong>,</strong><strong><code> &#64;Qualifier</code></strong><strong> 활용</strong>

---

<a id="1c3eda9b0fe1819db09ed3252f4623a9"></a>

코드에서 자주 사용하는 메인 데이터베이스의 커넥션을 획득하는 스프링 빈이 있고, 코드에서 특별한 기능으로 가끔 사용하는 서브 데이터베이스의 커넥션을 획득하는 스프링 빈이 있다고 생각해보자&#46; 메인 데이터베이스의 커넥션을 획득하 는 스프링 빈은 <code>&#64;Primary</code> 를 적용해서 조회하는 곳에서 <code>&#64;Qualifier</code> 지정 없이 편리하게 조회하고, 서브 데이터베 이스 커넥션 빈을 획득할 때는 <code>&#64;Qualifier</code> 를 지정해서 명시적으로 획득 하는 방식으로 사용하면 코드를 깔끔하게 유지할 수 있다&#46; 물론 이때 메인 데이터베이스의 스프링 빈을 등록할 때 <code>&#64;Qualifier</code> 를 지정해주는 것은 상관없다&#46;

<a id="1c3eda9b0fe18113acbddc814ec1c7b1"></a>

### 우선순위 

---

<a id="1c3eda9b0fe181ef9484f778b6995558"></a>

<code>&#64;Primary</code> 는 기본값 처럼 동작, <code>&#64;Qualifier</code> 는 매우 상세하게 동작

<a id="1c3eda9b0fe181c2b81ffcb1e21fa69d"></a>

스프링은 자동보다는 수동이, 넒은 범위의 선택권 보다는 좁은 범위의 선택권이 우선 순위가 높다&#46; 

<a id="1c3eda9b0fe1816dad80f600e6b87cf5"></a>

따라서<code> &#64;Qualifier</code> 가 우선권이 높다&#46;
