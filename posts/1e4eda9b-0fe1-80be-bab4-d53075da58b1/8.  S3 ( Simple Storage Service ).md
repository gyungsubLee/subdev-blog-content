## S3 ( Simple Storage Service )

---

> 📖 
> 
> <a id="1eeeda9b0fe180ffacb5fe7742c26e64"></a>
> 
> <strong><code>S3</code></strong><strong> ( Simple Storage Service )</strong>
> 
> ---
> 
> <a id="1eeeda9b0fe1807e863bf5203b18db7e"></a>
> 
> AWS에서 제공하는 인터넷 스토리지 서비스이다 &#46;
> 
> -  <u>폴더 형태</u>(<code>Buckets</code>)의<u> </u><u>데이터 저장 공간</u>을 제공한다&#46;
> 
> - 모든 파일을 <code>객체</code>라 부르며 <code>key</code>로 식별한다&#46; 
> 
> -  <code>정적 웹 사이트 호스팅</code>, <code>온라인 백업</code>, <code>데이터 아카이브</code>, <code>기업 애플리케이션</code>,<code> Big Data 분석</code> 등 다양한 용도로 사용된다&#46; 

<a id="1eeeda9b0fe18066aaf0e2afa1c568ba"></a>

### 1&#46;  기본 개념

<details>
<summary>사용 예</summary>

- <strong>웹 사이트 호스팅</strong>

- <strong>멀티미디어 파일 저장 및 스트리밍</strong>

- 애플리케이션 데이터 저장

- 백업 및 복원

- 아카이브

</details>

<details>
<summary>장점</summary>

- 높은 내구성, 가용성 및 안정성

- 손쉬운 사용 및 관리

- 보안성

- 높은 확장성

</details>

<details>
<summary><strong>S3 &#45; </strong><strong><code>Buckets</code></strong><strong> </strong></summary>

> ✏️ 
> 
> <a id="1eeeda9b0fe180d88b93d28578562a0d"></a>
> 
> <code>Buckets</code>은 <code>S3</code>에서 <u>데이터를 저장</u>하는 가장 상위 레벨의 <strong><u>폴더 형태의 컨테이너</u></strong>를 말한다&#46;
> 
> - S3에 <u>저장되는 파일들</u>을 <u>‘</u><strong><u>객체’</u></strong>라고 부르고 <strong>모든 객체는 ‘키(디렉토리)’로 식별</strong>된다&#46; 

<a id="1eeeda9b0fe180ca8395c8dafd68ef05"></a>

```bash
# prefix/delimiter/object-name

s3://my-bucket/my_folder/my_file.txt
```

<details>
<summary><strong>버킷 네이밍 컨벤션</strong></summary>

- 대문자 금자, 언더스코어 금지

- <strong><code>길이</code></strong>&#58; 3 &#126; 64 사이

- 소문자, 숫자, 점(<code>&#46;</code>) 및 하이픈(<code>&#45;</code>)으로만 구성될 수 있다 &#46;

- 문자 또는 숫자로 시작하고 끝나야 한다&#46; 

- 두 마침표를 나란히 붙여 사용하면 안된다&#46; 

- IP 주소 형식 (ex&#46; 192&#46;168&#46;5&#46;4)을 사용하지 않는다&#46;

</details>

</details>

### 3&#46; Bucket Policy

> ✏️ 
> 
> <a id="1efeda9b0fe1805da999d5f1a11a05ba"></a>
> 
> <code>S3</code>은 <strong>기본적</strong>으로 <strong><u>퍼블릭 접근 권한 차단</u></strong>되어 있다&#46; 

<details>
<summary><strong><code>Bucket Policy</code></strong></summary>

> ✏️ 
> 
> <a id="1eeeda9b0fe1803eb903d9c4ffdd8a7a"></a>
> 
> <strong><code>Bucket Policy</code></strong>
> 
> ---
> 
> - IAM 과 유사한 <strong><u>JSON 형식</u></strong><strong><u>의 문서</u></strong>이다&#46; 
> 
> - <strong>버킷의 모든 객체</strong>에 대한 <strong><u>엑세스 제어 가능</u></strong>
> 
> - <strong><u>특정 객체</u></strong> 또는 <strong><u>객체 그룹</u></strong>에 대한 <strong><u>엑세스 제어 가능</u></strong>
> 
> - <strong><u>액세스를 허용</u></strong>하는<u> </u><strong><u>IP 주소</u></strong> 또는 <strong><u>범위</u></strong> 지정 가능
> 
> - <strong><u>액세스 가능</u></strong><strong>한 </strong><strong><u>리소스 범위 제한</u></strong><strong> 가능</strong>
> 
> - <strong><u>암호화된 연결</u></strong><strong><u>을 사용</u></strong>도록 <strong><u>강제</u></strong>할 수 있음

<details>
<summary>ex )</summary>

> ✏️ 
> 
> - <strong><code>Effect</code></strong>&#58; <code>Allow</code> or <code>Deny</code>
> 
> - <strong><code>Principal</code></strong>&#58; 대상 유저 ( iam )
> 
> - <strong><code>Resource</code></strong>&#58; <code>버킷</code> or <code>프로젝트</code>

<a id="1eeeda9b0fe180d79fe3e4d796169d9b"></a>

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowUserToGetBucket",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::ACCOUNT-ID:user/{USERNAME}"
            },
            "Action": "s3:GetBucketLocation",
            "Resource": "arn:aws:s3:::{BUCKET-NAME}"
        }
    ]
}
```

- 해당 정책은 IAM 사용자(<code>{USERNAME}</code>)가 <u>GetBucketLocation 작업</u><u>을 수행</u>할 수 있도록 지정된 버킷 <code>{BUCKET&#45;NAME}</code>에 대한 <strong><u>엑세서스를 허용</u></strong>한다&#46; 

</details>

</details>

<details>
<summary><strong><code>ARN</code></strong></summary>

> ✏️ 
> 
> <a id="1eeeda9b0fe180e8bd2ad57a2bf093db"></a>
> 
> AWS에서 사용하는 <strong><u>고유한 식별자</u></strong>로, AWS의 <strong><u>모든 리소스에 대한 고유한 식별자 역할</u></strong>을 한다&#46; 

<a id="1eeeda9b0fe18017b9d4f7c83bb14c7c"></a>

```javascript
arn:partition:service:region:account-id:resource-id
arn:partition:service:region:account-id:resource-type/resource-id
arn:partition:service:region:account-id:resource-type:resource-id
 
// 예시
arn:aws:iam::123456789012:user/johndoe
arn:aws:s3:::my_corporate_bucket/
arn:aws:ec2:us-east-1:123456789012:vpc/vpc-0e9801d129EXAMPLE
```

<details>
<summary>ARN 구성 형식</summary>

- <code>arn</code>&#58; AWS 리소스 이름을 가리키는 고정 문자열

- <code>aws</code>&#58; 리소스가 AWS에서 호스팅되는 것을 나타내는 고정 문자열

- <code>service</code>&#58; AWS 서비스 이름을 나타내는 문자열 
    - ex) <code>s3</code>, <code>lambda</code>, <code>ec2</code> 등 

- <code>region</code>&#58; AWS 리전 이름을 나타내는 문자열
    - ex) <code>us&#45;east&#45;1</code>, <code>ap&#45;northeast&#45;2</code> 등

- <code>account&#45;id</code>&#58; AWS 계정 ID를 나타내는 숫자

- <code>resource&#45;id</code>&#58; 해당 리소스의 고유 식별자
    - ex) S3 버킷 이름, <code>Lambda 함수 이름</code> 등 

</details>

</details>

### 4&#46; 정적 웹 호스팅 ( 프론트 )

> ✏️ 
>

### 5&#46; 파일 시스템

> ✏️ 
> 
> <a id="1efeda9b0fe18017ae42f2f825ead7ee"></a>
> 
> <strong>S3를 파일 시스템처럼 사용한다면 </strong><u>퍼블릭 접근을 허용하면 안</u><strong>된다&#46; </strong>
> 
> <a id="1efeda9b0fe18083a013fcbaafb65e6f"></a>
> 
> <strong><u>서버 측에서만 접근</u></strong><strong>하도록 설정하는 것이 보안적으로 올바르다&#46;</strong>
> 
> - <strong>ex)  백엔드 서버 &#45; 파일 업로드/다운로드, 이미지 저장소 등</strong>

<details>
<summary><strong> IAM 정책 예시 (EC2 Role에 부여)</strong></summary>

<a id="1efeda9b0fe180b8b48dda32e18ca11a"></a>

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
```

</details>

> 이미지 
>

> 
> 클라이언트로 받아온 이미지를 S3에 업로드하고 DB에는 해당 url 만 저장한다&#46; 
> 
> <a id="1efeda9b0fe18033a402cc83fa34557c"></a>
> 
> 그리고 해당 이미지 조회 요청 시, url 만을 반환하여 클라이언트에서 직접 S3로부터 자원을 가져오도록 한다&#46;
> 
> - S3가 클라이언트에게 직접 파일 서빙 → 부하 분산

<details>
<summary>🧐 S3에 너무 많은 부하가 걸리지 않나?</summary>

<a id="1efeda9b0fe180c5b5f9e8c16fc5b9f6"></a>

<code>S3</code>는 <strong><u>수백만 QPS(초당 요청 수) 를 감당</u></strong>할 수 있도록 설계된 <strong>매우 고성능 분산 스토리지</strong>이다&#46;

<details>
<summary><strong>1&#46; S3는 정적 콘텐츠 배포에 특화된 CDN 연계 스토리지이다&#46;</strong></summary>

- 고성능 서버 없이도 이미지, 동영상, HTML, JS 등을 안정적으로 제공 가능

- AWS 내부에서 자동으로 확장  → 사용자 수에 따라 서버 증설 불필요

</details>

<details>
<summary>2&#46;  대규모 서비스 &#45; S3 기반 운영</summary>

- 넷플릭스, 에어비앤비, 슬랙, 트레바리 등의 기업도 S3를 정적 리소스 저장소로 사용한다&#46;

- 이미지, 영상, 다운로드용 파일 등

</details>

<details>
<summary>3&#46; <strong>CloudFront 연동으로 트래픽 캐싱 가능</strong></summary>

- <strong>CloudFront가 S3 앞단(프론트)에서 동작하며, 사용자 요청을 캐싱하여 S3의 부하를 줄인다</strong>
    <a id="1efeda9b0fe18068894bee73d986c5d0"></a>

    ```plaintext
    [사용자 브라우저]
           |
           v
    [CloudFront (CDN)]  ← 콘텐츠 캐싱
           |
           v
    [S3 Origin]         ← 실제 비디오, 이미지 저장소
    ```

</details>
