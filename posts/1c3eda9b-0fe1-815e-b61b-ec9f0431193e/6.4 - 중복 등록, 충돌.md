같은 빈 이름을 등록 시, 컴포넌트 스캔에서 두가지의 충돌 상황이 발생한다&#46;<br>

1. <strong>자동 빈 등록 vs 자동 빈 등록</strong>

1. <strong>수동 빈 등록 vs 자동 빈 등록</strong>

<a id="1c3eda9b0fe18108863cca09985b5bbc"></a>

### 자동 빈 등록 vs 자동 빈 등록

---

<a id="1c3eda9b0fe181e39f54daa6e17bfb69"></a>

자동으로 빈 등록 시, 동일한 빈 이름으로 충돌이 발생한 경우 오류가 발생된다&#46;<br>→ <code>ConflictingBeanDefinitionException</code> 예외 발생

<a id="1c3eda9b0fe181cf9663cfd4cd9eb4c0"></a>

### <strong>수동 빈 등록 </strong>vs <strong>자동 빈 등록</strong>

---

<a id="1c3eda9b0fe181098f5ef084be412e7a"></a>

```java
// 자동 빈 등록
@Component
public class MemoryMemberRepository implements MemberRepository {}
```

<a id="1c3eda9b0fe1811896cae3609ac9642f"></a>

```java
// 수동 빈 등록
 @Configuration
 @ComponentScan(
         excludeFilters = @Filter(type = FilterType.ANNOTATION, classes =Configuration.class)
 )
 public class AutoAppConfig {
     @Bean(name = "memoryMemberRepository")
     public MemberRepository memberRepository() {
         return new MemoryMemberRepository();
     }
}
```

> 수동으로 등록 한 빈이 우선권을 가진다&#46;<br>→ 수동 빈이  자동 빈을 오버라이딩 처리

<a id="1c3eda9b0fe181b9a3ebfce3276e146d"></a>

<strong>수동 빈 등록시 남는 로그</strong>

<a id="1c3eda9b0fe181518e31cebb28e9d9cd"></a>

```plaintext
Overriding bean definition for bean 'memoryMemberRepository' with a differentdefinition: replacing
```

<a id="1c3eda9b0fe1810c928ed075e28e9aef"></a>

설계 시, 의도적으로 해당 결과(수동 빈 오버라이드)를 기대했다면, 수동 조작이 우선권을 가지는 것이 좋지만, 현실은 여러 설정들이 꼬여서 발생하는 경우가 대부분이다&#46;

<a id="1c3eda9b0fe181b8b94cf5b135260f7c"></a>

→ <strong>애매한 처리하기 어려운 버그</strong>가 만들어진다고함… 

<a id="1c3eda9b0fe1817eb4b9f2a434ea6334"></a>

⇒ 스프링부트에서 수동 빈 등록과 자동 빈 등록이 충돌나면 오류가 발생하도록 기본 값이 변경됨(강의 버전이 좀 지났다… 재확인이 필요)

<a id="1c3eda9b0fe181478313dec99658bb03"></a>

<strong>수동 빈 등록, 자동 빈 등록 오류시 스프링 부트 에러</strong>

> 스프링 부트인 <code>CoreApplication</code> 을 실행해보면 오류를 볼 수 있음

<a id="1c3eda9b0fe18101a416d669d5432bbd"></a>

```plaintext
Consider renaming one of the beans or enabling overriding by setting
spring.main.allow-bean-definition-overriding=trues
```
