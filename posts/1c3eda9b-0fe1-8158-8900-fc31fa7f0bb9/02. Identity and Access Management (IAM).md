## IAM 

---

<a id="1c3eda9b0fe18167aa15da1c748c903a"></a>

AWS 계정 및 권한 관리하는 서비스이다&#46; 

<a id="1c3eda9b0fe181439be7d1c791469026"></a>

AWS 서비스와 리소스에 대한 <strong>엑세스를 관리</strong>하며 사용자, 그룹, 역할, 정책으로 구성된다&#46;

<a id="1c3eda9b0fe18197a871df6fc0c3bc37"></a>

<strong>리전에 속하는 서비스가 아닌</strong> <strong>글로벌 서비스</strong>로 계정 보안 강화를 위해 루트 계정(AWS 회원가입 시 만들어지는 계정)은 최초 사용자 계정 생성 이후 가능하면 사용하지 않는다&#46; 

![](0fdd7926717c2c8d.webp)

<a id="1c3eda9b0fe181c79322e03c2d568ded"></a>

사용자 계정(IAM 계정)으로 서비스를 사용하고 사용자는 필요한 최소한의 권한만 부여(최소 권한의 원칙)

<a id="1c3eda9b0fe181aca16bcb686e9c9c65"></a>

루트 계정과 개별 사용자 계정에 강력한 암호 정책과 멀티팩터 인증(MFA) 적용<br>사용자의 암호에 대한 복잡성 요구 사항과 의무 교체 주기를 정의

<a id="1c3eda9b0fe181d4af10c5d74373625f"></a>

<strong>액세스 키(Access Key)</strong>는 공유하면 안된다&#33;

<a id="1c3eda9b0fe1814e8053d7ef3e9f0cc1"></a>

## IAM 루트 사용자 자격 증명을 요구하는 작업

---

<a id="1c3eda9b0fe181d49f7dec879966b6d0"></a>

계정 설정을 변경(계정 이름, 이메일 주소, 루트 사용자 암호 및 루트 사용자 액세스 키), 연락처 정보, 결제 통화 기본 설정 및 리전과 같은 기타 계정 설정에는 루트 사용자 자격 증명이 필요하지 않음&#46;

<a id="1c3eda9b0fe181408f16dd45c07ae8c6"></a>

IAM 사용자 권한을 복원, IAM 관리자가 실수로 권한을 취소하면 루트 사용자로 로그인하여 정책을 편집하고 해당 권한을 복원

<a id="1c3eda9b0fe181f0891fda3b2c5f74d7"></a>

Biling and Cost Management 콘솔에 대한 IAM 액세스 활성화

<a id="1c3eda9b0fe181e8a499fef5a64b6f4a"></a>

특정 세금 계산서를 조회

<a id="1c3eda9b0fe18191809ec60105c0f46f"></a>

AWS 계정을 닫음f

<a id="1c3eda9b0fe181a4af7fedcba38303fe"></a>

AWS 지원 플랜(Support Plan)을 변경하거나 AWS 지원 플랜을 취소

<a id="1c3eda9b0fe18103b291d3c48c2d7b04"></a>

예약 인스턴스 마켓플레이스에 판매자로 등록

<a id="1c3eda9b0fe181daa4d5c957ec1e1ad9"></a>

MFA(멀티 팩터 인증) Delete를 활성화하도록 Amazon S3 버킷을 구성

<a id="1c3eda9b0fe18199a3e8f165a9f53917"></a>

잘못된 VPC ID 또는 VPC 엔드포인트 ID가 들어 있는 Amazon S3 버킷 정책을 편집하거나 삭제

## IAM &#45; 정책

---

<a id="1c3eda9b0fe181f6b441e94990aa282b"></a>

AWS 리소스에 대한 액세스 권한을 정의 한 것

<a id="1c3eda9b0fe18106b1b6c2ee927f8706"></a>

사용자, 그룹, 역할에 정책을 연결하여 사용

<a id="1c3eda9b0fe18179a55ff6a381941f44"></a>

가능하면 정책을 개별 사용자에게 직접 부여하지 말고 사용자가 속한 그룹에 권한 부여

<a id="1c3eda9b0fe181bd8d5eff0428f9537f"></a>

IAM 정책 종류

<a id="1c3eda9b0fe181c092f5e7305aad444a"></a>

• AWS 관리형 정책&#58; AWS에서 생성 및 관리하는 정책

<a id="1c3eda9b0fe181928679fbbe91ee94f6"></a>

• 고객 관리형 정책(사용자 지정 정책)&#58; 사용자가 직접 생성 및 관리하는 정책

<a id="1c3eda9b0fe18132a380c71352cbcfbe"></a>

• 인라인 정책&#58; 사용자, 그룹, 역할에 직접 생성하는 정책

<a id="1c3eda9b0fe181ed9b64fa9d99ea2124"></a>

• 대부분의 경우 관리형 정책을 사용하는 것을 권장

<a id="1c3eda9b0fe181d78257c1cf674e518e"></a>
