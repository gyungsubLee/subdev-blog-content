가상 메모리(Virtual Memory)는 현대 컴퓨팅 시스템에서 물리적 메모리(DRAM)의 용량 한계를 극복하고, 프로세스 간 완전한 메모리 격리(Isolation) 및 보안을 보장하는 핵심 하드웨어&#45;소프트웨어 추상화 계층이다&#46; 

<a id="3f4eda9b0fe180d7a370fcf7d0694f0a"></a>

운영체제 커널은 중앙 처리 장치(CPU)의 메모리 관리 장치(MMU)와 긴밀히 협력하여 가상 주소 공간을 물리적 주소 공간으로 다단계 변환하며, 요구 페이징(Demand Paging), 메모리 압축(Memory Compression), 계층적 스왑(Tiered Swapping) 메커니즘을 통해 하드웨어 자원의 효율성을 극대화한다&#46;

<a id="3f4eda9b0fe18023914feee548cccd70"></a>

가상 메모리의 하드웨어 및 소프트웨어 추상화 계층가상 메모리 아키텍처의 핵심은 가상 주소(Virtual Address)를 실제 메모리 칩의 물리 주소(Physical Address)로 변환하는 계층적 페이지 테이블(Hierarchical Page Table) 구조에 있다 &#91;cite&#58; 1, 2&#93;&#46; 64비트 아키텍처 환경에서는 주소 공간이 매우 광대하고 희소(Sparse)하게 분포하므로, 전체 주소를 단일 테이블로 관리하는 것은 메모리 오버헤드 측면에서 불가능하다 

<a id="3f4eda9b0fe180e6ad38e9585a9c6735"></a>

&#91;cite&#58; 2&#93;&#46; 이에 따라 운영체제는 다단계 라딕스 트리(Radix Tree) 형태의 페이지 테이블 구조를 채택한다 &#91;cite&#58; 2, 3&#93;&#46;x86&#95;64 페이징 모드 구조&#58; 4단계 및 5단계 페이징x86&#95;64 아키텍처에서 전통적인 표준은 48비트 가상 주소를 사용하는 4단계 페이징(4&#45;level Paging) 방식이다 &#91;cite&#58; 1, 3&#93;&#46; 4단계 페이징은 각 프로세스당 256TB의 가상 주소 공간(사용자 공간 128TB, 커널 공간 128TB)을 제공한다 &#91;cite&#58; 3&#93;&#46; 그러나 데이터베이스 및 인공지능 워크로드가 급격히 확장됨에 따라 테라바이트급 이상의 단일 메모리 요구가 발생하였고, 이를 지원하기 위해 Linux 4&#46;14 커널부터 LA57(57&#45;bit Linear Addresses)을 통한 5단계 페이징(5&#45;level Paging)이 도입되었다 &#91;cite&#58; 1, 3, 4&#93;&#46; 5단계 페이징은 최대 128PB의 가상 주소 공간을 프로세스에 할당할 수 있도록 확장한다 &#91;cite&#58; 3&#93;&#46;4단계 페이징 환경에서 48비트 가상 주소의 주소 변환 분할 수식은 다음과 같이 정의된다&#58;&#36;&#36;VA&#95;{48} = &#92;text{PGD}&#91;47&#58;39&#93; &#92;Vert &#92;text{PUD}&#91;38&#58;30&#93; &#92;Vert &#92;text{PMD}&#91;29&#58;21&#93; &#92;Vert &#92;text{PTE}&#91;20&#58;12&#93; &#92;Vert &#92;text{Offset}&#91;11&#58;0&#93;&#36;&#36;반면, 5단계 페이징 환경에서 57비트 가상 주소의 주소 변환 분할 수식은 다음과 같이 P4D 계층이 추가되어 확장된다 &#91;cite&#58; 1, 3&#93;&#58;&#36;&#36;VA&#95;{57} = &#92;text{PGD}&#91;56&#58;48&#93; &#92;Vert &#92;text{P4D}&#91;47&#58;39&#93; &#92;Vert &#92;text{PUD}&#91;38&#58;30&#93; &#92;Vert &#92;text{PMD}&#91;29&#58;21&#93; 4단계 페이징 시스템에서는 소프트웨어 계층에서 P4D 디렉터리가 폴딩(Folding) 처리되어 <code>p4d&#95;offset()</code> 함수가 상위 PGD 엔트리를 그대로 반환하는 무작업(No&#45;op) 함수로 최적화된다 &#91;cite&#58; 1, 4&#93;&#46;페이징 모드가상 주소 비트주소 공간 크기최상위 디렉터리페이지 테이블 탐색 계층주요 적용 환경<strong>x86&#45;32 (기본)</strong>32 비트4 GBPGDPGD &#36;&#92;rightarrow&#36; (P4D Folded) &#36;&#92;rightarrow&#36; PUD &#36;&#92;rightarrow&#36; PMD &#36;&#92;rightarrow&#36; PTE범용 데스크톱 및 일반 서버 &#91;cite&#58; 1, 3&#93;<strong>x86&#45;64 (5단계, LA57)</strong>57 비트128 PBPGDPGD &#36;&#92;rightarrow&#36; P4D &#36;&#92;rightarrow&#36; PUD &#36;&#92;rightarrow&#36; PMD &#36;&#92;rightarrow&#36; PTE대규모 인메모리 DB 및 초거대 인프라 &#91;cite&#58; 1, 3&#93;페이지 테이블 엔트리(PTE) 비트 레이아웃 및 제어 플래그페이지 테이블의 최하위 계층인 PTE(Page Table Entry)는 64비트 크기의 데이터 구조로서, 단순한 물리 페이지 프레임 번호(PFN, Page Frame Number) 외에 해당 페이지의 상태 및 하드웨어적 접근 권한을 제어하는 제어 비트들을 포함한다 &#91;cite&#58; 1, 3&#93;&#46;PTE 비트 구조의 최하위 비트인 Present(Bit 0) 플래그는 해당 페이지가 실제 물리 메모리(RAM)에 상주하는지 여부를 나타내며, 0으로 설정된 상태에서 접근이 발생하면 하드웨어 페이지 폴트(&#35;PF) 예외가 유발된다 &#91;cite&#58; 3, 5&#93;&#46; Read/Write(Bit 1) 플래그는 페이지의 쓰기 권한을 제어하여 쓰기 시 복사(Copy&#45;on&#45;Write) 메커니즘 구현의 핵심 기반을 제공하고, User/Supervisor(Bit 2) 플래그는 커널 전용 영역과 사용자 영역의 접근 권한을 격리한다 &#91;cite&#58; 5&#93;&#46; Page WT(Bit 3)와 Page CD(Bit 4)는 CPU 하드웨어 캐시의 Write&#45;Through 및 Cache Disable 정책을 결정한다&#46;또한 Accessed(Bit 5)와 Dirty(Bit 6) 비트는 MMU가 페이지를 읽거나 쓸 때 하드웨어적으로 1로 세팅하여, 커널 페이지 교체 알고리즘(LRU)에서 페이지의 가치 판단 기준으로 활용된다&#46; Page Size(Bit 7) 비트는 상위 계층 엔트리(PMD/PUD)에서 활성화될 때 하위 PTE 계층을 거치지 않고 직접 2MB 또는 1GB 단위의 대형 페이지를 매핑하도록 변경한다 &#91;cite&#58; 1, 3&#93;&#46; Global(Bit 8) 비트는 프로세스 전환 시 TLB 플러시 대상에서 제외되도록 지정하며, 최상위 비트인 Execute Disable(Bit 63, XD/NX) 비트는 인스트럭션 인출을 차단하여 버퍼 오버플로우 공격을 방지한다 &#91;cite&#58; 3&#93;&#46;페이지 테이블 변환 및 락/캐싱 최적화 메커니즘가상 주소를 물리 주소로 변환할 때 매번 메모리의 4단계 또는 5단계 페이지 테이블 구조를 조회하는 것은 상당한 딜레이를 유발한다 &#91;cite&#58; 1&#93;&#46; 이를 해결하기 위해 CPU 내부에는 고속 전용 캐시 메모리인 TLB(Translation Lookaside Buffer)가 집적되어 있다 &#91;cite&#58; 1, 2&#93;&#46;TLB 동작과 슛다운(Shootdown) 오버헤드TLB는 가장 최근에 변환된 가상 주소&#45;물리 주소 매핑 쌍을 주소 변환 캐시 형태로 저장한다 &#91;cite&#58; 1, 2&#93;&#46; TLB 히트(Hit) 시 1 클럭 주기 이내에 주소 변환이 완료되지만, TLB 미스(Miss) 발생 시 MMU는 메모리를 여러 번 읽는 페이지 워크(Page Walk)를 수행한다 &#91;cite&#58; 1&#93;&#46;대규모 대칭형 다중 처리(SMP) 환경에서는 프로세스 주소 공간이 변경(예&#58; 페이지 해제, 접근 권한 축소)될 때, 다른 코어의 TLB에 남아있는 유효하지 않은 매핑 정보를 동기화하는 작업이 필수적이다 &#91;cite&#58; 1&#93;&#46; 이를 TLB 슛다운(TLB Shootdown)이라 하며, 주 코어가 다른 모든 코어에게 프로세서 간 인터럽트(IPI, Inter&#45;Processor Interrupt)를 전송하고 코어들의 실행을 멈춘 뒤 TLB를 비우는 방식으로 동작한다 &#91;cite&#58; 1&#93;&#46; IPI 발생은 시스템 전체의 컨텍스트 스위칭 오버헤드를 가중시키고 멀티코어 확장성을 저해하는 주요 원인이 된다 &#91;cite&#58; 1&#93;&#46;PCID 및 KPTI 기반 하드웨어 보안 최적화컨텍스트 스위칭 시 실행되는 프로세스가 바뀌면 CR3 레지스터가 새로운 프로세스의 PGD 주소로 갱신되며, 기본적으로 사용자 공간 TLB 캐시 전체가 플러시된다 &#91;cite&#58; 1, 3&#93;&#46; 이러한 성능 손실을 극복하기 위해 최신 x86 프로세서는 PCID(Process&#45;Context Identifiers) 기능을 제공한다 &#91;cite&#58; 3&#93;&#46;PCID는 CR3 레지스터 하위 12비트에 주소 공간 식별자(ASID)를 부여함으로써, 컨텍스트 스위칭 후에도 이전 프로세스의 TLB 엔트리를 무효화하지 않고 유지할 수 있게 한다 &#91;cite&#58; 3&#93;&#46; CR3 레지스터를 로드할 때 최상위 비트(Bit 63)를 1로 설정하면 하드웨어가 기존 TLB를 무효화하지 않는 NOFLUSH 비트로 동작하여 프로세스 전환 시의 주소 변환 오버헤드가 크게 경감된다 &#91;cite&#58; 3&#93;&#46;멜트다운(Meltdown) 보안 취약점을 해결하기 위해 도입된 KPTI(Kernel Page Table Isolation)는 커널 메모리 영역과 사용자 메모리 영역의 주소 공간을 완벽히 분리하여 2개의 PGD를 유지하게 만든다 &#91;cite&#58; 3&#93;&#46; 이로 인해 시스템 콜 호출 및 인터럽트 발생 시마다 CR3 레지스터를 교체해야 하는 대량의 성능 저하가 발생하였으나, KPTI와 PCID 기술을 결합 적용함으로써 CR3 전환 시 TLB 플러시를 방지하여 보안 조치로 인한 성능 저하를 최소화하였다 &#91;cite&#58; 3&#93;&#46;휴지 페이지(Huge Pages) 기술을 통한 성능 확장페이지 크기를 기본 4KB에서 2MB 또는 1GB 단위로 확대하는 휴지 페이지(Huge Pages) 기술은 주소 변환 성능을 획기적으로 끌어올린다 &#91;cite&#58; 1, 3&#93;&#46;PMD 레벨에서 PS(Page Size) 비트를 1로 설정하면, PTE 계층을 거치지 않고 PMD 엔트리가 직접 2MB 물리 프레임을 매핑한다 &#91;cite&#58; 1, 3&#93;&#46; 이에 따라 필요한 페이지 테이블 메모리 용량이 줄어들고, 동일한 TLB 엔트리 수로 수백 배 이상의 가상 메모리 영역을 커버할 수 있어 TLB 미스 비율과 페이지 워크 횟수를 크게 감소시킨다 &#91;cite&#58; 1&#93;&#46;페이지 폴트(Page Fault) 예외 처리 파이프라인프로세스가 접근하려는 가상 주소의 PTE 내 Present 비트가 0이거나 접근 권한을 위반할 경우, MMU는 하드웨어 예외인 페이지 폴트(&#35;PF, Vector 14)를 발생시킨다 &#91;cite&#58; 3, 5&#93;&#46;아키텍처 의존적 영역에서 독립적 영역으로의 전환페이지 폴트가 발생하면 CPU는 오작동을 유발한 가상 주소를 <code>CR2</code> 레지스터에 저장하고, 하드웨어 에러 코드를 커널 스택에 푸시한 후 <code>asm&#95;exc&#95;page&#95;fault</code> 어셈블리 진입점으로 제어를 이동시킨다 &#91;cite&#58; 5&#93;&#46; 진입 루틴은 CPU 레지스터 상태를 레지스터 스택에 보존한 다음 C 언어 예외 처리기인 <code>exc&#95;page&#95;fault()</code> 및 <code>do&#95;user&#95;addr&#95;fault()</code>를 순차적으로 호출한다 &#91;cite&#58; 5&#93;&#46;이 단계에서 커널은 접근이 시도된 가상 주소가 프로세스의 메모리 맵을 나타내는 <code>vm&#95;area&#95;struct</code>(VMA) Red&#45;Black 트리에 존재하는 유효한 구간인지를 검증한다 &#91;cite&#58; 5, 6&#93;&#46; 존재하지 않는 주소이거나 읽기 전용 영역에 쓰기를 시도하는 등 권한을 위반한 경우, 커널은 프로세스에 <code>SIGSEGV</code> 신호를 전달하여 실행을 중단시킨다 &#91;cite&#58; 1, 5&#93;&#46; 유효성 검증이 완료되면 예외 처리 흐름은 아키텍처 독립적인 핵심 메모리 관리 함수인 <code>handle&#95;mm&#95;fault()</code>로 이관된다 &#91;cite&#58; 16&#93;&#46;프로세스가 시간 &#36;t&#36; 시점에 참조한 페이지들의 집합을 &#36;P&#36;라 할 때, 델타(&#36;&#92;tau&#36;)만큼의 과거 시간 window 동안 프로세스가 참조한 페이지들의 집합인 워킹 셋 &#36;W(t, &#92;tau)&#36;는 다음과 같이 수식화된다&#58;&#36;&#36;W(t, &#92;tau) = &#92;{ p &#92;in P &#92;mid &#92;text{시각 } (t &#45; 10, 11&#93;&#46; 반대로 페이지 폴트 간격 &#36;T&#36;가 &#36;T&#95;{&#92;text{threshold}}&#36;보다 커지면 해당 프로세스에 물리 프레임이 과도하게 할당된 것으로 판단하고, 오랫동안 참조되지 않은 물리 프레임들을 회수하여 가용 메모리 풀에 반납함으로써 전체 시스템의 쓰레싱을 예방한다 &#91;cite&#58; 1, 3, 4&#93;&#46; 또한 단순 스왑을 넘어선 <code>zswap</code>과 같은 정교한 메모리 내 압축 캐시 메커니즘의 결합은 보조 기억 장치의 디스크 I/O 병목을 상쇄하는 필수 아키텍처로 자리 잡았다 &#91;cite&#58; 13, 14&#93;&#46;향후 가상 메모리 아키텍처는 CXL(Compute Express Link) 기반의 분산 메모리(Disaggregated Memory) 모듈 도입과 비휘발성 메모리(NVDIMM) 확장에 맞춰 근본적인 패러다임 변화를 맞이하고 있다&#46;
