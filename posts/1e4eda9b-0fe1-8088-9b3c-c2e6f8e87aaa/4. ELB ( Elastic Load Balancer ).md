## ELB ( Elastic Load Balancer )

---

> 📖 
> 
> <a id="1eceda9b0fe180bcaccef90655b46361"></a>
> 
> <strong><code>ELB</code></strong> ( <strong><code>Elastic Load Balancer</code></strong> )
> 
> ---
> 
> ![](efc41ee236b9657f.webp)
> 
> <a id="1eceda9b0fe180d39b33c4a80a9e529c"></a>
> 
> <code>ELB</code>(Elastic Load Balancer)는 AWS에서 제공하는 <u>로드 밸런싱 서비스</u>이다&#46; 
> 
> - 내부망 사용 시, HTTP 통신도 가능하다&#46;

<details>
<summary>로드 벨런서 </summary>

> ✏️ 
> 
> <a id="1eceda9b0fe180d783d5caff20e84194"></a>
> 
> <strong><code>로브벨런서</code></strong>는 <strong><u>분산 시스템 환경</u></strong>에서 <strong>트래픽(요청)을 다수의  인스턴스들에게 적절히 분산</strong> 시키는 장치 또는 소프트웨어이다&#46;
> 
> <details>
> <summary><strong><u>성능 향상, 과부하 방지, 장애 대응</u></strong>을 가능한 인프라 구축 가능</summary>
> 
> | <strong>문제</strong> | <strong>로드 밸런서 도입 전</strong> | <strong>로드 밸런서 도입 후</strong> |
> | --- | --- | --- |
> | <strong><code>성능</code></strong> | 한 서버에 요청 몰림, 과부하 | 여러 서버가 나눠서 처리 |
> | <strong><code>장애</code></strong> | 한 서버가 죽으면 전체 서비스 중단 | 나머지 서버가 요청 처리 가능 |
> | <strong><code>확장성</code></strong> | 서버 1대만 사용 | 서버를 추가하여 쉽게 확장 가능 |
> 
> </details>

<details>
<summary>핵심 기능</summary>

1. <strong><code>트래픽 분산</code></strong>&#58; 클라이언트 요청을 여러 서버에 분산

1. <strong><code>헬스 체크</code></strong>&#58; 서버 상태 주기적으로 확인, 비정상 서버는 제외

1. <strong><code>자동 장애 처리 (Failover)</code></strong>&#58; 한 서버가 죽어도 서비스 지속 가능

1. <strong><code>세션 고정 (Sticky Session)</code></strong>&#58; 같은 사용자 요청은 같은 서버로 고정 (선택적)

1. <strong><code>SSL 종료 (TLS Termination)</code></strong>&#58; HTTPS 처리를 로드 밸런서에서 처리 가능

</details>

<details>
<summary>유형</summary>

- <strong>계층 (  OSI Layer )</strong>
    | <strong>구분</strong> | <strong>설명</strong> | <strong>예시</strong> |
    | --- | --- | --- |
    | <strong><code>L4</code></strong><strong>, 전송 계층</strong> | TCP/UDP 수준에서 분산 | <code>AWS NLB</code>, <code>HAProxy TCP 모드</code> |
    | <strong><code>L7</code></strong><strong>, 애플리케이션 계층</strong> | HTTP, URL, 쿠키 등 기준 분산 | <code>AWS ALB</code>, <code>Nginx</code>, <code>Traefik</code> |

- <strong>운영 방식</strong>
    | <strong>유형</strong> | <strong>설명</strong> | <strong>예시</strong> |
    | --- | --- | --- |
    | <strong><u>하드웨어 </u></strong><strong>로드 밸런서</strong> | 전용 장비, 고성능, 비쌈 | <code>F5</code>, <code>Citrix</code> 등 |
    | <strong><u>소프트웨어</u></strong><strong> 로드 밸런서</strong> | 일반 서버에 설치 | <code>Nginx</code>, <code>HAProxy</code> |
    | <strong><u>클라우드형</u></strong><strong> 로드 밸런서</strong> | 관리형 서비스 | <code>AWS ELB</code>, <code>GCP Load Balancer</code> |

</details>

<details>
<summary>분산 알고리즘</summary>

| <strong>알고리즘</strong> | <strong>설명</strong> |
| --- | --- |
| <strong><code>Round Robin</code></strong> | 요청을 순서대로 서버에 분산 |
| <strong><code>Least Connection</code></strong> | 연결 수가 가장 적은 서버에 분산 |
| <strong><code>IP Hash</code></strong> | 클라이언트 IP 기준으로 서버 고정 |
| <strong><code>Weighted Round Robin</code></strong> | 성능 좋은 서버에 더 많은 요청 분산 |

</details>

</details>

<details>
<summary>ELB 유형</summary>

> ✏️ 
> 
> <a id="1eceda9b0fe180079834e073bca7d2c6"></a>
> 
> AWS 에서는 다양한 유형의 로드 밸런서를 지원한다&#46;
> 
> <a id="1eceda9b0fe1807da347ed8968e92675"></a>
> 
> 각각의 로드 밸런서는 다양한 기능과 구성을 제공하며, 선택적으로 사용할 수 있다&#46;
> 
> <a id="1eceda9b0fe1806db589dff331cc5177"></a>
> 
> 이러한 <strong><u>로드 밸런서</u></strong>를 통해 <strong><u>고가용성 및 확정성이 있는 인프라 구축이 가능</u></strong>하기 때문에 <br><strong><u>인스턴스의 장애와 부하 분산에 대한 대응을 용이</u></strong>하게 해준다&#46; 
> 
> - ex) <code>ALB</code> &#45;  URL 경로 라우팅, 호스트 기반 라우팅 등 다양한 라우팅 정책 제공

<details>
<summary><code>ALB</code>( Application Load Balancer )</summary>

- OSI 모델 7 계층에서 동작하며, HTTP/HTTPS 트래픽을 처리한다&#46; 

- 또한, 컨테이너화된 애플리케이션과 연동하여 사용할 수 있다&#46;

---

- HTTP 요청을 여러 타깃 그룹에 나눠줄 수 있다

- 한 머신 안이라도 여러 어플리케이션(컨테이너)에 나눠 줄 수 있다&#46;

- HTTP/2 와 웹소켓 지원

- HTTPS 로 리다이렉트 지원

- URL, hostname, quert string, header 에 기반해서 다른 타깃 그룹으로 보낼 수 있다&#46;

</details>

<details>
<summary><code>NLB</code>( Network Load Balancer )</summary>

- OSI 모델 4계층에서 동작하며, TCP/UDP 트래픽을 처리한다&#46; 

- 높은 처리량을 필요로 하는 애플리케이션에 적합하다&#46; 

</details>

<details>
<summary><code>CLB</code> ( Classic Load Balancer )</summary>

- OSI 모델 4 &#126; 7 계층에서 동작하며, HTTP/HTTPS, TCP/UDP 트래픽을 처리한다&#46; 

- 가장 오래된 형태의 로드 벨런서이다&#46; <br>따라서 <code>ALB</code>, <code>NLB</code> 사용을 권장한다&#46;

</details>

</details>

<summary><strong>SSL ( Secure Sockets Layer )</strong></summary>

- 인터넷 상에서 정보를 안전하게 전송하기 위한 프로토콜이다&#46; 

- SSL은 클라이언트와 서버 사이에 안전한 접속을 만들어주며, 전송되는 데이터를 암호화하여 정보의 안전성을 보장한다&#46;

</details>

<details>
<summary><strong>TLS ( Transport Layer Security )</strong></summary>

- SSL을 보완한 기술로 현재는 사실 SSL이 아니라 TLS 기술이다

-  그러나 모두가 아직까지 SSL이라고 부르고 있다
