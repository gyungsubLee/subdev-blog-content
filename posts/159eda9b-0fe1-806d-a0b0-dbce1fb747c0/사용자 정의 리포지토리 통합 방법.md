<a id="159eda9b0fe1807b94f3f7f53a95ad52"></a>

Spring Data JPA는 사용자 정의 레포지토리를 통합하는 데 있어 <strong><u>컨벤션 기반의 매핑 기능을 제공</u></strong>한다 

<a id="159eda9b0fe180d3bb52d3612c48a72d"></a>

 이 기능은 개발자가 인터페이스를 정의하면, 스프링이 자동으로 구현체를 생성하여 데이터 접근 로직을 처리할 수 있게 해준다&#46; 그러나 <u>복잡한 쿼리나 동적 쿼리가 필요한 경우</u>에는 <strong><u>사용자 정의 리포지토리를 통해 추가적인 기능을 구현</u></strong>해야 한다&#46;

<a id="159eda9b0fe180bf92afc79f088daa93"></a>

## 사용자 정의 리포지토리 통합 방법

---

<a id="159eda9b0fe180aebebddc1c87de62c0"></a>

### 1&#46; 사용자 정의 인터페이스 생성

<a id="159eda9b0fe180649930ff55d5be6058"></a>

먼저, 필요한 메서드를 선언하는 사용자 정의 인터페이스를 생성한다&#46;

- 특정 조건에 맞는 멤버를 찾는 메서드를 선언할 수 있다&#46;

<a id="159eda9b0fe180b5b7d8d1ea150f4657"></a>

```java
public interface MemberRepositoryCustom {
    List<Member> findMemberCustom();
}
```

<a id="159eda9b0fe1809d9ee1ddd7693c3659"></a>

### 2&#46; 사용자 정의 인터페이스 구현 클래스 작성

<a id="159eda9b0fe180c49b4ef41569f0cf3a"></a>

사용자 정의 인터페이스를 구현하는 클래스를 작성한다&#46;

<a id="159eda9b0fe1805ca4b7ce795ebcc913"></a>

이 클래스는 <code>인터페이스 이름 &#43; Impl</code> 형식으로 명명되어야 하며,<code>EntityManager</code>를 사용하여 직접 쿼리를 실행할 수 있다&#46;

- 스프링은 이 <u>구현체</u>를 <u>프록시 객체로 생성</u>하여 <u>빈으로 등록</u>한다&#46;

<a id="159eda9b0fe180d8992be7483af3e424"></a>

```java
@RequiredArgsConstructor
public class MemberRepositoryImpl implements MemberRepositoryCustom {
    private final EntityManager em;

    @Override
    public List<Member> findMemberCustom() {
        return em.createQuery("select m from Member m", Member.class).getResultList();
    }
}
```

<a id="159eda9b0fe18036b475f285892d2fa6"></a>

### 3&#46; 기존 리포지토리에 사용자 정의 인터페이스 통합

<a id="159eda9b0fe1806496addaddc97be7d9"></a>

기존의 JPA 리포지토리 인터페이스에 사용자 정의 인터페이스를 상속받아 통합한다&#46;

<a id="159eda9b0fe1809ea4d5e9d0ed3d48d5"></a>

이렇게 하면 기본 CRUD 메서드와 함께 사용자 정의 메서드를 사용할 수 있다&#46;

<a id="159eda9b0fe180c1b195de803d3044da"></a>

```java
public interface MemberRepository extends JpaRepository<Member, Long>, MemberRepositoryCustom {
    // 기본 CRUD 메서드와 사용자 정의 메서드 사용 가능
}
```

<a id="159eda9b0fe180df8e69df09345a2774"></a>

## 동적 쿼리 작성

---

<a id="159eda9b0fe180d98525c81d085b12aa"></a>

동적 쿼리는 실행 시점에 조건이나 구조가 변경될 수 있는 쿼리로 Spring Data JPA에서는 여러 가지 방법으로 동적 쿼리를 작성할 수 있다&#46;

- JPQL&#58; Java Persistence Query Language

- Criteria API&#58; 타입 안전성과 동적 쿼리 작성을 지원하는 API

- QueryDSL&#58; 복잡한 동적 쿼리를 쉽게 작성할 수 있도록 도와주는 라이브러리

<a id="159eda9b0fe1808ba528dfc55fd2a05d"></a>

작성 및 유지보수를 위해 스프링에서는 동적 쿼리 처리를 QueryDSL을 많이 사용해서 처리한다&#46;

<a id="159eda9b0fe18042897ec47a5f85f3d0"></a>

## 사용자 정의 리포지토리 통합 방법 &#45; QueryDSL

---

<a id="159eda9b0fe1807ea076e42e25b502a5"></a>

방법은 위와 동일하지만 QueryDSL을 사용하기 위해서 약간의 추가 설정이 필요하다&#46; 

1. 의존성 등록
    - 강의 코드 기준

    <a id="15beda9b0fe180a582dbce11b951d141"></a>

    ```sql
    // 9. QueryDSL 적용을 위한 의존성 (SpringBoot3.0 부터는 jakarta 사용해야함)
    implementation 'com.querydsl:querydsl-jpa:5.0.0:jakarta'
    annotationProcessor "com.querydsl:querydsl-apt:${dependencyManagement.importedProperties['querydsl.version']}:jakarta"
    annotationProcessor "jakarta.annotation:jakarta.annotation-api"
    annotationProcessor "jakarta.persistence:jakarta.persistence-api"
    ```

1. config 설정
    - 해당 config를 통해 JPAQueryFactory를 빈으로 등록해야지 QueryDSL을 사용할 수 있다&#46;

    <a id="9e95c0f7fff34641a64ffb7f49d16df6"></a>

    ```java
    @Configuration
    public class JPAConfiguration {

      @PersistenceContext
      private EntityManager entityManager;

      @Bean
      public JPAQueryFactory jpaQueryFactory() {
        return new JPAQueryFactory(entityManager);
      }
    }
    ```

1. 사용자 정의 리포지토리 통합 방법  &#45; 위와 동일하다&#46; 
    <a id="15beda9b0fe180808374d09ff74a6dd4"></a>

    3&#46;1 구현체 클래스 생성

    <a id="15beda9b0fe180748307d6768538fb83"></a>

    ```sql
    @Service
    public class UserService {

        private final UserRepository userRepository;

        public UserService(UserRepository userRepository) {
            this.userRepository = userRepository;
        }

        // 일반 데이터 조회
        public List<User> getUsersByName(String name) {
            // 비즈니스 로직 처리 후 Repository 호출
            if (name == null || name.isEmpty()) {
                throw new IllegalArgumentException("Name cannot be null or empty");
            }
            return userRepository.findByName(name);
        }

        // 스트림 처리
        public void processUsersWithNameNotNull() {
            try (Stream<User> userStream = userRepository.readAllByNameNotNull()) {
                userStream.forEach(user -> {
                    // 사용자 데이터 처리 로직
                    System.out.println("Processing user: " + user.getName());
                });
            } catch (Exception e) {
                // 예외 처리
                e.printStackTrace();
            }
        }
    }
    ```
