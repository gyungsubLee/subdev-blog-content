### SingletonService

> test&#46;java&#46;hello&#46;core&#46;singleton

<a id="1c3eda9b0fe181c38e15fd37889f5c05"></a>

```java
package hello.core.singleton;

public class SingletonService {

    // 1. static 영역에 객체를 딱 1개만 생성한다.
    private static final SingletonService instance = new SingletonService();

    // 2. public으로 열어서 객체 인스턴스가 필요하면, 해당 static 메서드를 통해서만 조회하도록 허용한다.
    public static SingletonService getInstance(){
        return instance;
    }

    // 3. 생성자를 private으로 선언하여, 외부에서 new 키워드를 사용한 객체 생성을 하지 못하게 막는다.
    private SingletonService() {
        
    }
    
    public void logic() {
        System.out.println("싱글톤 객체 로직 호출");
    }
}
```

> 1&#46; <strong>static 영역에 객체 instance를 미리 생성</strong>한다&#46;<br><br>2&#46;  <strong>해당 객체 인스턴스가 필요</strong>하면 오직 <strong><u><code>getInstance()</code></u></strong><strong><u> 메서드를 통해서만 조회 가능</u></strong>하다&#46; <br>     이 메서드 호출 시,<strong><u> 항상 같은 인스턴스를 반환</u></strong>한다&#46;<br><br>3&#46; <strong>딱 1개의 객체 인스턴스만 존재</strong>해야 한다&#46; <br>    따라서 <strong>생성자를 private로 막아, 외부에서 new 키워드로 객체 인스턴스가 생성되는 것을 막</strong>는다&#46;

### SingletonServiceTest

<a id="1c3eda9b0fe1812aaa47ee57d83b7612"></a>

```java
package hello.core.singleton;

import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

import static org.assertj.core.api.Assertions.assertThat;

public class SingletonServiceTest {
    @Test
    @DisplayName("싱글톤 패턴을 적용한 객체 사용")
    public void singletonServiceTest() {

        // private으로 생성자를 막아, 컴파일 오류 발생
       new SingletonService(); // Error: SingletonService() has private acces...

        // 1. 조회: 호출할 때 마다 같은 객체를 반환
        SingletonService singletonService1 = SingletonService.getInstance();

        // 2. 조회: 호출할 때 마다 같은 객체를 반환
        SingletonService singletonService2 = SingletonService.getInstance();

        // 참조값이 같은 것을 확인
        System.out.println("singletonService1 = "+ singletonService1);
        System.out.println(" singletonService1 = "+ singletonService2);

        // sigletonService1 == singletonService2
        assertThat(singletonService1).isSameAs(singletonService2);

        singletonService1.logic();
    }
}
```

> private → new 키워드 막힘 <br>호출(<code>getInstance()</code> ) 할 때마다, 같은 객체 인스턴스를 반환하는 것을 확인

### 싱글톤 패턴 문제점

- 해당 패턴을 구현하는 코드가 많이 들어간다

- 의존관계상 클라이언트가 구현 클래스(인스턴스)에 의존한다&#46; →<strong> DIP</strong> 위반

- 클라이언트가 인스턴스에 의존하여, <strong>OCP </strong>를 위반할 가능성이 높다

- 테스트하기 어렵다&#46;

- 내부 속성을 변경하거나 초기화 하기 어렵다&#46;

- <code>private</code> 생성자로 자식 클래스를 만들기 어렵다&#46;

- 결론적으로 유연성이 떨어진다&#46;
