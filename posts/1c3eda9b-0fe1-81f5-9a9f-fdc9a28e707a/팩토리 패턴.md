## 팩토리 패턴

---

- 인스턴스의 생성 책임을 분리하여 클래스로 만든 패턴

- 객체 생성 로직을 캡슐화하여 코드의 유연성과 확장성을 높인다&#46;

-  여러 개의 클래스 인스턴스를 동적으로 생성할 필요가 있을 때, 사용하면 코드가 훨씬 깔끔하고 유지보수하기 쉬워진다&#46;
    - 생성할 객체의 클래스가 런타임에 결정될 때

    - 객체 생성 로직이 복잡하거나 자주 변경될 때

    - 상속 구조에서 여러 하위 클래스 중 하나를 선택해서 객체를 생성해야 할 때

<summary>ex1) </summary>

<details>
<summary> &#91; 코드 &#93; Service &#45;  간단한 의존성 클래스 </summary>

<a id="1c3eda9b0fe18131ae3dd2e409b91804"></a>

```java
class Service {
    public void perform() {
        System.out.println("Service is working");
    }
}
```

</details>

<details>
<summary> &#91; 코드 &#93; Client &#45; <strong>Service를 주입받는 클래스</strong></summary>

<a id="1c3eda9b0fe181a19a70f1df4f6cb74f"></a>

```java
class Client {
    private final Service service;

    // 생성자 주입
    public Client(Service service) {
        this.service = service;
    }

    public void doSomething() {
        service.perform();
    }
}
```

</details>

<details>
<summary> &#91; 코드 &#93; ClientFactory &#45; <strong> 팩토리 클래스 (객체 생성을 담당)</strong></summary>

<a id="1c3eda9b0fe1811082a5fba44123940a"></a>

```java
class ClientFactory {
    public static Client createClient() {
        // 필요한 의존성 객체를 생성하고 주입
        Service service = new Service();
        return new Client(service);
    }
}
```

</details>

<details>
<summary> &#91; 코드 &#93; Main &#45; <strong>  팩토리 패턴 사용 예시</strong></summary>

<a id="1c3eda9b0fe18136b205e458d2de854e"></a>

```java
public class Main {
    public static void main(String[] args) {
        // 팩토리를 통해 Client 인스턴스를 생성 및 필요한 의존성을 주입
        Client client = ClientFactory.createClient();
        client.doSomething(); // "Service is working" 
    }
}
```

</details>

- ex2)
    <details>
    <summary>&#91; 코드  &#93; &#60;interface&#62; Animal </summary>

    <a id="1c3eda9b0fe18171816ad8e7c81b8008"></a>

    ```java
    public interface Animal {
        void speak();
    }
    ```

    </details>

    <details>
    <summary>&#91; 코드  &#93; 구현 클래스들 &#45; Dog, Cat, Bird </summary>

    <a id="1c3eda9b0fe181f4a7ecdd6f0d04e7b2"></a>

    ```java
    public class Dog implements Animal {
        @Override
        public void speak() {
            System.out.println("Bark!");
        }
    }

    public class Cat implements Animal {
        @Override
        public void speak() {
            System.out.println("Meow!");
        }
    }

    public class Bird implements Animal {
        @Override
        public void speak() {
            System.out.println("Tweet!");
        }
    }
    ```

    </details>

    <details>
    <summary>&#91; 코드  &#93; <strong>팩토리 클래스 </strong> &#45; AnimalFactory</summary>

    <a id="1c3eda9b0fe1811ba658d9de88cd97cb"></a>

    ```java
    public class AnimalFactory {
        public Animal createAnimal(String type) {
            if (type == null) {
                throw new NullPointException("type is null")
            }  
            
            switch (type.toLowerCase()) {
                case "dog":
                    return new Dog();
                case "cat":
                    return new Cat();
                case "bird":
                    return new Bird();
                default:
                    throw new IllegalArgumentException("Unknown animal type: " + type);
            }
        }
    }
    ```

    </details>

    <details>
    <summary>&#91; 코드  &#93; <strong>팩토리 사용</strong>&#45; Main </summary>

    <a id="1c3eda9b0fe181868099f8a60d1113e9"></a>

    ```java
    public class Main {
        public static void main(String[] args) {
            AnimalFactory factory = new AnimalFactory();

            // Dog 인스턴스 생성
            Animal dog = factory.createAnimal("dog");
            dog.speak();  // 출력: Bark!

            // Cat 인스턴스 생성
            Animal cat = factory.createAnimal("cat");
            cat.speak();  // 출력: Meow!

            // Bird 인스턴스 생성
            Animal bird = factory.createAnimal("bird");
            bird.speak();  // 출력: Tweet!
        }
    }
    ```

    </details>

- 팩토리 패턴의 이점
    - 확장성
        - 새로운 동물 클래스를 추가할 때 기존 코드를 변경할 필요 없이 팩토리 클래스에만 추가해주면 된다&#46;

    - <strong>유지보수성</strong>
        - 객체 생성 로직이 캡슐화되어 코드가 더욱 간결하고 유지보수하기 쉬워진다&#46;

    - <strong>결합도 감소</strong>
        - 클라이언트는 구체적인 클래스에 의존하지 않고, 인터페이스나 추상 클래스에 의존하게 되어 결합도가 낮아진다&#46;
