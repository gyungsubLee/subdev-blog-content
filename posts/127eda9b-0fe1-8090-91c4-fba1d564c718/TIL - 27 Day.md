## 1&#46;2 &#45; 다형성(Object)을 통한 중복 해결 시도 → Bad Case

> ✏️ 
> 
> <a id="128eda9b0fe1810c9103e687e8413bee"></a>
> 
> 다형성(부모타입 참조)을 사용해서 문제를 해결 시도
> 
> > <strong><code>Object</code></strong><strong> </strong>는 모든 타입의 부모이다&#46; 

<details>
<summary>&#91; 코드 &#93; ObjectBox</summary>

<a id="128eda9b0fe181b7add0c2c7c081c41f"></a>

```java
package generic.ex1;

public class ObjectBox {

    private Object value;

    public Object get() {
        return value;
    }

    public void set(Object value) {
        this.value = value;
    }
}
```

-  <code>Object value</code>
    - Object는 모든 타입의 부모이다&#46; 

    - 부모는 자식을 담을 수 있으므로 (다형성)  <br>모든 타입을 ObjectBox에 보관할 수 있다&#46; 

</details>

<details>
<summary>&#91; 코드 &#93; BoxMain2</summary>

<a id="128eda9b0fe181aa957bf3754108071b"></a>

```java
package generic.ex1;

public class BoxMain2 {

    public static void main(String[] args) {
        ObjectBox integerBox = new ObjectBox();
        integerBox.set(10);
        Integer integer = (Integer) integerBox.get();   // Object -> Integer 캐스팅
        System.out.println("integer = " + integer);

        ObjectBox stringBox = new ObjectBox();
        stringBox.set("hello");
        String str = (String) stringBox.get();
        System.out.println("str = " + str);

        // 잘못된 인수 전달 시
        integerBox.set("문자100");
        Integer result = (Integer) integerBox.get();    // String -> Integer 캐스팅 예
        System.out.println("result = " + result);
    }
}
```

</details>

<details>
<summary>문제) 반환 타입이 맞지 않음 → 직접 다운 캐스팅</summary>

<a id="128eda9b0fe181a5b931e82b531dfa2f"></a>

```java
Integer integer = (Integer) integerBox.get();
```

- 위와 같이 반환 타입을 맞추기 위해 접 다운 캐스팅<code>()</code>을 해야한다&#46;

</details>

- String&#58; <code>“문자100” </code>→ Integer 캐스팅 
    <a id="128eda9b0fe18168a84ccc7c4b3b4600"></a>

    ```java
    integerBox.set("문자100");
    ```

> 🧐 
> 
> <a id="128eda9b0fe18102b86de0699390b5f0"></a>
> 
> 정리
> 
> - <code>다형성</code>(<strong><code>Object</code></strong>, 상위 형식 타입 할당 가능)을 통해 코드의 중복을 제거하고, 기존 코드를 재사용할 수 있게 되었다&#46; 그러나 입력 시, <strong><u>실수로 원하지 않는 타입이 할당</u></strong>될 수 있는  <strong><u>타입 안정성의 문제</u></strong>가 발생된다&#46; 
> 
> - 위 코드 예로 설명하자만, IntegerBox에는 숫자만 들어가야만 하고, StringBox에는 문자열만 입력할 수 있어야 한다&#46; 
> 
> - 하지만 <strong><u>Setter의 매개변수 타입이 Object</u></strong>이기 때문에, <strong><u>다른 타입의 값이 입력</u></strong>될 수 있다&#46; <strong><u>반환 타입 또한 Object</u></strong>이기 때문에, <strong><u>getter 사용 시 원하는 타입을 정확하게 받을 수 없</u></strong>고, 항상 <strong><u>위험한 다운 캐스팅을 시도</u></strong>해야 한다&#46;
> 
> - 결과적으로 <strong><u>타</u></strong><u>입 안정성이 떨</u>어서<strong><u> </u></strong><strong><u>오류 발생 확률이 높</u></strong><strong>아</strong><strong>진</strong>다&#46;

## 1&#46;3&#46; &#45; 제네릭 적용

> ✏️ 
> 
> <a id="128eda9b0fe18152ac02de3fe3d33f56"></a>
> 
> <strong><code>제네릭</code></strong>을 사용하면 &#91;<code>코드의 재사용</code>, <code>타입 안정성</code>&#93; 둘다 만족시킬 수 있게 코드 작성이 가능하다&#46; 

<details>
<summary>&#91; 코드 &#93; GenericBox</summary>

<a id="128eda9b0fe181a7ac30f12f9ed5be00"></a>

```java
package generic.ex1;

public class GenericBox<T> {

    private T value;

    public void set(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }
}

```

</details>

<details>
<summary>&#91; 코드 &#93; BoxMain3</summary>

<a id="128eda9b0fe181a3b7c2f89c3841e190"></a>

```java
package generic.ex1;

public class BoxMain3 {
    public static void main(String[] args) {
        GenericBox<Integer> integerBox = new GenericBox<Integer>(); // 생성 시점에 T의 타입 결정
        integerBox.set(10);
        // integerBox.set("문자100");   // Integer 타입만 허용, 컴파일 오류
        Integer integer = integerBox.get();;   // Integer 타입 반환 (캐스팅 X)
        System.out.println("integer = " + integer);

        GenericBox<String> stringBox = new GenericBox<String>();
        stringBox.set("hello");       // String 타입만 허용
        String str = stringBox.get();   // String 타입 반환
        System.out.println("str = " + str);

        // 원하는 모든 타입 사용 가능
        GenericBox<Double> doubleBox = new GenericBox<Double>();
        doubleBox.set(10.5);
        Double doubleValue = doubleBox.get();
        System.out.println("doubleValue = " + doubleValue);

        // 타입 추론: 생성하는 제네릭 타입 생략 가능
        GenericBox<Integer> integerBox2 = new GenericBox<>();
    }
}
```

</details>

- 자바 컴파일러가 타입을 추론할 수 있는 상황에만 가능, 쉽게 이야기해 서 읽을 수 있는 타입 정보가 주변에 있어야 추론할 수 있다&#46;

<a id="128eda9b0fe18179a5a7e107028446d7"></a>

```java
GenericBox<Integer> integerBox = new GenericBox<Integer>() // 타입 직접 입력
GenericBox<Integer> integerBox = new GenericBox<>(); // 타입 추론
```

</details>

## 1&#46;4  &#45; 제네릭 용어와 관례

> ✏️ 
> 
> <a id="128eda9b0fe181f4afddf8971ab435e4"></a>
> 
> 제네릭 핵심은 <strong><u>사용할 타입을 미리 결정하지 않</u></strong>는 것이다&#46;
> 
> <a id="128eda9b0fe1819eb9d1c7cffe00194c"></a>
> 
> 즉, <u>클래스 내부에서 사용</u>하는 <strong><u>타입</u></strong>을 클래스를 <u>정의하는 시점이 아닌</u>, <strong><u>실제 사용하는 생성 시점에서 타입을 결정</u></strong>한다&#46; 

<details>
<summary>비유) 메서드의 &#91; 매개변수 &#45; 인자 &#93; </summary>

<details>
<summary>메서드에 필요한 값을 <strong>메</strong><strong><u>서드 정의 시점</u></strong><strong><u>에 미리 </u></strong><strong><u>결정</u></strong></summary>

<a id="128eda9b0fe181759cf2c2ee084d097c"></a>

```java
void method1() {
     println("hello");
}
```

- 위와 같이 값을 메서드 정의 시정메 미리 결정

- 해당 메서드는 오직 <code>“hello”</code> 라는 값만 출력 가능
    <a id="128eda9b0fe181ff98c5c3a486b07fa4"></a>

    → <strong>재사용성 ↓</strong>

</details>

<details>
<summary>메서드에 필요한 값을 인자를 통해 <strong><u>매개변수로 전달</u></strong>, 메서드의 사용 시점에서  값을 결정</summary>

<a id="128eda9b0fe1812b805bf56bd84e4bb9"></a>

```java
 void method2(String param) {
     println(param);
}
 void main() {
     method2("hello");
     method2("hi");
}
```

- 메서드에 필요한 값을 <strong><u>메서드 정의 시점이 아닌,</u></strong> <strong><u>메서드</u></strong>를 <strong><u>실제 사용하는 시점</u></strong>으로 미룰 수 있다&#46;

<details>
<summary>인자를 통해 원하는 값 매개변수로 전달</summary>

<details>
<summary>매개변수&#58; <code>String param</code></summary>

<a id="128eda9b0fe181a680bdd4c709a7c5b4"></a>

```java
void method2(String param) { // 매개변수
   println(param);
}
```

</details>

<details>
<summary>인자&#58; <code>“hello”</code>, <code>“hi”</code></summary>

<a id="128eda9b0fe18118b50bd759fdc06674"></a>

```java
void main() {
   method2("hello"); // 인수("hello") 전달
   method2("hi");
}
```

</details>

<a id="128eda9b0fe181fba67cc3ff78e10ee3"></a>

```java
//method2("hello") 호출 예
void method2(String param="hello") {
   println(param);      // "hello" 출력됨
}
```

<a id="128eda9b0fe181f5b336ce1b86c97f6b"></a>

```java
//method2("hi") 호출 예
void method2(String param="hi") {
   println(param);      // "hi" 출력됨
```

</details>

</details>

</details>

<details>
<summary>제네릭의<strong><u> 타입 매개변수</u></strong> 와 <strong><u>타입 인자</u></strong></summary>

- 앞서 설명한 메서드의 매개변수 와 인자의 관계와 비슷하게 동작한다&#46;

- 제네릭 클래스를 정의할 때 내부에서 사용할 <u>타입을 미리 결정하는 것이 아닌</u>, <u>해당 클래스</u>를 <strong><u>실제 사용하는 생성 시점</u></strong>에 내부에서 사용할 <strong><u>타입을 결정</u></strong>한다&#46;

- 차이가 있다면 <strong><u>메서드의 매개변수</u></strong>는 <u>사용할 값</u>에 대한 결정을 <strong><u>메서드 사용 시점</u></strong>에 결정하는 것이고, <strong><u>제네릭의 타입 매개변수</u></strong>는 <u>사용할 타입</u>을 <strong><u>클래스 사용(생성) 시점</u></strong>에 결정하는 것이다&#46; 

</details>

> 💬 
> 
> <a id="128eda9b0fe181f9913fdca1e95871c3"></a>
> 
> <strong>정리 </strong>
> 
> - <code>메서드</code>&#58; 매개변수에 인자 전달, 사용할 값 결정
> 
> -  <code>제네릭 클래스</code>&#58; 타입 매개변수에 타입 인자 전달, 사용할 타입 결정

> 따라서 <u>제네릭</u>에서 사용하는 용어도<u> 매개변수, 인자 용어를 그대로 가져와 사용</u>한다&#46;다만, 값이 아닌 <strong><u>타입을 결정</u></strong>하는 것이기 때문에 <u>앞에 타입을 붙</u>인다&#46;

---

- <code>타입 매개변수</code>&#58; <code>GenericBox&#60;T&#62;</code>에서  <code>T</code>

- <code>타입 인자</code>
    - <code>GenericBox&#60;Integer&#62;</code>에서 <code>Integer</code>

    - <code>GenericBox&#60;String&#62;</code>에서 <code>String</code>

> 제네릭 타입의 타입 매개변수 <code>&#60;T&#62;</code>에 타입 인자를 전달하여 사용할 타입을 결정한다&#46;

---

- <code>GenericBox&#60;T&#62;</code>
    -  <code>Integer</code> &#45;&#62; <code>GenericBox&#60;Integer&#62;</code>

    -  <code>String</code> &#45;&#62; <code>GenericBox&#60;String&#62;</code>

<a id="128eda9b0fe181f88530eb3b3d4d9155"></a>

### 용어 정리

<details>
<summary>제네릭(Generic) 단어</summary>

- 제네릭이라는 영어 단어는 ‘일반적’, ‘범용적’ 이라는 뜻을 가진다&#46;

- 풀어보면 특정 타입에 속한 것이 아닌 ‘일반적, 범용적으로 사용할 수 있다’는 뜻이다&#46; 

</details>

<details>
<summary>제네릭 타입(Generic Type)</summary>

- <code>클래스</code>나 <code>인터페이스</code>를 정의할 때 <strong><u><code>타입 매개변수</code></u></strong><strong><u>를 사용</u></strong>하는 것을 말한다&#46;

- <code>제네릭 클래스</code>, <code>제네릭 인터페이스</code>를 모두 합쳐서 <code>제네릭 타입</code>이라 한다&#46;
    - 타입은 클래스, 인터페이스, 기본형(int 등)을 모두 합쳐서 부르는 말임

<details>
<summary>예시) 제네릭 타입 </summary>

<a id="128eda9b0fe181288599f9e01491182c"></a>

```java
class GenericBox<T> { 
		private T t; 
}
```

- 제네릭 타입 = 제네릭 클래스  = <code>GenericBox&#60;T&#62;</code>

</details>

</details>

<details>
<summary>타입 매개변수(Type Parameter)</summary>

- 제네릭 타입이나 메서드에서 사용되는 변수

- 실제 타입으로 대체됨
    - ex) <code>GenericBox&#60;T&#62;</code> → <code>T</code>&#58; 타입 매개변수

</details>

<details>
<summary>타입 인자(Type Argument)</summary>

- 제네릭 타입을 사용할 때, 제공되는 실제 타입

- ex) &#58; <code>GenericBox&#60;Integer&#62;</code> &#45;&#62; <code>Integer</code>&#58; 타입 인자

</details>

<a id="128eda9b0fe181f58ceddece20d2acc1"></a>

### 제네릭 명명 관례 

- 주로 사용하는 키워드
    - <code>E</code> &#45; Element

    - <code>K</code> &#45; Key

    - <code>N</code> &#45; Number

    - <code>T</code> &#45; Type

    - <code>V</code> &#45; Value

    - <code>S</code>, <code>U</code>, <code>V</code> etc &#45; 2nd, 3rd, 4th types

-  한번에 여러 타입 매개변수를 선언할 수 있다
    <a id="128eda9b0fe181b98fa5cbd12d023e74"></a>

    ```java
    class Data<K, V> {}
    ```

- <strong>타입 인자로 </strong><strong><u>기본형은 사용할 수 없</u></strong><strong>다</strong>
    - 타입 인자로 기본형( <code>int</code> , <code>double</code> &#46;&#46;)은 사용할 수 없다&#46;
        <a id="128eda9b0fe181618716f88bae44d440"></a>

         ⇒ 래퍼 클래스( <code>Integer</code> , <code>Double</code> )를 사용

<a id="128eda9b0fe18106a425dd192116bca4"></a>

### <code>raw Type</code> (<code>로타입</code>, <code>원시 타입</code>) → 사용 ❌

<a id="128eda9b0fe181639c84cd570e6cad14"></a>

```java
GenericBox integerBox = new GenericBox();  // 타입 지정 X -> Object 사용
integerBox.set(10);
Integer result = (Integer) integerBox.get(); 
System.out.println("result = " + result);
```

- 위와 같이 <code>&#60;&#62;</code>을  지정하지 않음 → <code>Object</code> 할당
    - 따라서 <strong><u>타입 안정성이 떨</u></strong>어져 <strong><u>오류</u></strong>가 발생될 수 있다&#46; 
        <a id="128eda9b0fe181a3aa28e06fffd16448"></a>

        ⇒   사용 ❌ 

<details>
<summary>🧐 왜 <code>raw Type(원시타입)</code>이 지원되는가?</summary>

<a id="128eda9b0fe1810bbb6bebfb76b30643"></a>

제네릭 타입을 사용할 때는 항상 <code>&#60;&#62;</code> 를 사용해서 사용 시점에 타입을 지정해야 한다&#46; 

> 🧐 그런데 왜 이런 로타입을 지원하는 것 인가?

<a id="128eda9b0fe1818b8befeae1e75a79ed"></a>

제네릭은 자바가 처음 등장할 때 부터 있던 것이 아닌, 오랜 사용 후에 등장한 개념이다&#46; 따라서 제네릭 사용 이전 코드와의 하위 호환을 위해 지원한다&#46;

</details>
